Forms and Validation

Build robust forms. Controlled versus uncontrolled inputs, React 19 form actions with FormData, client-side validation, React Hook Form with Zod, file uploads and accessible error messages.

02Controlled Form

function ContactForm() {
  const [values, setValues] = useState({ name: "", email: "", message: "" });
  const [errors, setErrors] = useState({});
  const [status, setStatus] = useState("idle");

  const handleChange = (e) => {
    const { name, value } = e.target;
    setValues(v => ({ ...v, [name]: value }));
  };

  const validate = (v) => {
    const e = {};
    if (!v.name.trim()) e.name = "Name is required";
    if (!/^\S+@\S+\.\S+$/.test(v.email)) e.email = "Enter a valid email";
    if (v.message.length < 10) e.message = "Message must be at least 10 characters";
    return e;
  };

  async function handleSubmit(e) {
    e.preventDefault();
    const found = validate(values);
    setErrors(found);
    if (Object.keys(found).length) return;

    setStatus("submitting");
    try {
      await sendMessage(values);
      setStatus("success");
      setValues({ name: "", email: "", message: "" });
    } catch {
      setStatus("error");
    }
  }

  return (
    <form onSubmit={handleSubmit} noValidate>
      <label htmlFor="name">Name</label>
      <input id="name" name="name" value={values.name} onChange={handleChange}
             aria-invalid={!!errors.name} aria-describedby={errors.name ? "name-err" : undefined} />
      {errors.name && <p id="name-err" role="alert">{errors.name}</p>}
      {/* email and message fields follow the same pattern */}
      <button disabled={status === "submitting"}>{status === "submitting" ? "Sending…" : "Send"}</button>
      {status === "success" && <p>Thanks! We'll reply soon.</p>}
      {status === "error" && <p role="alert">Something went wrong. Try again.</p>}
    </form>
  );
}

03Uncontrolled Form with FormData and Form Actions (React 19)

The simplest approach: no state per field.

async function createCourse(formData) {
  const course = Object.fromEntries(formData);          // { title: "...", level: "..." }
  await api.createCourse(course);
}

<form action={createCourse}>
  <input name="title" required minLength={3} />
  <select name="level" defaultValue="beginner">
    <option value="beginner">Beginner</option>
    <option value="advanced">Advanced</option>
  </select>
  <input type="checkbox" name="published" />
  <button>Create</button>
</form>

FormData essentials

formData.get("title");                 // string | File | null
formData.getAll("tags");               // all values for a repeated field (checkbox group, multi-select)
formData.has("published");             // checkboxes are only present when checked
Object.fromEntries(formData);          // simple object (repeated names keep the last value)
new FormData(formElement);             // build one from a <form>

Validation with useActionState

async function register(prev, formData) {
  const email = formData.get("email");
  const password = formData.get("password");

  const errors = {};
  if (!/^\S+@\S+\.\S+$/.test(email)) errors.email = "Invalid email";
  if (password.length < 8) errors.password = "At least 8 characters";
  if (Object.keys(errors).length) return { errors, values: { email } };   // keep what the user typed

  const res = await api.register(email, password);
  return res.ok ? { success: true } : { errors: { form: res.message }, values: { email } };
}

function Register() {
  const [state, action, pending] = useActionState(register, {});
  return (
    <form action={action}>
      <input name="email" type="email" defaultValue={state.values?.email} />
      {state.errors?.email && <p role="alert">{state.errors.email}</p>}
      <input name="password" type="password" />
      {state.errors?.password && <p role="alert">{state.errors.password}</p>}
      {state.errors?.form && <p role="alert">{state.errors.form}</p>}
      <button disabled={pending}>Create account</button>
    </form>
  );
}
Note

React resets uncontrolled fields after a successful action. To keep entered values after a failed validation, return them in state and use defaultValue.

04Built-in HTML Validation

Use the browser first: it is accessible and free.

<input type="email" required />
<input type="password" required minLength={8} maxLength={64} />
<input type="number" min={1} max={100} step={1} />
<input pattern="[0-9]{10}" title="10-digit mobile number" />
  • required, minLength, maxLength, min, max, pattern, type="email|url|tel|number|date"
  • noValidate on <form> turns off the browser's bubbles when you render your own messages
  • e.target.checkValidity() and reportValidity() for custom flows

06Common Form Patterns

Checkbox group

const [tags, setTags] = useState([]);
const toggle = (tag) => setTags(t => t.includes(tag) ? t.filter(x => x !== tag) : [...t, tag]);

{["java", "react", "sql"].map(tag => (
  <label key={tag}><input type="checkbox" checked={tags.includes(tag)} onChange={() => toggle(tag)} /> {tag}</label>
))}

Debounced search

const [q, setQ] = useState("");
const debounced = useDebounce(q, 300);              // custom hook (see Custom Hooks topic)
useEffect(() => { search(debounced); }, [debounced]);

Dependent fields

const [country, setCountry] = useState("");
const states = useMemo(() => getStates(country), [country]);
<select value={country} onChange={e => { setCountry(e.target.value); setState(""); }}>…</select>

Multi-step form

Keep a step index and a single data object in the parent; each step component receives data and onNext(partial).

Preventing double submit

Disable the button with isPending/status; for actions useFormStatus().pending does it automatically.

07File Uploads

function Avatar() {
  const [preview, setPreview] = useState(null);

  function handleFile(e) {
    const file = e.target.files?.[0];
    if (!file) return;
    if (!file.type.startsWith("image/")) return alert("Images only");
    if (file.size > 2 * 1024 * 1024) return alert("Max 2 MB");
    setPreview(URL.createObjectURL(file));          // revoke later with URL.revokeObjectURL
  }

  async function upload(formData) {
    await fetch("/api/avatar", { method: "POST", body: formData });   // browser sets multipart headers
  }

  return (
    <form action={upload}>
      <input type="file" name="avatar" accept="image/*" onChange={handleFile} />
      {preview && <img src={preview} alt="Preview" width={96} />}
      <button>Upload</button>
    </form>
  );
}

Never set Content-Type manually for FormData, and always re-validate on the server: client validation is for usability, not security.

08React Hook Form + Zod

For big forms use React Hook Form (uncontrolled inputs → very few re-renders) with Zod schemas.

npm install react-hook-form zod @hookform/resolvers
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";

const schema = z.object({
  name: z.string().min(2, "Name is too short"),
  email: z.string().email("Invalid email"),
  age: z.coerce.number().int().min(13, "Must be 13+"),
  password: z.string().min(8, "At least 8 characters"),
  confirm: z.string(),
}).refine(d => d.password === d.confirm, { message: "Passwords don't match", path: ["confirm"] });

export default function SignupForm() {
  const { register, handleSubmit, reset, setError, formState: { errors, isSubmitting } } = useForm({
    resolver: zodResolver(schema),
    defaultValues: { name: "", email: "", age: "", password: "", confirm: "" },
  });

  const onSubmit = async (data) => {
    try {
      await api.signup(data);
      reset();
    } catch (e) {
      setError("root", { message: e.message });
    }
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      <input {...register("name")} placeholder="Name" />
      {errors.name && <p role="alert">{errors.name.message}</p>}

      <input {...register("email")} type="email" placeholder="Email" />
      {errors.email && <p role="alert">{errors.email.message}</p>}

      <input {...register("age")} type="number" placeholder="Age" />
      {errors.age && <p role="alert">{errors.age.message}</p>}

      <input {...register("password")} type="password" />
      <input {...register("confirm")} type="password" />
      {errors.confirm && <p role="alert">{errors.confirm.message}</p>}

      {errors.root && <p role="alert">{errors.root.message}</p>}
      <button disabled={isSubmitting}>Sign up</button>
    </form>
  );
}

Zod essentials

z.string().min(1).max(50).trim().regex(/^[a-z]+$/);
z.number().int().positive();
z.boolean();   z.date();   z.enum(["admin", "student"]);
z.array(z.string()).min(1);
z.object({ ... }).optional();
z.infer;   // type Schema = z.infer<typeof schema> in TypeScript
schema.safeParse(data);     // { success, data } | { success: false, error }

Share the same Zod schema between client and server so rules never drift.

09Accessible Forms Checklist

  • Every input has a real <label htmlFor> (or wraps the input)
  • Group radios/checkboxes with <fieldset> and <legend>
  • Mark invalid inputs with aria-invalid="true" and link the message with aria-describedby
  • Announce errors (role="alert" or aria-live="polite")
  • Don't rely on colour alone; keep visible focus styles
  • Move focus to the first invalid field after a failed submit
  • Use the correct type, autoComplete and inputMode
  • Buttons: type="button" for non-submit actions inside forms

10Security Notes

  • Validate on the server too; the client can be bypassed
  • Never trust hidden fields or client-side price/role values
  • Protect against CSRF (SameSite cookies, tokens) when using cookie auth
  • Don't log or store passwords; send over HTTPS only
  • Sanitise rich text before rendering as HTML

11Quick Recap

  • Controlled = value in state; uncontrolled = read with FormData or refs
  • React 19: <form action={fn}> + useActionState + useFormStatus removes most boilerplate
  • Use HTML validation attributes first; show accessible, linked error messages
  • For large forms, React Hook Form + Zod gives performance and shared schemas
  • Always re-validate on the server
