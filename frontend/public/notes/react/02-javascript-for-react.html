Modern JavaScript You Need for React

The ES6+ features used in every React codebase. Variables, arrow functions, destructuring, spread, array methods, modules, promises, async/await and closures.

01Why This Topic?

React code is "just JavaScript". Most beginner struggles come from not knowing the JavaScript features React uses constantly. Master these and React becomes easy.

02Variables: let and const

const course = "React";     // cannot be reassigned (preferred default)
let count = 0;              // can be reassigned
count = count + 1;
// var is function-scoped and hoisted: avoid it
  • Use const by default; use let only when you must reassign
  • const does not make objects/arrays immutable, only the binding
const user = { name: "Asha" };
user.name = "Ravi";         // allowed (mutating the object)
// user = {};               // TypeError (reassigning the variable)

04Arrow Functions

function add(a, b) { return a + b; }       // regular function
const add2 = (a, b) => a + b;              // arrow, implicit return
const square = (n) => n * n;
const greet = name => `Hi ${name}`;        // one parameter: parentheses optional
const makeUser = (n) => ({ name: n });     // returning an object: wrap in ()
const log = () => { console.log("hi"); };  // block body needs explicit return

Arrow functions do not have their own this, which is why they are used for callbacks and event handlers in React.

05Destructuring

Objects

const student = { id: 1, name: "Asha", city: "Chennai" };
const { name, city } = student;
const { name: studentName } = student;      // rename
const { age = 18 } = student;               // default value

Arrays

const [first, second] = ["a", "b", "c"];
const [count, setCount] = useState(0);      // exactly what hooks return

In function parameters (props!)

function Card({ title, price = 0 }) {       // destructure props directly
  return <h3>{title}: {price}</h3>;
}

06Spread and Rest

// Spread arrays
const a = [1, 2];
const b = [...a, 3, 4];                      // [1, 2, 3, 4]

// Spread objects (copy + override)
const base = { name: "Asha", age: 20 };
const updated = { ...base, age: 21 };        // { name: "Asha", age: 21 }

// Rest: collect the remaining items
const { name, ...others } = base;            // others = { age: 20 }
const sum = (...nums) => nums.reduce((t, n) => t + n, 0);
Remember

Spread is how you update state immutably in React. Never mutate state; create a new copy.

07Array Methods

React renders lists with these, so know them well. None of them mutate the original array (except sort, reverse, splice, push, pop).

const nums = [1, 2, 3, 4, 5];

nums.map(n => n * 2);                    // [2, 4, 6, 8, 10]     transform each item
nums.filter(n => n % 2 === 0);           // [2, 4]               keep matching items
nums.find(n => n > 3);                   // 4                    first match
nums.findIndex(n => n > 3);              // 3
nums.some(n => n > 4);                   // true
nums.every(n => n > 0);                  // true
nums.reduce((total, n) => total + n, 0); // 15                   combine into one value
nums.includes(3);                        // true
nums.slice(1, 3);                        // [2, 3]               copy part
[...nums].sort((a, b) => b - a);         // copy, then sort (don't sort state in place)
nums.toSorted((a, b) => b - a);          // ES2023: non-mutating sort
nums.at(-1);                             // 5                    last item

Array method cheat sheet for React

TaskUse
Render a listitems.map(item => <li key={item.id}>…</li>)
Remove an item from stateitems.filter(i => i.id !== id)
Update one item in stateitems.map(i => i.id === id ? { ...i, done: true } : i)
Add an item to state[...items, newItem]
Total / countreduce

09Optional Chaining and Nullish Coalescing

const city = user?.address?.city;            // undefined instead of an error if address is missing
const first = list?.[0];
user.save?.();                               // call only if the method exists

const name = input ?? "Guest";               // fallback only for null/undefined
const count = 0 || 10;                       // 10   (|| treats 0 as falsy)
const count2 = 0 ?? 10;                      // 0    (?? only checks null/undefined)

10Truthy and Falsy, and Short-circuiting

Falsy values: false, 0, "", null, undefined, NaN. Everything else is truthy.

const label = isAdmin && "Admin";            // "Admin" or false
const text = name || "Anonymous";
const cond = isLoggedIn ? "Logout" : "Login";
Warning

In JSX, {count && <Badge/>} prints 0 when count is 0. Use {count > 0 && <Badge/>} instead.

11ES Modules (import / export)

export const PI = 3.14;                  // named export
export function add(a, b) { return a + b; }
export default function greet() { }      // one default export per file
import greet, { PI, add } from "./utils.js";     // default + named
import { add as sum } from "./utils.js";         // rename
import * as utils from "./utils.js";             // everything
import logo from "./logo.svg";                   // assets (handled by the bundler)
  • Relative paths start with ./ or ../; packages have no path prefix (import React from "react")
  • One component per file, exported as default or named, is the usual React style

12Functions, Callbacks and Higher-order Functions

// A function can be passed around like any value
function run(task) { task(); }
run(() => console.log("hi"));

// Higher-order function: takes or returns functions
const times = (n) => (x) => x * n;
const double = times(2);
double(5);                                   // 10

Event handlers, map, useEffect callbacks and props like onClick all rely on this idea.

13Closures

A function remembers the variables from where it was created.

function counter() {
  let count = 0;
  return () => ++count;
}
const next = counter();
next();  // 1
next();  // 2

In React, each render creates new functions that "close over" that render's props and state. This is why a stale closure can show an old value (see the Effects topic).

14Promises and async/await

// Promise
fetch("/api/courses")
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.error(err));

// async/await: same thing, easier to read
async function loadCourses() {
  try {
    const res = await fetch("/api/courses");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json();
  } catch (err) {
    console.error(err);
    throw err;
  }
}
const [a, b] = await Promise.all([fetchUser(), fetchCourses()]);   // run in parallel
Promise.allSettled([p1, p2]);                                      // wait for all, never rejects
Promise.race([p1, p2]);                                            // first to finish
Note

fetch only rejects on network failure. A 404 or 500 still resolves, so always check res.ok.

15The Event Loop (in one minute)

JavaScript is single-threaded. Long-running work (network, timers) is handed off, and its callback runs later from a queue. Promise callbacks (microtasks) run before timers (setTimeout).

console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// 1, 4, 3, 2

16Immutability

React compares references to decide if something changed. If you mutate an object in place, the reference is the same and React may skip the update.

// Wrong: mutates the existing array
items.push(newItem);

// Right: new array, new reference
const next = [...items, newItem];

Immutable update patterns

TaskPattern
Update object field{ ...obj, field: value }
Update nested field{ ...obj, address: { ...obj.address, city: "Pune" } }
Add to array[...arr, item]
Remove from arrayarr.filter(x => x.id !== id)
Replace in arrayarr.map(x => x.id === id ? updated : x)
Insert at index[...arr.slice(0, i), item, ...arr.slice(i)]

17Classes and this (brief)

Modern React uses function components, so you rarely write classes. Just know that this depends on how a function is called, and arrow functions capture this from their surroundings.

21Quick Recap

  • Prefer const; use template literals and arrow functions
  • Destructuring and spread appear in almost every component
  • map, filter, reduce build UI from data; never mutate state, copy it
  • ?. and ?? handle missing data safely
  • Modules split code into files; export default + named exports
  • async/await + fetch for network calls; always check res.ok
