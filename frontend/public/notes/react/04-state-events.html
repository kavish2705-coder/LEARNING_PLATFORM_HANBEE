State, Events and Controlled Inputs

Make components interactive with useState. Updater functions, immutable updates for objects and arrays, lifting state up, controlled inputs and how React batches updates.

01What is State?

State is data a component remembers between renders. When state changes, React re-renders the component so the screen matches the new data.

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);        // [current value, setter], initial value 0

  return (
    <div>
      <p>You clicked {count} times</p>
      <button onClick={() => setCount(count + 1)}>Click</button>
    </div>
  );
}

Why not a normal variable?

A plain let count = 0 is reset on every render and changing it does not trigger a re-render. State persists and triggers renders.

Local variableState
Survives re-rendersNoYes
Changing it re-rendersNoYes

02Rules of Hooks

Hooks are functions that start with use. They must follow two rules (enforced by eslint-plugin-react-hooks):

  1. Call hooks only at the top level of a component or custom hook: not inside loops, conditions or nested functions
  2. Call hooks only from React functions: components or custom hooks

(use() in React 19 is the one hook-like API that may be called conditionally.)

03How a Render Works

1. Trigger   : initial render or a state update
2. Render    : React calls your component to get JSX (pure calculation)
3. Commit    : React updates the DOM with the differences
4. Browser paints, then effects run

State is a snapshot

Each render has its own values of props and state. Setting state does not change the variable in the current render; it schedules a new render.

function Demo() {
  const [n, setN] = useState(0);
  function handleClick() {
    setN(n + 1);
    setN(n + 1);
    setN(n + 1);
    console.log(n);        // still 0 in this render
  }                        // result: n becomes 1, not 3
  return <button onClick={handleClick}>{n}</button>;
}

Updater functions

When the next value depends on the previous one, pass a function.

function handleClick() {
  setN(prev => prev + 1);
  setN(prev => prev + 1);
  setN(prev => prev + 1);      // n becomes 3
}

Batching

React batches multiple state updates in one event (and in promises, timeouts and native handlers since React 18) into a single re-render.

04Lazy Initial State

const [todos, setTodos] = useState(() => JSON.parse(localStorage.getItem("todos")) ?? []);

Pass a function so expensive initialisation runs only once, not on every render.

05State Can Be Any Type

const [name, setName] = useState("");
const [age, setAge] = useState(0);
const [isOpen, setIsOpen] = useState(false);
const [user, setUser] = useState(null);
const [items, setItems] = useState([]);
const [form, setForm] = useState({ email: "", password: "" });

06Updating Objects Immutably

Never mutate state. Create a new object.

const [user, setUser] = useState({ name: "Asha", address: { city: "Chennai" } });

// Wrong
user.name = "Ravi";                    // mutates; no re-render guaranteed

// Right
setUser({ ...user, name: "Ravi" });
setUser(prev => ({ ...prev, address: { ...prev.address, city: "Pune" } }));   // nested

07Updating Arrays Immutably

TaskAvoid (mutates)Use (new array)
Addpush, unshift[...arr, item], [item, ...arr]
Removepop, shift, splicefilter

Sort / reversesort, reversetoSorted, toReversed or copy first
const [todos, setTodos] = useState([{ id: 1, text: "Learn React", done: false }]);

const add = (text) => setTodos(prev => [...prev, { id: crypto.randomUUID(), text, done: false }]);
const remove = (id) => setTodos(prev => prev.filter(t => t.id !== id));
const toggle = (id) => setTodos(prev => prev.map(t => t.id === id ? { ...t, done: !t.done } : t));
Tip

For deeply nested state, the Immer library (or useImmer) lets you write "mutating" code that produces immutable updates.

08A Complete Todo Example

import { useState } from "react";

export default function Todos() {
  const [todos, setTodos] = useState([]);
  const [text, setText] = useState("");

  function handleSubmit(e) {
    e.preventDefault();
    const trimmed = text.trim();
    if (!trimmed) return;
    setTodos(prev => [...prev, { id: crypto.randomUUID(), text: trimmed, done: false }]);
    setText("");
  }

  return (
    <section>
      <form onSubmit={handleSubmit}>
        <input value={text} onChange={e => setText(e.target.value)} placeholder="New task" />
        <button>Add</button>
      </form>
      <ul>
        {todos.map(t => (
          <li key={t.id}>
            <label>
              <input
                type="checkbox"
                checked={t.done}
                onChange={() => setTodos(prev => prev.map(x => x.id === t.id ? { ...x, done: !x.done } : x))}
              />
              <span style={{ textDecoration: t.done ? "line-through" : "none" }}>{t.text}</span>
            </label>
            <button onClick={() => setTodos(prev => prev.filter(x => x.id !== t.id))}>✕</button>
          </li>
        ))}
      </ul>
      <p>{todos.filter(t => !t.done).length} remaining</p>
    </section>
  );
}

09Controlled Inputs

A controlled input's value lives in React state. The input shows value, and onChange updates state.

function Login() {
  const [form, setForm] = useState({ email: "", password: "", remember: false });

  function handleChange(e) {
    const { name, value, type, checked } = e.target;
    setForm(prev => ({ ...prev, [name]: type === "checkbox" ? checked : value }));
  }

  return (
    <form>
      <input name="email" type="email" value={form.email} onChange={handleChange} />
      <input name="password" type="password" value={form.password} onChange={handleChange} />
      <label><input name="remember" type="checkbox" checked={form.remember} onChange={handleChange} /> Remember me</label>
    </form>
  );
}

</select>
Warning

Giving value without onChange makes the input read-only. Initialise value with "", not undefined/null, to avoid the controlled/uncontrolled warning.

Uncontrolled inputs

Let the DOM hold the value and read it when needed (with a ref or FormData). Simpler for large forms. Covered in the Forms topic.

10Lifting State Up

When two components need the same data, move the state to their closest common parent and pass it down.

function Parent() {
  const [query, setQuery] = useState("");
  return (
    <>
      <SearchBox query={query} onQueryChange={setQuery} />
      <ResultList query={query} />
    </>
  );
}

function SearchBox({ query, onQueryChange }) {
  return <input value={query} onChange={e => onQueryChange(e.target.value)} />;
}

Where should state live?

  1. Used by one component → keep it there
  2. Used by siblings → lift to the common parent
  3. Used across the app (theme, current user) → Context or a state library

11Choosing What to Put in State

Good state

  • Changes over time and affects what is rendered
  • Cannot be computed from other state or props

Derive instead of duplicating

// Bad: redundant state that can go out of sync
const [items, setItems] = useState([]);
const [count, setCount] = useState(0);

// Good: derive during render
const [items, setItems] = useState([]);
const count = items.length;
const total = items.reduce((t, i) => t + i.price * i.qty, 0);
const visible = items.filter(i => i.name.includes(query));

State structure tips

  • Group related values that change together
  • Avoid contradictions (isLoading + isError + isSuccess → use one status)
  • Avoid duplicated data (store selectedId, not a copy of the selected object)
  • Avoid deeply nested state; normalise by id
const [status, setStatus] = useState("idle");   // "idle" | "loading" | "success" | "error"
const [selectedId, setSelectedId] = useState(null);
const selected = items.find(i => i.id === selectedId);

12Resetting State with key

Changing a component's key makes React create a fresh instance with new state.

<ProfileForm key={user.id} user={user} />      // switching users resets the form

13State and Re-rendering Facts

  • Calling setX(sameValue) (same via Object.is) does not re-render
  • When a component re-renders, all its children re-render too (unless memoised)
  • State is private to each component instance: two <Counter /> have separate counts
  • State is tied to a component's position in the tree; moving or removing it resets state

14Quick Recap

  • const [value, setValue] = useState(initial); setting state triggers a re-render
  • State is a snapshot; use updater functions (prev => …) when based on previous state
  • Never mutate: use spread, map, filter to create new objects/arrays
  • Controlled inputs: value + onChange
  • Lift state up to share it; derive values instead of duplicating state
  • Change key to reset a component's state
