Data Fetching and Server State

Talk to APIs the modern way. fetch and Axios, why server state differs from UI state, and TanStack Query for caching, mutations, optimistic updates, pagination and Suspense.

01Calling APIs

fetch

async function getCourses() {
  const res = await fetch("/api/courses");
  if (!res.ok) throw new Error(`Request failed: ${res.status}`);     // fetch does NOT reject on 404/500
  return res.json();
}

// POST with JSON
await fetch("/api/courses", {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${token}` },
  body: JSON.stringify({ title: "React 19" }),
});

Build a small API client

const BASE = import.meta.env.VITE_API_URL;                 // Vite env var, must start with VITE_

export class ApiError extends Error {
  constructor(status, message) { super(message); this.status = status; }
}

export async function api(path, { method = "GET", body, signal } = {}) {
  const res = await fetch(`${BASE}${path}`, {
    method,
    signal,
    credentials: "include",                                  // send cookies (session auth)
    headers: body ? { "Content-Type": "application/json" } : undefined,
    body: body ? JSON.stringify(body) : undefined,
  });
  if (!res.ok) throw new ApiError(res.status, (await res.text()) || res.statusText);
  return res.status === 204 ? null : res.json();
}

import axios from "axios";

02Environment Variables

VITE_API_URL=https://api.hanbee.com
  • Vite exposes only variables prefixed with VITE_, accessed as import.meta.env.VITE_API_URL
  • Never put secrets in front-end env vars: they are bundled into public JavaScript

03The Problem with useEffect Fetching

Hand-rolling useEffect + useState for every request means re-implementing:

  • loading and error state
  • caching (don't refetch what you already have)
  • deduplication (two components requesting the same data)
  • race conditions and cancellation
  • retries, refetch on focus/reconnect, pagination, invalidation after mutations

04Server State vs Client State

Client (UI) stateServer state
ExamplesModal open, input text, selected tabCourses, user profile, orders
OwnerYour appThe server (you have a copy)
Can become staleNoYes
ToolsuseState, useReducer, ZustandTanStack Query, SWR, RTK Query
Tip

Don't put server data into Redux/Zustand by hand. Let a server-state library cache it, and keep your global store for real UI state.

useQuery: reading data

import { useQuery } from "@tanstack/react-query";

function Courses({ level }) {
  const { data, isPending, isError, error, isFetching, refetch } = useQuery({
    queryKey: ["courses", { level }],                        // cache key: refetches when it changes
    queryFn: ({ signal }) => api(`/courses?level=${level}`, { signal }),
    staleTime: 5 * 60 * 1000,
  });

  if (isPending) return <Skeleton />;
  if (isError) return <p role="alert">{error.message} <button onClick={() => refetch()}>Retry</button></p>;

  return (
    <>
      {isFetching && <small>Updating…</small>}
      <ul>{data.map(c => <li key={c.id}>{c.title}</li>)}</ul>
    </>
  );
}

Key concepts

ConceptMeaning
Query keyArray that uniquely identifies the data; include every variable the fetch depends on
staleTimeHow long data counts as fresh (no refetch). Default 0
gcTimeHow long unused cache is kept (default 5 min; was cacheTime)
isPendingNo data yet (replaced isLoading for first load in v5)
isFetchingA request is in flight (including background refetch)
Background refetchStale data is shown instantly while fresh data loads, on mount, window focus and reconnect
DeduplicationMany components with the same key share one request

Dependent and conditional queries

const { data: user } = useQuery({ queryKey: ["user"], queryFn: fetchUser });
const { data: courses } = useQuery({
  queryKey: ["courses", user?.id],
  queryFn: () => fetchCoursesFor(user.id),
  enabled: !!user,                                          // wait until user exists
});

useMutation: changing data

import { useMutation, useQueryClient } from "@tanstack/react-query";

function AddCourse() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: (newCourse) => api("/courses", { method: "POST", body: newCourse }),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ["courses"] }),   // refetch lists
    onError: (err) => toast.error(err.message),
  });

  return (
    <form action={(fd) => mutation.mutate({ title: fd.get("title") })}>
      <input name="title" />
      <button disabled={mutation.isPending}>{mutation.isPending ? "Saving…" : "Add"}</button>
      {mutation.isError && <p role="alert">{mutation.error.message}</p>}
    </form>
  );
}

mutate(vars) fires and forgets; mutateAsync(vars) returns a promise you can await.

Optimistic updates

const toggleDone = useMutation({
  mutationFn: (todo) => api(`/todos/${todo.id}`, { method: "PATCH", body: { done: !todo.done } }),
  onMutate: async (todo) => {
    await queryClient.cancelQueries({ queryKey: ["todos"] });
    const previous = queryClient.getQueryData(["todos"]);
    queryClient.setQueryData(["todos"], old => old.map(t => t.id === todo.id ? { ...t, done: !t.done } : t));
    return { previous };                                     // context for rollback
  },
  onError: (_err, _todo, ctx) => queryClient.setQueryData(["todos"], ctx.previous),
  onSettled: () => queryClient.invalidateQueries({ queryKey: ["todos"] }),
});

(React 19's useOptimistic offers a simpler local alternative for UI-only optimism.)

Pagination and infinite scroll

// Page-based
const { data, isPlaceholderData } = useQuery({

  placeholderData: keepPreviousData,                         // no flicker between pages

// Infinite scroll
const { data, fetchNextPage, hasNextPage, isFetchingNextPage } = useInfiniteQuery({
  queryKey: ["feed"],
  queryFn: ({ pageParam }) => api(`/feed?cursor=${pageParam}`),
  initialPageParam: 0,
  getNextPageParam: (last) => last.nextCursor,

06Fetching with use() and Suspense (React 19)

function CoursePage({ id }) {
  const promise = useMemo(() => fetchCourse(id), [id]);     // stable promise (or from a cache/library/Server Component)
  return (
    <Suspense fallback={<Skeleton />}>
      <Course promise={promise} />
    </Suspense>
  );
}
function Course({ promise }) {
  const course = use(promise);
  return <h1>{course.title}</h1>;
}

For production use a library or framework loader so promises are cached properly.

07Loading, Error and Empty States

Always design all four states:

if (isPending) return <Skeleton />;                    // loading
if (isError) return <ErrorState onRetry={refetch} />;  // error
if (data.length === 0) return <EmptyState />;          // empty
return <List items={data} />;                          // success
  • Prefer skeletons over spinners for content areas
  • Show stale data while refreshing (isFetching indicator)
  • Give errors a retry action and a human message

08Authentication with APIs

ApproachNotes
HTTP-only cookie sessionSafest for browsers; send with credentials: "include"; needs CSRF protection

Handle 401 globally (redirect to login), refresh tokens in one place, and cancel requests on logout.

11Quick Recap

  • Check res.ok with fetch; centralise requests in an API client; keep secrets off the front end
  • Server state (cached copy of remote data) needs different tooling than UI state
  • TanStack Query: useQuery (keys, staleTime), useMutation + invalidateQueries, optimistic updates, pagination, Suspense
  • Always handle loading, error and empty states
  • Prefer cookie-based sessions or in-memory tokens over localStorage tokens
