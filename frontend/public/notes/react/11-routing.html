Routing with React Router

Multi-page navigation in a single-page app. Routes, links, nested layouts, URL parameters, search params, loaders and actions, protected routes and lazy-loaded pages with React Router v7.

01Why Routing?

A single-page application (SPA) loads one HTML page and swaps the UI with JavaScript. A router keeps the URL in sync with what's on screen, so links, bookmarks, the back button and sharing all work.

React Router v7 is the most popular router. It merges the old Remix framework and works in three modes:

ModeDescription
Declarative<BrowserRouter> + <Routes>: simple, client-side routing
DatacreateBrowserRouter + loaders/actions: data fetching tied to routes
FrameworkFull-stack (SSR, file routes, type safety) built on Vite

These notes focus on declarative and data modes. In v7 everything is imported from react-router (the separate react-router-dom package is no longer needed).

npm install react-router

02Declarative Routing

import { BrowserRouter } from "react-router";

createRoot(document.getElementById("root")).render(
  <BrowserRouter>
    <App />
  </BrowserRouter>
);
import { Routes, Route, Link, NavLink } from "react-router";

function App() {
  return (
    <>
      <nav>
        <NavLink to="/" end>Home</NavLink>
        <NavLink to="/courses">Courses</NavLink>
        <NavLink to="/about">About</NavLink>
      </nav>

      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/courses" element={<Courses />} />
        <Route path="/courses/:courseId" element={<CourseDetail />} />
        <Route path="/about" element={<About />} />
        <Route path="*" element={<NotFound />} />
      </Routes>
    </>
  );
}

Link vs anchor

<Link to="/courses">Courses</Link>              {/* client-side navigation: no page reload */}
<a href="https://example.com">External</a>      {/* use <a> for external sites */}

NavLink for active styling

<NavLink to="/courses" className={({ isActive }) => (isActive ? "link active" : "link")}>Courses</NavLink>
<NavLink to="/" end>Home</NavLink>               {/* `end` stops "/" matching every path */}

03URL Parameters

<Route path="/courses/:courseId/lessons/:lessonId" element={<Lesson />} />

import { useParams } from "react-router";

function Lesson() {
  const { courseId, lessonId } = useParams();       // always strings
  return <p>Course {courseId}, lesson {lessonId}</p>;
}

Optional segments: path="/users/:id?". Splats: path="/files/*" (params["*"]).

04Search Params (Query String)

import { useSearchParams } from "react-router";

function Courses() {
  const [params, setParams] = useSearchParams();
  const level = params.get("level") ?? "all";
  const page = Number(params.get("page") ?? 1);

  return (
    <>
      <select value={level} onChange={e => setParams({ level: e.target.value, page: 1 })}>
        <option value="all">All</option>
        <option value="beginner">Beginner</option>
      </select>
      <button onClick={() => setParams(p => { p.set("page", String(page + 1)); return p; })}>Next</button>
    </>
  );
}

Keep filters, sorting and pagination in the URL so views are shareable and survive refresh.

05Nested Routes and Layouts

Child routes render inside the parent's <Outlet />.

import { Outlet } from "react-router";

function DashboardLayout() {
  return (
    <div className="layout">
      <Sidebar />
      <main><Outlet /></main>        {/* matched child route renders here */}
    </div>
  );
}

<Routes>
  <Route path="/" element={<MarketingLayout />}>
    <Route index element={<Home />} />
    <Route path="pricing" element={<Pricing />} />
  </Route>

  <Route path="/dashboard" element={<DashboardLayout />}>
    <Route index element={<Overview />} />                 {/* /dashboard */}
    <Route path="courses" element={<MyCourses />} />       {/* /dashboard/courses */}
    <Route path="courses/:id" element={<CourseProgress />} />
    <Route path="settings" element={<Settings />} />
  </Route>

  <Route path="*" element={<NotFound />} />
</Routes>
  • index marks the default child
  • Child paths are relative to the parent
  • A layout route without path can wrap routes without affecting the URL
  • Pass data to children with <Outlet context={…} /> and useOutletContext()

06Programmatic Navigation

import { useNavigate, Navigate } from "react-router";

function Login() {
  const navigate = useNavigate();

  async function handleSubmit() {
    await login();
    navigate("/dashboard", { replace: true });       // replace: back button won't return to login
  }
}

navigate(-1);                                         // go back
<Navigate to="/login" replace />                      // redirect during render

Other hooks: useLocation() (pathname, search, state), useMatch, useNavigationType.

Pass hidden data with navigate("/thanks", { state: { orderId: 7 } }) and read it via useLocation().state.

07Data Mode: createBrowserRouter

Define routes as objects, with loaders (fetch data before rendering), actions (handle form submissions) and error elements.

import { createBrowserRouter } from "react-router";
import { RouterProvider } from "react-router/dom";

const router = createBrowserRouter([
  {
    path: "/",
    element: <RootLayout />,
    errorElement: <RootError />,
    children: [
      { index: true, element: <Home /> },
      {
        path: "courses",
        element: <Courses />,
        loader: coursesLoader,
      },
      {
        path: "courses/:courseId",
        element: <CourseDetail />,
        loader: courseLoader,
        action: enrollAction,
      },
    ],
  },
]);

createRoot(document.getElementById("root")).render(<RouterProvider router={router} />);

Loaders

export async function courseLoader({ params, request }) {
  const res = await fetch(`/api/courses/${params.courseId}`, { signal: request.signal });
  if (res.status === 404) throw new Response("Not found", { status: 404 });
  return res.json();
}

import { useLoaderData } from "react-router";

function CourseDetail() {
  const course = useLoaderData();                    // data is ready when the component renders
  return <h1>{course.title}</h1>;
}

Benefits: no loading spinners-inside-components for first render, parallel data loading for nested routes, no request waterfalls, automatic cancellation.

Actions and Forms

import { Form, redirect, useNavigation, useActionData } from "react-router";

export async function enrollAction({ request, params }) {
  const data = await request.formData();
  const email = data.get("email");
  if (!email) return { error: "Email is required" };
  await api.enroll(params.courseId, email);
  return redirect(`/courses/${params.courseId}/thanks`);
}

function EnrollForm() {
  const navigation = useNavigation();                // "idle" | "loading" | "submitting"
  const actionData = useActionData();
  return (
    <Form method="post">
      <input name="email" type="email" />
      {actionData?.error && <p role="alert">{actionData.error}</p>}
      <button disabled={navigation.state === "submitting"}>Enroll</button>
    </Form>
  );
}

After an action, React Router automatically revalidates loaders so the page shows fresh data.

Pending UI and fetchers

const navigation = useNavigation();
{navigation.state === "loading" && <TopProgressBar />}

const fetcher = useFetcher();                        // submit/load without navigating
<fetcher.Form method="post" action="/like"><button>{fetcher.state === "idle" ? "Like" : "…"}</button></fetcher.Form>

Error handling

import { useRouteError, isRouteErrorResponse } from "react-router";

function RootError() {
  const error = useRouteError();
  if (isRouteErrorResponse(error)) return <h1>{error.status} {error.statusText}</h1>;
  return <h1>Unexpected error: {error.message}</h1>;
}

Each route can have its own errorElement; errors bubble to the nearest one.

08Protected Routes

function RequireAuth({ roles }) {
  const { user, loading } = useAuth();
  const location = useLocation();

  if (loading) return <Spinner />;
  if (!user) return <Navigate to="/login" replace state={{ from: location }} />;
  if (roles && !roles.includes(user.role)) return <Navigate to="/403" replace />;
  return <Outlet />;
}

<Routes>
  <Route path="/login" element={<Login />} />
  <Route element={<RequireAuth />}>
    <Route path="/dashboard" element={<Dashboard />} />
  </Route>
  <Route element={<RequireAuth roles={["admin"]} />}>
    <Route path="/admin" element={<Admin />} />
  </Route>
</Routes>

After login: navigate(location.state?.from?.pathname ?? "/dashboard", { replace: true }).

Warning

Client-side route guards only hide UI. Always enforce authorisation on the server/API; anyone can read your front-end code.

09Lazy Loading Routes

const router = createBrowserRouter([
  {
    path: "/reports",
    lazy: async () => {
      const { Reports, loader } = await import("./pages/Reports");   // code-split per route
      return { Component: Reports, loader };
    },
  },
]);

Or with declarative routes: const Reports = lazy(() => import("./Reports")) inside <Suspense>.

10Scroll, Titles and Focus

  • <ScrollRestoration /> restores scroll positions between navigations (data mode)
  • Update the title per route with <title> in the page component (React 19)
  • Move focus to the main heading on navigation for screen reader users

11URL Design Tips

  • Use meaningful, lowercase, hyphenated paths: /courses/react-19
  • Prefer slugs or ids that are stable
  • Put filters in query strings, resource identity in the path
  • Provide a catch-all * 404 route
  • Redirect old URLs with <Navigate> or a loader redirect()

12Hosting a Client-side Router

Because routes like /courses/5 don't exist as files, the server must return index.html for unknown paths (SPA fallback). Netlify: _redirects (/* /index.html 200); Vercel: rewrites; Nginx: try_files $uri /index.html;. Vite's dev server does this automatically.

14Quick Recap

  • Install react-router (v7); use BrowserRouter for simple apps or createBrowserRouter + RouterProvider for data APIs
  • Link/NavLink navigate without reloads; useNavigate for code; useParams and useSearchParams read the URL
  • Nested routes render through <Outlet />; index is the default child
  • Loaders fetch data per route, actions handle form posts, errorElement handles failures
  • Protect routes with a wrapper using Navigate, but enforce security on the server
  • Lazy-load route components; configure the server for SPA fallback
