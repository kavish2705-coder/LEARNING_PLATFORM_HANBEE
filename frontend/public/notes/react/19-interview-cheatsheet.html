Interview Questions and Cheat Sheet

Quick-revision answers to the most common React interview questions, a hooks cheat sheet, common bugs and their fixes, and a learning roadmap.

01Core Concepts

Interview question

What is React, and why use it?

A JavaScript library for building UIs from reusable components. It is declarative, uses a virtual DOM and reconciliation to update the real DOM efficiently, has one-way data flow and a very large ecosystem.

Interview question

What is the virtual DOM and how does reconciliation work?

The virtual DOM is a lightweight in-memory description of the UI. On each update React renders a new tree, diffs it against the previous one (same type and key = update, different = replace), and commits only the minimal changes to the real DOM.

Interview question

What is JSX? Can the browser read it?

A syntax extension that looks like HTML and compiles (via Babel/SWC) to function calls (jsx(...)). Browsers cannot run it directly, so a build step is required.

Interview question

Function vs class components?

Function components with hooks are the standard. Classes still work but are legacy, and are needed only for error boundaries (or use react-error-boundary).

Interview question

Props vs state?

Props are read-only inputs passed from a parent. State is data owned and updated by the component itself (via useState/useReducer); changing it triggers a re-render.

Interview question

What is unidirectional data flow?

Data flows from parent to child through props. Children communicate upwards by calling callbacks passed as props.

Interview question

Controlled vs uncontrolled components?

Controlled: input value lives in React state (value + onChange). Uncontrolled: the DOM holds the value, read via a ref or FormData. React 19 form actions make uncontrolled forms ergonomic.

Interview question

Why do lists need keys?

Keys give each item a stable identity so React can match items between renders, preserving state and minimising DOM changes. Use unique stable ids, not array indexes for dynamic lists.

Interview question

What is lifting state up?

Moving shared state to the closest common ancestor and passing it down with callbacks to update it.

Interview question

What is prop drilling and how do you avoid it?

Passing props through components that don't use them. Avoid with composition (children), Context, or a state library.

02Hooks

Interview question

What are the Rules of Hooks?

Call hooks only at the top level (no loops, conditions or nested functions) and only from React function components or custom hooks. Hooks rely on call order. (use() in React 19 can be conditional.)

Interview question

Explain useEffect and its dependency array.

Runs after render to sync with external systems. No array: after every render. []: once after mount. [a, b]: when a or b change. The returned function cleans up before the next run and on unmount.

Interview question

Why does useEffect run twice in development?

StrictMode mounts, unmounts and re-mounts to verify your effects clean up correctly. It does not happen in production.

Interview question

useMemo vs useCallback vs React.memo?

useMemo caches a computed value, useCallback caches a function reference, React.memo skips re-rendering a component when props are shallow-equal. The React Compiler automates most of this.

Interview question

useState vs useReducer?

useReducer centralises complex or related state transitions in a pure reducer, making them easier to test; useState is simpler for independent values.

Interview question

What does useRef do, and how does it differ from state?

Holds a mutable .current value across renders without triggering re-renders. Used for DOM nodes and instance-like values (timers, previous values).

Interview question

useLayoutEffect vs useEffect?

useLayoutEffect runs synchronously after DOM mutations but before paint (for measuring/positioning). useEffect runs after paint and is the default.

Interview question

What is a custom hook?

A function starting with use that composes other hooks to reuse stateful logic. Each caller gets isolated state.

Interview question

What causes a stale closure and how do you fix it?

A function captures values from the render in which it was created. If it outlives that render (effects, timers) it sees old values. Fix with correct dependencies, updater functions (setX(x => x + 1)), refs, or useEffectEvent.

03Rendering and Performance

Interview question

When does a component re-render?

When its state changes, its parent re-renders, or a context it consumes changes.

Interview question

How do you optimise a slow React app?

Measure with the Profiler; move state down; avoid unnecessary effects; memoise (or use the React Compiler); split code with lazy/Suspense; virtualise long lists; use transitions for heavy updates; optimise images and bundle size.

Interview question

What is useTransition/useDeferredValue?

Tools to mark updates as non-urgent so urgent interactions (typing) stay responsive. useTransition wraps the state update and gives isPending; useDeferredValue defers a value.

Interview question

What is Suspense?

A boundary that shows a fallback while descendants are not ready (lazy components, use(promise), data libraries, streaming SSR).

Interview question

What are error boundaries?

Components that catch render-time errors in their subtree and show a fallback. They don't catch event-handler or async errors.

Interview question

What are portals?

createPortal(children, domNode) renders children into another DOM node while keeping them in the same React tree, which is useful for modals and tooltips.

Interview question

What is hydration?

Attaching React's event handling and state to server-rendered HTML in the browser so it becomes interactive.

04React 19

Interview question

What's new in React 19?

Actions (async transitions), useActionState, useFormStatus, useOptimistic, the use API, ref as a prop, <Context> as provider, metadata tags (<title>, <meta>) from any component, stylesheet/script handling, better hydration and error reporting, stable Server Components and Server Actions. 19.2 added <Activity> and useEffectEvent.

Interview question

What does use() do and how is it different from hooks?

It reads a Promise (suspending until resolved) or a Context. Unlike hooks it can be called conditionally and in loops. Promises should be created outside render (parent, cache, Server Component).

Interview question

What is useActionState?

Wraps an action function (prevState, formData) => newState and returns [state, formAction, isPending], replacing hand-written submit/pending/error state.

Interview question

What is useOptimistic?

Shows an expected state immediately while an async action runs; React reverts automatically if the real state doesn't confirm.

Interview question

Is forwardRef still needed?

No. In React 19 function components receive ref as a normal prop; forwardRef is deprecated.

Interview question

What was removed in React 19?

propTypes and defaultProps (function components), ReactDOM.render/hydrate, findDOMNode, string refs, legacy context, react-test-renderer/shallow, UMD builds.

Interview question

What is the React Compiler?

A build-time tool that automatically memoises components and values, reducing the need for manual useMemo/useCallback/memo, provided code follows the Rules of React.

Interview question

What are Server Components?

Components that render only on the server, so their code isn't shipped to the client and they can access data sources directly. Interactive parts are Client Components marked with "use client".

Interview question

Are Server Actions secure by default?

They are public endpoints. You must authenticate, authorise and validate input inside every one.

05State Management and Ecosystem

Interview question

How do you manage global state?

Keep state local first. Use Context for rarely changing global values, Zustand/Redux Toolkit/Jotai for complex client state, TanStack Query for server state, and the URL for filters/pagination.

Interview question

Context vs Redux?

Context is a built-in way to pass values without drilling but re-renders all consumers on change and has no tooling. Redux Toolkit adds a predictable store, selectors, middleware and DevTools for large apps.

Interview question

Why use TanStack Query instead of useEffect + useState?

It handles caching, deduplication, background refetching, retries, pagination, mutations and invalidation, which are easy to get wrong by hand.

Interview question

CSR vs SSR vs SSG?

CSR builds HTML in the browser; SSR builds it per request on the server; SSG builds it at build time. SSR/SSG improve first paint and SEO.

Interview question

How would you protect routes?

A wrapper route that checks auth and redirects with <Navigate> plus role checks, but real enforcement must happen on the server/API.

Interview question

Where should you store JWTs?

Prefer HttpOnly, Secure, SameSite cookies, or short-lived tokens in memory with a refresh cookie. Avoid localStorage for sensitive tokens because XSS can read it.

Interview question

How do you test React components?

Vitest/Jest with React Testing Library and user-event, querying by role/label; MSW for network mocking; Playwright for end-to-end flows.

08Coding Challenge Ideas

  1. Counter with step and reset
  2. Todo list with filters (all/active/done) and localStorage
  3. Debounced search over an API
  4. Accordion and tabs (compound components)
  5. Modal with focus trap and Escape to close
  6. Infinite scroll list with IntersectionObserver
  7. Star rating and form validation
  8. Pagination component with URL search params
  9. Custom hooks: useDebounce, useLocalStorage, useFetch
  10. Optimistic "like" button with useOptimistic

09Learning Roadmap

  1. JavaScript fundamentals (ES6+, async, DOM, HTTP)
  2. React core: components, props, state, effects, forms
  3. Routing + data fetching: React Router, TanStack Query
  4. TypeScript with React
  5. Styling system: Tailwind or CSS Modules + a headless UI library
  6. State management (Zustand or Redux Toolkit) when needed
  7. Testing: Vitest, RTL, Playwright
  8. Framework: Next.js or React Router framework mode (Server Components, Server Actions)
  9. Production: accessibility, security, performance, CI/CD, monitoring
  10. Build projects: a course dashboard, e-commerce cart, chat or kanban board, then deploy them

10Official Resources

  • react.dev (documentation and interactive tutorial): the primary source
  • React Router, TanStack Query, Zustand, Redux Toolkit, Testing Library docs
  • web.dev for performance and accessibility guidance
  • Read the React release blog posts when new versions ship

11Quick Recap

  • Know the core model: components, props down, events up, state triggers renders
  • Be able to explain every hook and the Rules of Hooks, effects and cleanup, and stale closures
  • Know what React 19 changed: Actions, use, new form hooks, ref prop, Compiler, Server Components
  • Match tools to problems: Query for server state, Context/Zustand/RTK for client state, URL for filters
  • Practise by building and deploying real projects
