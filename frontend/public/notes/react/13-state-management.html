Global State Management

Decide where state belongs and pick the right tool. Context limits, Zustand, Redux Toolkit, Jotai, URL state and a practical decision guide.

01Types of State

KindExamplesBest home
Local UI stateInput text, open/closed, hoveruseState in the component
Shared UI stateSelected item across siblingsLift state to common parent
Global client stateTheme, sidebar, cart, current user sessionContext / Zustand / Redux Toolkit
Server stateCourses, users, ordersTanStack Query / SWR
URL stateFilters, page, selected tabRouter search params
Form stateField values, errorsReact Hook Form / form actions
Note

Rule of thumb: Keep state as local as possible. Reach for a global store only when many distant components need the same client-side data.

02Prop Drilling and Its Fixes

Passing props through many layers that don't use them is prop drilling. Fixes, in order:

  1. Composition: pass the finished element or children instead of data
<Layout sidebar={<UserMenu user={user} />} />          // Layout never needs to know about `user`
  1. Context for stable, app-wide values
  2. A store for frequently changing global state

03Context API (Recap and Limits)

Great for theme, locale, auth user. Limitations:

  • All consumers re-render whenever the context value changes (no selectors)
  • Large, fast-changing state in one context causes broad re-renders
  • No built-in devtools, middleware or persistence

Split by concern and use useMemo for the value (or the React Compiler). For heavier needs pick one of the libraries below.

04Zustand

A tiny, popular store with a hook API and selectors (components re-render only when the selected slice changes). No providers needed.

npm install zustand
import { create } from "zustand";
import { persist, devtools } from "zustand/middleware";

export const useCart = create(
  devtools(
    persist(
      (set, get) => ({
        items: [],
        add: (course) => set(s => ({ items: s.items.some(i => i.id === course.id) ? s.items : [...s.items, course] })),
        remove: (id) => set(s => ({ items: s.items.filter(i => i.id !== id) })),
        clear: () => set({ items: [] }),
        total: () => get().items.reduce((sum, i) => sum + i.price, 0),
      }),
      { name: "cart" }                                       // saved in localStorage
    )
  )
);
function CartBadge() {
  const count = useCart(s => s.items.length);               // re-renders only when the count changes
  return <span>{count}</span>;
}

function AddButton({ course }) {
  const add = useCart(s => s.add);                           // actions are stable
  return <button onClick={() => add(course)}>Add to cart</button>;
}
Warning

Select primitive values or stable references. useCart(s => ({ a: s.a, b: s.b })) creates a new object each time; use useShallow from zustand/react/shallow.

Zustand strengths
Tiny API, minimal boilerplateWorks outside React (useCart.getState())
Selector-based re-rendersMiddleware: persist, devtools, immer

05Redux Toolkit (RTK)

The official, batteries-included way to use Redux: a single global store, predictable updates through actions and reducers, excellent DevTools (time travel). Best for large apps and teams that value strict structure.

npm install @reduxjs/toolkit react-redux

Concepts

UI → dispatch(action) → reducer(state, action) → new state → store → UI re-renders (via selectors)

Slice

import { createSlice } from "@reduxjs/toolkit";

const cartSlice = createSlice({
  name: "cart",
  initialState: { items: [] },
  reducers: {
    added(state, action) {
      state.items.push(action.payload);                      // "mutating" syntax is safe: Immer under the hood
    },
    removed(state, action) {
      state.items = state.items.filter(i => i.id !== action.payload);
    },
    cleared: (state) => { state.items = []; },
  },
});

export const { added, removed, cleared } = cartSlice.actions;
export default cartSlice.reducer;

Store and provider

import { configureStore } from "@reduxjs/toolkit";
import cartReducer from "./cartSlice";

export const store = configureStore({ reducer: { cart: cartReducer } });
import { Provider } from "react-redux";
<Provider store={store}><App /></Provider>

Use in components

import { useSelector, useDispatch } from "react-redux";

function Cart() {
  const items = useSelector(state => state.cart.items);
  const dispatch = useDispatch();
  return items.map(i => <button key={i.id} onClick={() => dispatch(removed(i.id))}>Remove {i.title}</button>);
}

Async logic and RTK Query

// createAsyncThunk for custom async flows
export const loadProfile = createAsyncThunk("user/load", async (id) => (await fetch(`/api/users/${id}`)).json());

// RTK Query: built-in server-state caching (like TanStack Query)
const api = createApi({
  baseQuery: fetchBaseQuery({ baseUrl: "/api" }),
  endpoints: (b) => ({
    getCourses: b.query({ query: () => "courses" }),
    addCourse: b.mutation({ query: (body) => ({ url: "courses", method: "POST", body }) }),
  }),
});
export const { useGetCoursesQuery, useAddCourseMutation } = api;

06Jotai (Atomic State)

State is split into small atoms; components subscribe to only the atoms they use. Feels like useState that can be shared.

import { atom, useAtom, useAtomValue } from "jotai";

const countAtom = atom(0);
const doubleAtom = atom(get => get(countAtom) * 2);          // derived atom

function Counter() {
  const [count, setCount] = useAtom(countAtom);
  const double = useAtomValue(doubleAtom);
  return <button onClick={() => setCount(c => c + 1)}>{count} / {double}</button>;
}

07URL as State

Filters, sort order, current tab and pagination belong in the query string (useSearchParams): shareable, bookmarkable, back-button friendly. Libraries like nuqs add type-safe helpers.

09Decision Guide

  1. Data from an API? → TanStack Query (not a global store)
  2. Used by one component or a parent/child? → useState / lift up
  3. Theme, locale, logged-in user? → Context
  4. Cart, UI flags, wizards, shared client state? → Zustand (or Jotai)
  5. Large team/app needing conventions, middleware and time-travel debugging? → Redux Toolkit
  6. Filters/pagination? → URL
  7. Form fields? → React Hook Form or form actions

10Patterns for Good Global State

  • Store minimal data (ids, flags); derive the rest with selectors
  • Normalise collections ({ byId: {}, ids: [] }) for large lists
  • Keep state serialisable (no class instances, no functions in Redux)
  • Put actions/updates next to the data they modify
  • Don't mirror server data in two places
  • Persist only what must survive reloads (token metadata, theme, cart)
  • Reset stores on logout to avoid leaking one user's data to the next

11Example: Auth Store (Zustand)

export const useAuth = create((set) => ({
  user: null,
  status: "loading",
  async init() {
    try { set({ user: await api("/me"), status: "authed" }); }
    catch { set({ user: null, status: "guest" }); }
  },
  async login(credentials) {
    const user = await api("/login", { method: "POST", body: credentials });
    set({ user, status: "authed" });
  },
  async logout() {
    await api("/logout", { method: "POST" });
    set({ user: null, status: "guest" });
    queryClient.clear();                                     // drop cached server data
  },
}));

12Quick Recap

  • Match state to its type: local, shared, global client, server, URL, form
  • Prefer composition and Context first; Context re-renders every consumer
  • Zustand: tiny, selector-based store; Redux Toolkit: structured, devtools, RTK Query; Jotai: atoms
  • Server data belongs in TanStack Query/RTK Query, not hand-managed in a store
  • Keep state minimal, derived values computed, and reset stores on logout
