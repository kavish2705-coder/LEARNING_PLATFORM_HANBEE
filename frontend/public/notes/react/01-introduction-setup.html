Introduction to React and Project Setup

What React is, why teams use it, how it updates the screen efficiently, and how to create, run and understand your first React 19 project with Vite.

01What is React?

React is a JavaScript library for building user interfaces, created at Facebook (Meta) and released in 2013. You describe what the screen should look like for the current data, and React updates the browser efficiently when that data changes.

  • Library, not a framework: it handles the view layer. You choose routing, data fetching and state tools (or use a framework built on React such as Next.js).
  • Component-based: a UI is a tree of small, reusable pieces.
  • Declarative: you write the result, not the step-by-step DOM updates.
  • Used by Meta, Netflix, Airbnb, Uber, Shopify and countless startups; also powers React Native for mobile apps.

Imperative vs declarative

// Imperative (vanilla JS): you manage every step
const btn = document.getElementById("like");
let likes = 0;
btn.addEventListener("click", () => {
  likes++;
  btn.textContent = `Likes: ${likes}`;
});
// Declarative (React): describe the UI for the current state
function LikeButton() {
  const [likes, setLikes] = useState(0);
  return <button onClick={() => setLikes(likes + 1)}>Likes: {likes}</button>;
}

03Core Ideas

Components

Functions that return UI. Names start with a capital letter.

Virtual DOM and reconciliation

React keeps a lightweight description of the UI in memory (the virtual DOM). When state changes:

  1. React renders your components again to produce a new description
  2. It compares (diffs) the new description with the previous one
  3. It commits only the minimal real DOM changes
state change → render components → diff vs previous tree → update only changed DOM nodes

Unidirectional data flow

Parents pass data down through props; children notify parents by calling functions passed down as props.

Rendering is a pure calculation

Given the same props and state, a component must return the same JSX. Side effects (network calls, timers) belong in event handlers or effects, never in the render body.

05What's New: React 19 at a Glance

React 19 became stable in December 2024; later 19.x releases add refinements (19.2 added <Activity> and useEffectEvent). Headline features, each covered in its own topic:

  • Actions: async functions for form submits and mutations, with built-in pending state, errors and optimistic updates
  • New hooks: useActionState, useOptimistic, useFormStatus, and the use API
  • ref as a prop: no more forwardRef for function components
  • Document metadata: render <title>, <meta>, <link> anywhere in a component
  • Server Components and Server Actions are stable
  • Better errors: clearer hydration diffs, onCaughtError / onUncaughtError
  • React Compiler (separate tool) auto-optimises your components

08Creating a Project with Vite

Note

Create React App (CRA) was officially deprecated in 2025. Vite is the standard way to start a client-side React app. For full-stack apps use a framework such as Next.js or React Router's framework mode.

npm create vite@latest my-app -- --template react        # or react-ts for TypeScript
cd my-app
npm install
npm run dev                                              # http://localhost:5173

Other commands:

npm run build      # production build into dist/
npm run preview    # serve the production build locally
npm run lint       # ESLint

Project structure

my-app/
├── index.html            ← the single HTML page (has <div id="root">)
├── package.json          ← dependencies and scripts
├── vite.config.js        ← Vite settings
├── public/               ← static files served as-is (favicon, robots.txt)
└── src/
    ├── main.jsx          ← entry point: mounts React into #root
    ├── App.jsx           ← root component
    ├── App.css, index.css
    └── assets/           ← images and fonts imported by code

The entry point

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "./index.css";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
<body>
  <div id="root"></div>
  <script type="module" src="/src/main.jsx"></script>
</body>

Your first component

function App() {
  const name = "Hanbee";
  return (
    <main>
      <h1>Hello, {name}!</h1>
      <p>Welcome to React 19.</p>
    </main>
  );
}

export default App;

09StrictMode

<StrictMode> is a development-only helper that surfaces bugs:

  • Renders components twice to catch impure rendering
  • Re-runs effects once (mount → unmount → mount) to catch missing cleanup
  • Warns about deprecated APIs

It has no effect in production builds. If you see logs twice in development, that is why.

11Handy Dev Habits

  • Keep one component per file; name the file after the component (StudentCard.jsx)
  • Use .jsx (or .tsx) for files that contain JSX
  • Run ESLint with eslint-plugin-react-hooks to catch hook mistakes
  • Use React DevTools to inspect props, state and re-renders
  • Commit early; add node_modules and dist to .gitignore

13Quick Recap

  • React builds UIs from components; you describe the UI, React updates the DOM
  • Data flows down through props; changes go up through callback functions
  • Start projects with Vite (npm create vite@latest); CRA is deprecated
  • main.jsx mounts the app with createRoot(...).render(...)
  • React 19 adds Actions, new hooks, ref as a prop and stable Server Components
