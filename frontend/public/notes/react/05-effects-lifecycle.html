Effects and Component Lifecycle

Synchronise components with the outside world using useEffect. Dependencies, cleanup, data fetching and race conditions, when not to use an effect, and useEffectEvent from React 19.2.

01What is an Effect?

An effect is code that runs after React has rendered to synchronise your component with something outside React: the network, browser APIs, timers, subscriptions, third-party widgets.

import { useEffect, useState } from "react";

function Clock() {
  const [now, setNow] = useState(new Date());

  useEffect(() => {
    const id = setInterval(() => setNow(new Date()), 1000);   // setup
    return () => clearInterval(id);                           // cleanup
  }, []);                                                      // dependencies

  return <p>{now.toLocaleTimeString()}</p>;
}

Event handlers vs effects

Event handlerEffect
Runs becauseThe user did something (click, submit)The component appeared or its data changed
PurposeRespond to an interactionKeep the component in sync with something external
ExampleonClick={() => save()}Connect to a chat room while visible
Tip

If the code runs because of a specific user action, put it in the event handler, not an effect.

02useEffect Anatomy

useEffect(() => {
  // 1. setup: runs after render (when dependencies change)
  return () => {
    // 2. cleanup: runs before the next setup and on unmount
  };
}, [dep1, dep2]);              // 3. dependency array

The dependency array

FormWhen the effect runs
useEffect(fn)After every render
useEffect(fn, [])Once after mount (and cleanup on unmount)
useEffect(fn, [a, b])After mount and whenever a or b changed

Every reactive value (props, state, variables derived from them) used inside the effect must be listed. The ESLint rule react-hooks/exhaustive-deps checks this; do not silence it.

Lifecycle mapping

Class lifecycleHook equivalent
componentDidMountuseEffect(() => {...}, [])
componentDidUpdateuseEffect(() => {...}, [deps])
componentWillUnmountcleanup function returned from the effect

Better mental model: an effect starts a synchronisation and its cleanup stops it. React may start and stop it several times.

03Cleanup

Clean up anything the effect started so nothing leaks.

useEffect(() => {
  const onResize = () => setWidth(window.innerWidth);
  window.addEventListener("resize", onResize);
  return () => window.removeEventListener("resize", onResize);
}, []);

useEffect(() => {
  const connection = createConnection(roomId);
  connection.connect();
  return () => connection.disconnect();
}, [roomId]);                                   // reconnects when roomId changes

Typical things to clean up: event listeners, timers (setTimeout/setInterval), subscriptions, WebSocket connections, in-flight fetches (AbortController).

04StrictMode Runs Effects Twice (in development)

In development React mounts, unmounts, then re-mounts each component once to test that your cleanup works. If your effect breaks when run twice, it is missing cleanup; fix it instead of removing StrictMode.

Dev:  setup → cleanup → setup      Production: setup

05Fetching Data in an Effect

function Courses() {
  const [courses, setCourses] = useState([]);
  const [status, setStatus] = useState("loading");     // loading | success | error

  useEffect(() => {
    const controller = new AbortController();

    async function load() {
      try {
        const res = await fetch("/api/courses", { signal: controller.signal });
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        setCourses(await res.json());
        setStatus("success");
      } catch (err) {
        if (err.name !== "AbortError") setStatus("error");
      }
    }
    load();

    return () => controller.abort();                    // cancel on unmount / re-run
  }, []);

  if (status === "loading") return <p>Loading…</p>;
  if (status === "error") return <p role="alert">Could not load courses.</p>;
  return <ul>{courses.map(c => <li key={c.id}>{c.title}</li>)}</ul>;
}

Race conditions

If a query depends on state (like a search term), responses can arrive out of order. Ignore stale responses:

useEffect(() => {
  let ignore = false;
  fetchResults(query).then(data => {
    if (!ignore) setResults(data);
  });
  return () => { ignore = true; };                      // outdated request is ignored
}, [query]);
Tip

For real applications use a data library (TanStack Query, SWR) or a framework's data loading. They handle caching, retries, deduplication and race conditions for you. See the Data Fetching topic.

06You Might Not Need an Effect

Effects are an escape hatch. Many uses are mistakes:

SituationDo this instead
Transform data for displayCompute it during render
Expensive calculationuseMemo (or let the React Compiler do it)
Reset state when a prop changesGive the component a different key
Handle a user actionDo it in the event handler
Update state based on other stateDerive it, or compute in the handler
Notify a parent of a changeCall the parent's callback in the event handler
// Bad: effect to derive state (extra render, can desync)
const [fullName, setFullName] = useState("");
useEffect(() => setFullName(first + " " + last), [first, last]);

// Good
const fullName = first + " " + last;
// Bad: effect to react to a click
useEffect(() => { if (submitted) post(form); }, [submitted]);

// Good
function handleSubmit() { post(form); }

07Common Effect Use Cases

// Update document title
useEffect(() => { document.title = `${count} new messages`; }, [count]);

// Persist to localStorage
useEffect(() => { localStorage.setItem("theme", theme); }, [theme]);

// Subscribe to an external store: prefer useSyncExternalStore (below)
// Focus an input on mount
const ref = useRef(null);
useEffect(() => { ref.current?.focus(); }, []);

// Debounce
useEffect(() => {
  const id = setTimeout(() => setDebounced(value), 300);
  return () => clearTimeout(id);
}, [value]);

// Keyboard shortcut
useEffect(() => {
  const onKey = (e) => { if (e.key === "Escape") onClose(); };
  window.addEventListener("keydown", onKey);
  return () => window.removeEventListener("keydown", onKey);
}, [onClose]);

08Dependency Pitfalls

Infinite loops

useEffect(() => {
  setCount(count + 1);          // changes count → re-renders → effect runs again → loop
}, [count]);

Objects, arrays and functions created in the component body are new on every render, so putting them in the dependency array re-runs the effect every time.

// Problem: options is a new object each render
const options = { roomId };
useEffect(() => connect(options), [options]);

// Fix: depend on primitives, or create the object inside the effect
useEffect(() => connect({ roomId }), [roomId]);

Stale closures

An effect "closes over" the values from the render it was created in. Leaving a value out of the dependency array makes the effect see an old value.

useEffect(() => {
  const id = setInterval(() => console.log(count), 1000);   // always logs the initial count
  return () => clearInterval(id);
}, []);                                                       // count is missing!

Fix by adding the dependency, or use an updater function (setCount(c => c + 1)).

09useEffectEvent (React 19.2)

Sometimes an effect should react to some values but read the latest of others without re-running. useEffectEvent extracts that "event" logic.

import { useEffect, useEffectEvent } from "react";

function ChatRoom({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    showNotification("Connected!", theme);       // always sees the latest theme
  });

  useEffect(() => {
    const connection = createConnection(roomId);
    connection.on("connected", onConnected);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId]);                                   // reconnect only when roomId changes
}

Rules: call Effect Events only inside effects, never pass them to other components, and do not list them in the dependency array.

10useLayoutEffect

Runs synchronously after DOM changes but before the browser paints. Use only to measure the DOM and adjust layout without flicker (tooltips, positioning). Prefer useEffect otherwise because useLayoutEffect blocks painting.

useLayoutEffect(() => {
  const { height } = ref.current.getBoundingClientRect();
  setTooltipHeight(height);
}, []);

11useSyncExternalStore

The correct hook for subscribing to external stores (browser APIs, state libraries) without tearing.

function useOnlineStatus() {
  return useSyncExternalStore(
    (callback) => {
      window.addEventListener("online", callback);
      window.addEventListener("offline", callback);
      return () => {
        window.removeEventListener("online", callback);
        window.removeEventListener("offline", callback);
      };
    },
    () => navigator.onLine,         // client snapshot
    () => true                      // server snapshot
  );
}

12useEffect vs useLayoutEffect vs useInsertionEffect

HookRunsUse for
useEffectAfter paintAlmost everything
useLayoutEffectBefore paintMeasuring and positioning
useInsertionEffectBefore layout effectsCSS-in-JS libraries inserting styles

13Debugging Effects

  • Log inside setup and cleanup to see the order
  • Remember StrictMode doubles effects in development
  • Check the dependency list with the ESLint rule
  • Use React DevTools Profiler to see why something re-rendered
  • Ask: "Could this be done during render or in an event handler?"

14Quick Recap

  • Effects synchronise a component with external systems and run after render
  • Dependency array controls when: none = every render, [] = once, [a] = when a changes
  • Always clean up listeners, timers, subscriptions and requests
  • Handle race conditions with ignore flags or AbortController; prefer TanStack Query for data
  • Don't use effects for derived data or user actions; use render-time calculation and event handlers
  • useEffectEvent (19.2) reads the latest values without making the effect re-run
