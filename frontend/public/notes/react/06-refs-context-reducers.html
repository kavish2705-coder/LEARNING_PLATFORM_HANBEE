Refs, Context and Reducers

Reach the DOM with useRef, avoid prop drilling with Context, and manage complex state with useReducer. Includes ref as a prop and the simplified Context syntax from React 19.

01useRef

useRef returns a mutable object { current: value } that React keeps between renders. Changing ref.current does not trigger a re-render.

import { useRef } from "react";

const ref = useRef(null);       // React 19: an initial argument is required (TypeScript too)
ref.current = 5;                // mutate freely

Use 1: Access a DOM element

function SearchBox() {
  const inputRef = useRef(null);

  return (
    <>
      <input ref={inputRef} placeholder="Search" />
      <button onClick={() => inputRef.current.focus()}>Focus</button>
    </>
  );
}

Common DOM tasks: focus(), scrollIntoView(), measuring size (getBoundingClientRect()), playing a <video>, integrating a non-React library.

Use 2: Store values that should not cause renders

function Stopwatch() {
  const [time, setTime] = useState(0);
  const intervalRef = useRef(null);                    // timer id: not shown in UI

  const start = () => { intervalRef.current = setInterval(() => setTime(t => t + 1), 1000); };
  const stop = () => clearInterval(intervalRef.current);

  return <><p>{time}s</p><button onClick={start}>Start</button><button onClick={stop}>Stop</button></>;
}

Also good for: previous values, timeouts, whether a component is mounted, any "instance variable".

State vs ref

useStateuseRef
Change triggers re-renderYesNo
Value read during renderYes (it is the UI)Avoid reading/writing current during render
Mutable directlyNo (use setter)Yes
Use forData shown on screenTimers, DOM nodes, mutable instance values
Warning

Do not read or write ref.current during rendering (except for lazy initialisation). It makes components unpredictable.

Ref callbacks and cleanup (React 19)

A ref can be a function. In React 19 it may return a cleanup function.

<div
  ref={(node) => {
    const observer = new ResizeObserver(() => console.log("resized"));
    observer.observe(node);
    return () => observer.disconnect();       // new in React 19: runs when the element is removed
  }}
/>

Refs to a list of nodes

<ul>
  {items.map(item => (
    <li key={item.id} ref={(node) => {
      map.set(item.id, node);
      return () => map.delete(item.id);       // clean up (React 19)
    }}>{item.name}</li>
  ))}
</ul>

02ref as a Prop (React 19)

Function components now receive ref as a normal prop, so forwardRef is no longer needed. (forwardRef still works but is deprecated and will be removed.)

// React 19
function MyInput({ ref, label, ...props }) {
  return (
    <label>
      {label}
      <input ref={ref} {...props} />
    </label>
  );
}

function Form() {
  const inputRef = useRef(null);
  return <MyInput ref={inputRef} label="Name" />;
}
// Before React 19
const MyInput = forwardRef(function MyInput({ label, ...props }, ref) {
  return <label>{label}<input ref={ref} {...props} /></label>;
});

useImperativeHandle

Expose only specific methods to a parent instead of the whole DOM node.

function FancyInput({ ref }) {
  const inner = useRef(null);
  useImperativeHandle(ref, () => ({
    focus: () => inner.current.focus(),
    clear: () => { inner.current.value = ""; },
  }), []);
  return <input ref={inner} />;
}

Use sparingly; prefer props and state when possible.

03Context

Context lets a parent make data available to any descendant without passing props through every level (prop drilling).

Without context:  App → Layout → Sidebar → UserMenu → Avatar   (user passed through each)
With context:     App provides user → Avatar reads it directly

Create, provide, consume

import { createContext, useContext, useState } from "react";

const ThemeContext = createContext("light");                 // default value

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState("light");
  const toggle = () => setTheme(t => (t === "light" ? "dark" : "light"));

  return (
    <ThemeContext value={{ theme, toggle }}>                 {/* React 19: no .Provider needed */}
      {children}
    </ThemeContext>
  );
}

export function useTheme() {                                  // custom hook wraps useContext
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("useTheme must be used inside <ThemeProvider>");
  return ctx;
}
// main.jsx
<ThemeProvider><App /></ThemeProvider>

// anywhere deep inside
function ThemeButton() {
  const { theme, toggle } = useTheme();
  return <button onClick={toggle}>Theme: {theme}</button>;
}
Note

In React 19 you render <ThemeContext value={...}> directly. <ThemeContext.Provider> still works but is deprecated.

Reading context with use() (React 19)

import { use } from "react";
const { theme } = use(ThemeContext);        // like useContext, but may be called conditionally

When to use context

Good for rarely changing, app-wide values:

  • Theme and locale
  • Current authenticated user
  • Feature flags
  • Router and query client (libraries use it internally)

Context performance

  • Every consumer re-renders when the context value changes
  • A new object in value={{ ... }} on every render triggers consumers each time; keep it stable (React Compiler or useMemo)
  • Split contexts by concern (UserContext, ThemeContext) and by update frequency
  • Separate state and dispatch contexts to avoid unnecessary renders
  • For frequently changing global state use Zustand, Redux Toolkit or Jotai (see State Management)
const value = useMemo(() => ({ theme, toggle }), [theme]);   // not needed with the React Compiler

04useReducer

useReducer manages state with a reducer function: (state, action) => newState. Ideal when state has many fields or many ways to change.

import { useReducer } from "react";

const initial = { items: [], filter: "all" };

function reducer(state, action) {
  switch (action.type) {
    case "added":
      return { ...state, items: [...state.items, { id: action.id, text: action.text, done: false }] };
    case "toggled":
      return { ...state, items: state.items.map(i => i.id === action.id ? { ...i, done: !i.done } : i) };
    case "removed":
      return { ...state, items: state.items.filter(i => i.id !== action.id) };
    case "filter_set":
      return { ...state, filter: action.filter };
    default:
      throw new Error(`Unknown action: ${action.type}`);
  }
}

function Todos() {
  const [state, dispatch] = useReducer(reducer, initial);

  return (
    <>
      <button onClick={() => dispatch({ type: "added", id: crypto.randomUUID(), text: "New" })}>Add</button>
      {state.items.map(i => (
        <label key={i.id}>
          <input type="checkbox" checked={i.done} onChange={() => dispatch({ type: "toggled", id: i.id })} />
          {i.text}
        </label>
      ))}
    </>
  );
}

Rules for reducers

  • Pure: no API calls, no random values, no mutation of state
  • Return a new state object
  • Describe what happened in the action ("added"), not what to set

useState vs useReducer

useStateuseReducer
Code sizeSmaller for simple stateMore boilerplate
Complex logicScattered in handlersCentralised in the reducer
Related fieldsSeveral useState callsOne state object
TestingTest the componentTest the reducer as a plain function
Passing updates downMany settersOne dispatch

05Context + useReducer (mini global store)

const TasksContext = createContext(null);
const TasksDispatchContext = createContext(null);

export function TasksProvider({ children }) {
  const [tasks, dispatch] = useReducer(tasksReducer, []);
  return (
    <TasksContext value={tasks}>
      <TasksDispatchContext value={dispatch}>
        {children}
      </TasksDispatchContext>
    </TasksContext>
  );
}

export const useTasks = () => useContext(TasksContext);
export const useTasksDispatch = () => useContext(TasksDispatchContext);

Components that only dispatch don't re-render when the tasks change, because dispatch is stable.

07Quick Recap

  • useRef keeps a mutable value or DOM node across renders without re-rendering
  • React 19: ref is a normal prop (no forwardRef), ref callbacks can return cleanup, useRef needs an argument
  • Context removes prop drilling for app-wide values; <Context value> in 19; use(Context) can be conditional
  • Context re-renders all consumers when its value changes, so keep it for slow-changing data
  • useReducer centralises complex state transitions in a pure reducer
