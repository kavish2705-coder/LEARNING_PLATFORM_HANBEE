JSX, Components and Props

Write UI with JSX, build and compose function components, pass data with props and children, render conditionally and render lists with keys.

01What is JSX?

JSX is a syntax extension that lets you write HTML-like markup inside JavaScript. A build tool (Vite/Babel/SWC) converts it to plain JavaScript function calls.

const element = <h1 className="title">Hello, React!</h1>;
// is compiled to roughly:
const element2 = jsx("h1", { className: "title", children: "Hello, React!" });

JSX is not required, but it is how almost everyone writes React.

02JSX Rules

1. Return a single root element

// Wrong: two siblings
// return <h1>Title</h1><p>Text</p>;

// Right: wrap in a parent, or a Fragment
return (
  <>
    <h1>Title</h1>
    <p>Text</p>
  </>
);

<>...</> is a Fragment: it groups elements without adding a DOM node. Use <Fragment key={id}> when you need a key.

2. Close every tag

<img src="logo.png" alt="Logo" />
<input type="text" />
<br />

3. Use camelCase for attributes

HTMLJSX
classclassName
forhtmlFor
onclickonClick
tabindextabIndex
maxlengthmaxLength
stroke-widthstrokeWidth
style="color:red"style={{ color: "red" }}

aria-* and data-* attributes keep their hyphenated names.

4. JavaScript goes inside curly braces

const user = { name: "Asha", score: 92 };
return (
  <section>
    <h2>{user.name}</h2>
    <p>Score: {user.score}</p>
    <p>Grade: {user.score >= 90 ? "A" : "B"}</p>
    <p>{new Date().getFullYear()}</p>
    <img src={user.avatar} alt={`${user.name}'s avatar`} />
  </section>
);

Curly braces accept expressions (values), not statements like if or for.

5. Comments in JSX

{/* a JSX comment */}

6. Inline styles take an object

<div style={{ backgroundColor: "navy", padding: 16 }}>Box</div>

Numbers become px. Prefer CSS classes for anything beyond simple dynamic values.

7. JSX escapes content automatically

Text inside {} is escaped, which protects against XSS. Only dangerouslySetInnerHTML bypasses this (avoid it, or sanitise first).

03Components

A component is a JavaScript function that returns JSX. The name must start with a capital letter.

function Welcome() {
  return <h1>Welcome to Hanbee LMS</h1>;
}

export default Welcome;
import Welcome from "./Welcome";

function App() {
  return (
    <div>
      <Welcome />
      <Welcome />
    </div>
  );
}

Rules of components

  • Capitalised name (<Card /> is a component; <card> is an HTML tag)
  • Pure: same props + state = same output, no changing outside variables during render
  • Define components at the top level of a file, never inside another component
  • Each component can return JSX, null (nothing), a string, a number or an array

04Props

Props (properties) are the inputs to a component. They flow down from parent to child and are read-only.

function Greeting({ name, role = "Student" }) {   // destructured, with a default
  return <p>Hello {name}, you are a {role}.</p>;
}

<Greeting name="Asha" />
<Greeting name="Ravi" role="Mentor" />

Passing different types

<Course
  title="React 19"            // string
  lessons={24}                // number
  free                        // boolean true (shorthand for free={true})
  tags={["ui", "js"]}         // array
  author={{ name: "Hanbee" }} // object
  onEnroll={() => alert("Enrolled")}   // function
/>

Spreading props

const props = { title: "React", level: "Beginner" };
<Course {...props} />

Props are read-only

function Bad({ count }) {
  count = count + 1;     // never reassign or mutate props
}

If a component needs to change a value, it should keep it in state or ask the parent to change it through a callback.

05The children Prop

Anything between a component's tags is available as children.

function Card({ title, children }) {
  return (
    <div className="card">
      <h3>{title}</h3>
      <div className="card-body">{children}</div>
    </div>
  );
}

<Card title="Reminder">
  <p>Assignment due Friday.</p>
  <button>Open</button>
</Card>

This composition pattern (layouts, modals, wrappers) is preferred over inheritance in React.

06ref is a Prop in React 19

In React 19, function components receive ref like any other prop. forwardRef is no longer needed.

function TextInput({ ref, ...props }) {          // React 19
  return <input ref={ref} {...props} />;
}

07Default Props and Prop Types

  • Use default parameter values: function Button({ size = "md" }). The old defaultProps for function components was removed in React 19.
  • propTypes runtime checks were also removed in React 19. Use TypeScript (or a schema library) for prop validation.

08Conditional Rendering

function Status({ isLoggedIn, unread }) {
  if (!isLoggedIn) return <p>Please log in.</p>;          // early return

  return (
    <div>
      {isLoggedIn ? <Dashboard /> : <Login />}            {/* ternary: either/or */}
      {unread > 0 && <Badge count={unread} />}            {/* && : show or nothing */}
      {error && <p role="alert">{error}</p>}
      {items.length === 0 ? <Empty /> : <List items={items} />}
    </div>
  );
}

09Rendering Lists and Keys

const courses = [
  { id: 1, title: "Java" },
  { id: 2, title: "React" },
  { id: 3, title: "SQL" },
];

function CourseList() {
  return (
    <ul>
      {courses.map(course => (
        <li key={course.id}>{course.title}</li>
      ))}
    </ul>
  );
}

Why keys?

A key lets React match each item between renders so it can add, remove and reorder items correctly without losing their state.

Key rules

  • Must be unique among siblings (not globally)
  • Must be stable: use the data's id, not a random value each render
  • Avoid array index as key when the list can be reordered, filtered or edited (it breaks state and causes bugs); acceptable only for static lists
  • Never use Math.random() or crypto.randomUUID() during render
  • Put key on the element returned by map, not on an inner child
{rows.map(r => (
  <Fragment key={r.id}>
    <dt>{r.term}</dt>
    <dd>{r.meaning}</dd>
  </Fragment>
))}

Filtering and sorting lists

const visible = courses
  .filter(c => c.title.toLowerCase().includes(query.toLowerCase()))
  .toSorted((a, b) => a.title.localeCompare(b.title));

10Handling Events (Basics)

function Button() {
  function handleClick(event) {
    console.log("clicked", event.type);
  }
  return <button onClick={handleClick}>Click me</button>;     // pass the function, don't call it
}
Common events
MouseonClick, onDoubleClick, onMouseEnter, onMouseLeave
FormonChange, onSubmit, onFocus, onBlur, onInput
KeyboardonKeyDown, onKeyUp
Pointer / touchonPointerDown, onTouchStart
Warning

onClick={handleClick()} calls the function during render. Write onClick={handleClick} or onClick={() => handleClick(id)}.

function Form() {
  function handleSubmit(e) {
    e.preventDefault();                       // stop the browser's page reload
    console.log("submitted");
  }
  return <form onSubmit={handleSubmit}>…</form>;
}

React events are synthetic: a cross-browser wrapper with the same interface as native events. e.stopPropagation() stops bubbling.

11Component Composition

Build big UIs by nesting small components.

function CourseCard({ course }) {
  return (
    <article className="card">
      <CourseImage src={course.image} alt={course.title} />
      <CourseInfo title={course.title} level={course.level} />
      <EnrollButton courseId={course.id} />
    </article>
  );
}

When to split a component

  • It is reused in more than one place
  • It does one clear job and can have a clear name
  • The file is getting long or hard to read
  • Part of it needs its own state

13Document Metadata in React 19

You can render <title>, <meta> and <link> inside any component; React hoists them into <head>.

function CoursePage({ course }) {
  return (
    <article>
      <title>{course.title} | Hanbee LMS</title>
      <meta name="description" content={course.summary} />
      <h1>{course.title}</h1>
    </article>
  );
}

15Quick Recap

  • JSX = HTML-like syntax compiled to JS; one root, closed tags, camelCase attributes, {} for expressions
  • Components are capitalised pure functions; props flow down and are read-only
  • children enables composition; in React 19 ref is just a prop
  • Render conditionally with if, ternary and &&; render lists with map and stable keys
  • Pass handlers as onClick={fn}, never onClick={fn()}
