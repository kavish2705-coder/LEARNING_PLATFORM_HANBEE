Custom Hooks, Patterns and Error Boundaries

Reuse logic with custom hooks, structure components with composition patterns, handle failures with error boundaries, and render outside the tree with portals.

01Custom Hooks

A custom hook is a function whose name starts with use and that calls other hooks. It lets you reuse stateful logic (not UI) across components.

function useToggle(initial = false) {
  const [on, setOn] = useState(initial);
  const toggle = useCallback(() => setOn(v => !v), []);
  return [on, toggle];
}

function Menu() {
  const [open, toggleOpen] = useToggle();
  return <button onClick={toggleOpen}>{open ? "Close" : "Open"}</button>;
}

Rules

  • The name must start with use so linters can check the Rules of Hooks
  • Each call has its own isolated state: two components using useToggle() do not share state
  • It shares logic, not state (share state with Context or a store)
  • Custom hooks can call other hooks and return anything: values, arrays, objects, functions

02Useful Custom Hooks

useLocalStorage

function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    try {
      const saved = localStorage.getItem(key);
      return saved !== null ? JSON.parse(saved) : initial;
    } catch { return initial; }
  });

  useEffect(() => {
    try { localStorage.setItem(key, JSON.stringify(value)); } catch { /* storage full or blocked */ }
  }, [key, value]);

  return [value, setValue];
}

const [theme, setTheme] = useLocalStorage("theme", "light");

useDebounce

function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);
  return debounced;
}

useFetch (simple version)

function useFetch(url) {
  const [state, setState] = useState({ data: null, error: null, loading: true });

  useEffect(() => {
    const controller = new AbortController();
    setState(s => ({ ...s, loading: true }));

    fetch(url, { signal: controller.signal })
      .then(res => { if (!res.ok) throw new Error(`HTTP ${res.status}`); return res.json(); })
      .then(data => setState({ data, error: null, loading: false }))
      .catch(error => { if (error.name !== "AbortError") setState({ data: null, error, loading: false }); });

    return () => controller.abort();
  }, [url]);

  return state;
}

const { data, error, loading } = useFetch(`/api/courses/${id}`);
Tip

In real projects, prefer TanStack Query over a hand-written useFetch: caching, retries and deduplication are already solved.

useWindowSize / useMediaQuery

function useMediaQuery(query) {
  const [matches, setMatches] = useState(() => window.matchMedia(query).matches);
  useEffect(() => {
    const mql = window.matchMedia(query);
    const onChange = (e) => setMatches(e.matches);
    mql.addEventListener("change", onChange);
    return () => mql.removeEventListener("change", onChange);
  }, [query]);
  return matches;
}
const isMobile = useMediaQuery("(max-width: 640px)");

usePrevious

function usePrevious(value) {
  const ref = useRef(undefined);
  useEffect(() => { ref.current = value; });
  return ref.current;
}

useOnClickOutside

function useOnClickOutside(ref, handler) {
  useEffect(() => {
    const listener = (e) => { if (ref.current && !ref.current.contains(e.target)) handler(e); };
    document.addEventListener("pointerdown", listener);
    return () => document.removeEventListener("pointerdown", listener);
  }, [ref, handler]);
}

useInterval

function useInterval(callback, delay) {
  const saved = useRef(callback);
  useEffect(() => { saved.current = callback; }, [callback]);
  useEffect(() => {
    if (delay == null) return;
    const id = setInterval(() => saved.current(), delay);
    return () => clearInterval(id);
  }, [delay]);
}

Libraries of ready-made hooks

usehooks-ts, react-use, ahooks, @uidotdev/usehooks provide well-tested versions of these.

03Naming and Design Tips

  • Name by what it does, not how: useOnlineStatus, not useEventListenerOnWindow
  • Return the smallest useful API; use an array for 2 values, an object for more
  • Keep hooks focused; compose small hooks into bigger ones
  • Don't wrap one-off useEffect calls in a hook just for the sake of it
  • Test hooks with renderHook from React Testing Library

04Component Composition Patterns

Children and slots

function Layout({ header, sidebar, children }) {
  return (
    <div className="layout">
      <header>{header}</header>
      <aside>{sidebar}</aside>
      <main>{children}</main>
    </div>
  );
}
<Layout header={<Nav />} sidebar={<Menu />}><Dashboard /></Layout>

Compound components

Related components that share implicit state through Context, giving a flexible, declarative API.

const TabsContext = createContext(null);

function Tabs({ defaultValue, children }) {
  const [value, setValue] = useState(defaultValue);
  return <TabsContext value={{ value, setValue }}><div>{children}</div></TabsContext>;
}
Tabs.List = ({ children }) => <div role="tablist">{children}</div>;
Tabs.Tab = function Tab({ value, children }) {
  const ctx = use(TabsContext);
  return <button role="tab" aria-selected={ctx.value === value} onClick={() => ctx.setValue(value)}>{children}</button>;
};
Tabs.Panel = function Panel({ value, children }) {
  return use(TabsContext).value === value ? <div role="tabpanel">{children}</div> : null;
};

<Tabs defaultValue="notes">
  <Tabs.List><Tabs.Tab value="notes">Notes</Tabs.Tab><Tabs.Tab value="videos">Videos</Tabs.Tab></Tabs.List>
  <Tabs.Panel value="notes">…</Tabs.Panel>
  <Tabs.Panel value="videos">…</Tabs.Panel>
</Tabs>

Used by Radix UI, Headless UI, Reach UI and shadcn/ui.

Render props

A prop that is a function returning JSX: the component supplies data, the caller decides how to render.

function MouseTracker({ children }) {
  const [pos, setPos] = useState({ x: 0, y: 0 });
  return <div onPointerMove={e => setPos({ x: e.clientX, y: e.clientY })}>{children(pos)}</div>;
}
<MouseTracker>{({ x, y }) => <p>{x}, {y}</p>}</MouseTracker>

Mostly replaced by custom hooks today, but still common in libraries (e.g. Controller in React Hook Form).

Higher-order components (HOC)

A function that takes a component and returns an enhanced one.

function withAuth(Component) {
  return function Protected(props) {
    const { user } = useAuth();
    return user ? <Component {...props} user={user} /> : <Navigate to="/login" />;
  };
}
const AdminPage = withAuth(Admin);

Hooks and composition replaced most HOC use; you'll still meet them in older code (connect from Redux, withRouter).

Controlled vs uncontrolled components

A component can be controlled by its parent (value + onChange) or uncontrolled (own state, defaultValue). Good reusable components support both.

Container / presentational

Separate how it looks (presentational, receives props) from how it gets data (container or hook). Today the "container" is usually a custom hook or a Server Component.

Polymorphic as prop

function Text({ as: Tag = "p", children, ...rest }) { return <Tag {...rest}>{children}</Tag>; }
<Text as="h1">Title</Text>

05Error Boundaries

A render error in any component unmounts the whole tree by default. An error boundary catches errors in its children and shows a fallback.

Note

Error boundaries must still be class components, or you can use the react-error-boundary library (recommended).

import { ErrorBoundary } from "react-error-boundary";

function Fallback({ error, resetErrorBoundary }) {
  return (
    <div role="alert">
      <p>Something went wrong: {error.message}</p>
      <button onClick={resetErrorBoundary}>Try again</button>
    </div>
  );
}

<ErrorBoundary FallbackComponent={Fallback} onError={(e, info) => report(e, info.componentStack)} onReset={() => refetch()}>
  <Dashboard />
</ErrorBoundary>

What boundaries catch

CatchesDoes not catch
Errors during renderingErrors in event handlers (use try/catch)
Errors in lifecycle/effects' render phaseAsync code (promises, setTimeout)
Errors in child constructorsErrors in the boundary itself
Rejected promises read with use() / SuspenseServer-side rendering errors (handled by the framework)

Placement strategy

  • One top-level boundary (app crash page)
  • Route-level boundaries so a broken page doesn't take down the layout
  • Boundaries around independent widgets (charts, comments) so they fail alone
  • Combine with <Suspense>: ErrorBoundary > Suspense > Component

Class boundary (for reference)

class Boundary extends React.Component {
  state = { error: null };
  static getDerivedStateFromError(error) { return { error }; }
  componentDidCatch(error, info) { report(error, info.componentStack); }
  render() { return this.state.error ? <p>Oops</p> : this.props.children; }
}

Errors in event handlers and async code

async function handleSave() {
  try { await save(); } catch (e) { setError(e.message); }
}

06Portals

Render children into a different DOM node while keeping them in the same React tree (context and events still bubble through React parents). Ideal for modals, tooltips and dropdowns that must escape overflow: hidden or z-index stacking.

import { createPortal } from "react-dom";

function Modal({ open, onClose, children }) {
  if (!open) return null;
  return createPortal(
    <div className="backdrop" onClick={onClose}>
      <div className="modal" role="dialog" aria-modal="true" onClick={e => e.stopPropagation()}>
        {children}
        <button onClick={onClose}>Close</button>
      </div>
    </div>,
    document.body
  );
}

For modals also manage focus trapping, Escape to close and scroll locking, or use the native <dialog> element / Radix Dialog.

07Suspense Boundaries (Recap)

<Suspense fallback={…}> shows a fallback while children are loading (lazy components, use(promise), data libraries). Combine with error boundaries and nest them for granular loading UI.

08Lists of Components and Dynamic Rendering

const widgets = { chart: ChartWidget, table: TableWidget, text: TextWidget };
function Widget({ type, ...props }) {
  const Component = widgets[type];
  return Component ? <Component {...props} /> : null;
}

Store the component reference (capitalised variable), never a string, when rendering dynamically.

09Quick Recap

  • Custom hooks (useXyz) reuse stateful logic; each use gets its own state
  • Prefer hooks and composition over HOCs and render props; compound components suit tabs/menus/accordions
  • Error boundaries (use react-error-boundary) catch render errors; handle event/async errors with try/catch
  • Place boundaries at app, route and widget level, combined with Suspense
  • Portals render modals and tooltips outside their parent DOM node while staying in the React tree
