TypeScript with React

Add static types to React 19 code. Typing props, children, state, events, refs, context, reducers, generic components, hooks and Server Actions, plus the React 19 type changes.

01Why TypeScript?

TypeScript adds static types to JavaScript. In React it gives you:

  • Autocomplete for props, hooks and APIs
  • Compile-time errors for wrong props, missing fields and typos
  • Safer refactoring across large codebases
  • Self-documenting components (replaces propTypes, which React 19 removed)

03TypeScript Basics Refresher

let name: string = "Asha";
let age: number = 20;
let active: boolean = true;
const tags: string[] = ["a", "b"];                    // or Array<string>
const pair: [string, number] = ["x", 1];              // tuple
let id: string | number;                              // union
type Level = "beginner" | "intermediate" | "advanced"; // literal union

interface Course {
  id: number;
  title: string;
  level: Level;
  tags?: string[];                                    // optional
  readonly createdAt: Date;                           // read-only
}

type CourseSummary = Pick<Course, "id" | "title">;    // utility types
type CourseDraft = Partial<Course>;
type WithoutId = Omit<Course, "id">;
type Lookup = Record<string, Course>;

function area(w: number, h: number): number { return w * h; }
const double = (n: number): number => n * 2;

type vs interface

Both describe object shapes. Use interface for object contracts that may be extended, type for unions, tuples and computed types. Either is fine in React; be consistent.

unknown vs any

any switches off checking: avoid it. Use unknown for values you must validate first.

04Typing Props

interface CourseCardProps {
  title: string;
  price?: number;                                     // optional
  level: "beginner" | "advanced";
  tags: string[];
  onEnroll: (id: number) => void;                      // callback
  children?: React.ReactNode;                          // anything renderable
}

function CourseCard({ title, price = 0, level, tags, onEnroll, children }: CourseCardProps) {
  return (
    <article>
      <h3>{title}</h3>
      <p>{level} · ₹{price}</p>
      {children}
    </article>
  );
}
  • No need for React.FC; annotate props directly (this is the modern convention)
  • Return type is inferred (JSX.Element); don't annotate it

Extending HTML element props

type ButtonProps = React.ComponentProps<"button"> & {
  variant?: "primary" | "ghost";
};

function Button({ variant = "primary", className, ...rest }: ButtonProps) {
  return <button className={`btn btn--${variant} ${className ?? ""}`} {...rest} />;
}

React.ComponentProps<"input">, React.ComponentProps<typeof MyComponent> and React.ComponentPropsWithoutRef<"div"> reuse existing prop types. In React 19, ref is part of function-component props, so ComponentProps<"input"> already includes it.

Discriminated unions for variants

type AlertProps =
  | { kind: "success"; message: string }
  | { kind: "error"; message: string; retry: () => void };

function Alert(props: AlertProps) {
  if (props.kind === "error") return <p role="alert">{props.message} <button onClick={props.retry}>Retry</button></p>;
  return <p>{props.message}</p>;                      // narrowed to success
}

06Typing Events

function Form() {
  const [email, setEmail] = useState("");

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => setEmail(e.target.value);
  const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => { e.preventDefault(); };
  const handleClick = (e: React.MouseEvent<HTMLButtonElement>) => console.log(e.clientX);
  const handleKey = (e: React.KeyboardEvent<HTMLInputElement>) => { if (e.key === "Enter") submit(); };
  const handleSelect = (e: React.ChangeEvent<HTMLSelectElement>) => setLevel(e.target.value as Level);

  return <form onSubmit={handleSubmit}><input value={email} onChange={handleChange} onKeyDown={handleKey} /></form>;
}

Inline handlers are inferred automatically: onChange={e => setEmail(e.target.value)}. Annotate only when defining the function separately.

07Typing Refs

const inputRef = useRef<HTMLInputElement>(null);          // React 19 requires an argument
inputRef.current?.focus();

const timerRef = useRef<number | null>(null);             // mutable value

// ref as a prop (React 19)
function TextInput({ ref, ...props }: React.ComponentProps<"input">) {
  return <input ref={ref} {...props} />;
}

08Typing Context

interface AuthContextValue {
  user: User | null;
  login: (email: string, password: string) => Promise<void>;
  logout: () => void;
}

const AuthContext = createContext<AuthContextValue | null>(null);

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const value: AuthContextValue = {
    user,
    login: async (email, password) => setUser(await api.login(email, password)),
    logout: () => setUser(null),
  };
  return <AuthContext value={value}>{children}</AuthContext>;
}

export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth must be used within AuthProvider");   // narrows away null
  return ctx;
}

09Typing useReducer

type State = { items: Todo[] };
type Action =
  | { type: "added"; text: string }
  | { type: "toggled"; id: string }
  | { type: "removed"; id: string };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case "added":   return { items: [...state.items, { id: crypto.randomUUID(), text: action.text, done: false }] };
    case "toggled": return { items: state.items.map(t => t.id === action.id ? { ...t, done: !t.done } : t) };
    case "removed": return { items: state.items.filter(t => t.id !== action.id) };
  }                                                            // exhaustive: TS errors if a case is missing
}

const [state, dispatch] = useReducer(reducer, { items: [] });

10Generic Components

interface ListProps<T> {
  items: T[];
  getKey: (item: T) => string | number;
  renderItem: (item: T) => React.ReactNode;
}

function List<T>({ items, getKey, renderItem }: ListProps<T>) {
  return <ul>{items.map(item => <li key={getKey(item)}>{renderItem(item)}</li>)}</ul>;
}

<List items={courses} getKey={c => c.id} renderItem={c => <b>{c.title}</b>} />   // T inferred as Course

11Typing Custom Hooks

function useLocalStorage<T>(key: string, initial: T): [T, React.Dispatch<React.SetStateAction<T>>] {
  const [value, setValue] = useState<T>(() => {
    const saved = localStorage.getItem(key);
    return saved ? (JSON.parse(saved) as T) : initial;
  });
  useEffect(() => localStorage.setItem(key, JSON.stringify(value)), [key, value]);
  return [value, setValue];
}

const [theme, setTheme] = useLocalStorage<"light" | "dark">("theme", "light");

Return tuples with an explicit type (otherwise TS infers an array union), or return an object.

12Typing API Data

interface Course { id: number; title: string }

async function getCourse(id: number): Promise<Course> {
  const res = await fetch(`/api/courses/${id}`);
  if (!res.ok) throw new Error("Failed");
  return res.json() as Promise<Course>;         // this is only a promise; the compiler can't verify the response
}

Types vanish at runtime. Validate untrusted data with Zod and infer the type from the schema:

import { z } from "zod";
const CourseSchema = z.object({ id: z.number(), title: z.string() });
type Course = z.infer<typeof CourseSchema>;
const course = CourseSchema.parse(await res.json());      // throws if the server sent something unexpected

14React 19 Actions and Types

type FormState = { error?: string; success?: boolean };

async function subscribe(prev: FormState, formData: FormData): Promise<FormState> {
  const email = formData.get("email");
  if (typeof email !== "string" || !email.includes("@")) return { error: "Invalid email" };
  await api.subscribe(email);
  return { success: true };
}

const [state, formAction, isPending] = useActionState(subscribe, {});     // types inferred

formData.get() returns FormDataEntryValue | null: always narrow it (typeof x === "string").

16Useful Utility Types

TypeMeaning
Partial<T> / Required<T>Make all props optional / required
Pick<T, K> / Omit<T, K>Choose / drop properties
Record<K, V>Object with keys K and values V
ReturnType<typeof fn>Function's return type
Parameters<typeof fn>Function's argument tuple
Awaited<Promise<T>>Unwrapped promise value
NonNullable<T>Remove null/undefined
typeof obj / keyof TDerive types from values and keys
satisfiesCheck a value matches a type while keeping its narrow type
const routes = { home: "/", courses: "/courses" } as const;     // literal types

17Common TypeScript + React Mistakes

MistakeBetter
any everywhereunknown + narrowing, or proper types
Type assertions (as Foo) to silence errorsFix the model or validate with Zod
React.FC with children assumptionsPlain function with typed props
Non-null assertions (ref.current!)Optional chaining or guards
Optional props that are really requiredMake required; use unions for variants
Storing derived values in stateDerive with types intact
Ignoring strict errorsFix them; they are real bugs

18Quick Recap

  • Use .tsx, enable strict, annotate props and let TypeScript infer most other things
  • useState<T | null>(null), useRef<HTMLElement>(null), typed events (React.ChangeEvent<HTMLInputElement>)
  • Context with a null default plus a hook that throws; reducers with discriminated-union actions
  • Generic components and hooks keep reuse type-safe
  • Types are erased at runtime: validate external data with Zod
  • React 19: useRef needs an argument, React.JSX replaces global JSX, ref is a prop
