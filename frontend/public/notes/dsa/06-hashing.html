Hashing: HashMap and HashSet Patterns

How hash tables work and the patterns that make them the most-used tool in interviews. Frequency counting, two sum, grouping, prefix-sum maps and designing your own hash table.

01What is Hashing?

Hashing maps a key to an array index using a hash function, giving average O(1) insert, lookup and delete.

key "Asha" ──hash()──► 8734512 ──% capacity──► bucket 5

buckets:  [0] [1] [2] [3] [4] [5: Asha→91] [6] [7] ...
StructureStoresJava class
Hash setUnique keysHashSet
Hash mapKey → value pairsHashMap
Insertion-orderedSame, remembers orderLinkedHashMap, LinkedHashSet
SortedSame, sorted by key (O(log n))TreeMap, TreeSet

02Hash Functions

A good hash function is deterministic, fast and spreads keys evenly.

// Polynomial rolling hash for strings (how String.hashCode() works)
int hash = 0;
for (char c : s.toCharArray()) hash = 31 * hash + c;
int bucket = (hash & 0x7fffffff) % capacity;          // make it non-negative, then map to a bucket
  • Equal objects must produce equal hash codes (equals/hashCode contract)
  • Unequal objects may share a hash code (a collision)

03Collision Handling

Two keys landing in the same bucket is unavoidable (pigeonhole principle).

Separate chaining

Each bucket holds a list (or tree) of entries. Java's HashMap converts a long chain (8 or more entries, table size at least 64) into a red-black tree, so the worst case is O(log n) per bucket.

bucket 3 → [k1:v1] → [k2:v2] → [k3:v3]

Open addressing

All entries live in the array itself. On collision, probe for another slot:

ProbingNext slot
Linear(h + i) % m
Quadratic(h + i²) % m
Double hashing(h1 + i·h2) % m

Deletion needs tombstones; clustering hurts performance when the table is full.

Load factor and resizing

load factor = entries / buckets. Java's HashMap defaults to 0.75: when exceeded, the table doubles and every entry is rehashed. Resizing is O(n) but rare, so put stays O(1) amortised.

ComplexityAverageWorst
put, get, remove, containsO(1)O(n) (O(log n) with tree bins)

04A Simple HashMap from Scratch

class MyHashMap {
    private static class Entry { int key, val; Entry next; Entry(int k, int v) { key = k; val = v; } }

    private Entry[] table = new Entry[16];
    private int size;

    private int index(int key) { return (key & 0x7fffffff) % table.length; }

    void put(int key, int val) {
        int i = index(key);
        for (Entry e = table[i]; e != null; e = e.next)
            if (e.key == key) { e.val = val; return; }       // update existing
        Entry n = new Entry(key, val);
        n.next = table[i]; table[i] = n;                      // insert at the chain head
        if (++size > table.length * 0.75) resize();
    }

    int get(int key) {
        for (Entry e = table[index(key)]; e != null; e = e.next)
            if (e.key == key) return e.val;
        return -1;
    }

    void remove(int key) {
        int i = index(key);
        Entry prev = null;
        for (Entry e = table[i]; e != null; prev = e, e = e.next) {
            if (e.key == key) {
                if (prev == null) table[i] = e.next; else prev.next = e.next;
                size--;
                return;
            }
        }
    }

    private void resize() {
        Entry[] old = table;
        table = new Entry[old.length * 2];
        for (Entry head : old)
            for (Entry e = head; e != null; ) {
                Entry next = e.next;
                int i = index(e.key);
                e.next = table[i]; table[i] = e;
                e = next;
            }
    }
}

05Using HashMap and HashSet in Java

Map<String, Integer> map = new HashMap<>();
map.put("a", 1);
map.get("a");                              // null if absent
map.getOrDefault("z", 0);
map.containsKey("a");   map.remove("a");   map.size();
map.putIfAbsent("b", 2);
map.merge("a", 1, Integer::sum);           // counting idiom
map.computeIfAbsent("k", x -> new ArrayList<>()).add(5);   // grouping idiom
for (Map.Entry<String, Integer> e : map.entrySet()) { e.getKey(); e.getValue(); }

Set<Integer> set = new HashSet<>();
set.add(3);   set.contains(3);   set.remove(3);          // add returns false if already present

Custom keys: override equals and hashCode

record Point(int x, int y) { }                           // records generate equals/hashCode
Set<Point> visited = new HashSet<>();
visited.add(new Point(1, 2));

// Or a fast encoding for grid cells: key = row * COLS + col  or  (long) r << 32 | c
Warning

Never mutate an object after using it as a key; its hash changes and it becomes unreachable. Prefer immutable keys such as String, Integer and records. Arrays do not override hashCode; convert with Arrays.toString(arr) or List.of(...) to use them as keys.

06Pattern 1: Frequency Counting

static Map<Character, Integer> frequency(String s) {
    Map<Character, Integer> f = new HashMap<>();
    for (char c : s.toCharArray()) f.merge(c, 1, Integer::sum);
    return f;
}

Use an int[26] (or int[128]) instead of a map for letters; it is faster.

Contains duplicate

static boolean containsDuplicate(int[] a) {
    Set<Integer> seen = new HashSet<>();
    for (int x : a) if (!seen.add(x)) return true;
    return false;
}

First non-repeating character, majority element, valid anagram, ransom note: all frequency counting.

07Pattern 2: Two Sum (complement lookup)

Store each number's index; check whether target - x has already been seen.

static int[] twoSum(int[] a, int target) {
    Map<Integer, Integer> idx = new HashMap<>();             // value → index
    for (int i = 0; i < a.length; i++) {
        Integer j = idx.get(target - a[i]);
        if (j != null) return new int[]{j, i};
        idx.put(a[i], i);
    }
    return new int[0];                                        // O(n) time, O(n) space
}

08Pattern 3: Grouping by a Canonical Key

Group anagrams

static List<List<String>> groupAnagrams(String[] words) {
    Map<String, List<String>> groups = new HashMap<>();
    for (String w : words) {
        char[] c = w.toCharArray();
        Arrays.sort(c);
        groups.computeIfAbsent(new String(c), k -> new ArrayList<>()).add(w);   // sorted letters = canonical form
    }
    return new ArrayList<>(groups.values());                  // O(n · k log k)
}

For O(n · k) use the 26-count signature as the key instead of sorting.

Isomorphic strings

Map each character to its partner both ways; fail if a mapping conflicts.

09Pattern 4: Prefix Sum + HashMap

Count subarrays whose sum equals k. If prefix[j] - prefix[i] = k, then prefix[i] = prefix[j] - k.

static int subarraySum(int[] a, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    count.put(0, 1);                                          // empty prefix
    int sum = 0, res = 0;
    for (int x : a) {
        sum += x;
        res += count.getOrDefault(sum - k, 0);                // how many earlier prefixes complete a subarray?
        count.merge(sum, 1, Integer::sum);
    }
    return res;                                               // O(n), works with negatives (sliding window doesn't)
}

Longest subarray with sum k / equal 0s and 1s

Store the first index where each prefix sum occurred; the answer is i - firstIndex[prefix - k]. For equal 0s and 1s, treat 0 as -1 and look for sum 0.

Subarray sums divisible by k

Track ((sum % k) + k) % k remainders: two equal remainders mean the subarray between them is divisible by k.

10Pattern 5: Sets for Existence and Ranges

Longest consecutive sequence: O(n)

static int longestConsecutive(int[] a) {
    Set<Integer> set = new HashSet<>();
    for (int x : a) set.add(x);
    int best = 0;
    for (int x : set) {
        if (set.contains(x - 1)) continue;                    // only start counting from a sequence's beginning
        int len = 1;
        while (set.contains(x + len)) len++;
        best = Math.max(best, len);
    }
    return best;
}

Intersection and union of arrays, happy number (cycle detection with a set), find missing/duplicate.

11Pattern 6: Top K Frequent (bucket sort)

static int[] topKFrequent(int[] a, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : a) freq.merge(x, 1, Integer::sum);

    List<Integer>[] buckets = new List[a.length + 1];          // index = frequency
    for (var e : freq.entrySet()) {
        int f = e.getValue();
        if (buckets[f] == null) buckets[f] = new ArrayList<>();
        buckets[f].add(e.getKey());
    }
    int[] res = new int[k];
    int p = 0;
    for (int f = buckets.length - 1; f > 0 && p < k; f--)
        if (buckets[f] != null)
            for (int x : buckets[f]) { if (p < k) res[p++] = x; }
    return res;                                                 // O(n)
}

Alternative: a min-heap of size k for O(n log k) (see Heaps).

12Pattern 7: Caching and Memoisation

Hash maps store results of expensive computations (Map<State, Result>): the base of top-down dynamic programming and LRU caches.

13Pattern 8: Index Maps and Design Problems

  • Insert / delete / getRandom in O(1): ArrayList + HashMap<value, index>; delete by swapping with the last element
  • Time-based key-value store: Map<String, List<(time, value)>> + binary search
  • Two sum data structure, LFU/LRU cache, randomised set
class RandomizedSet {
    private final List<Integer> list = new ArrayList<>();
    private final Map<Integer, Integer> pos = new HashMap<>();
    private final Random rnd = new Random();

    boolean insert(int v) {
        if (pos.containsKey(v)) return false;
        pos.put(v, list.size()); list.add(v);
        return true;
    }
    boolean remove(int v) {
        Integer i = pos.remove(v);
        if (i == null) return false;
        int last = list.get(list.size() - 1);
        list.set(i, last);                                      // move the last element into the hole
        if (last != v) pos.put(last, i);
        list.remove(list.size() - 1);
        return true;
    }
    int getRandom() { return list.get(rnd.nextInt(list.size())); }
}

16When to Use Hashing

  • You need fast lookup, membership or counting
  • You want to turn a nested-loop O(n²) search into O(n) by remembering what you have seen
  • Order does not matter (otherwise consider TreeMap, sorting or LinkedHashMap)

Trade-off: O(n) extra space, no ordering, and worst-case collisions.

17Common Mistakes

  • Using a mutable object (or an array) as a key
  • Overriding equals without hashCode
  • Modifying a map while iterating over it (ConcurrentModificationException): use Iterator.remove() or removeIf
  • Boxing overhead: for small integer ranges use arrays instead of Map<Integer, Integer>
  • Assuming iteration order from HashMap
  • map.get(k) unboxing a null into int → NullPointerException (use getOrDefault)

18Quick Recap

  • Hash tables give average O(1) operations; collisions use chaining (trees in Java) or open addressing; the table resizes at load factor 0.75
  • Key patterns: frequency count, complement lookup (two sum), grouping by canonical key, prefix sum + map, sets for existence
  • Use immutable keys and always override equals and hashCode together
  • TreeMap when you need sorted keys or nearest-key queries; LinkedHashMap for ordering and LRU
