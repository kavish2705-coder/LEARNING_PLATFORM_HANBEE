Sorting Algorithms

How the classic sorting algorithms work and when to use each. Bubble, selection, insertion, merge, quick, heap and counting sort, plus stability, Java's built-in sorts and sorting-based interview problems.

01Why Sorting?

Sorted data makes many problems easy: binary search, two pointers, finding duplicates, merging intervals, grouping, and closest pairs. Sorting costs O(n log n) at best for comparison sorts, which is often a worthwhile first step.

02Key Terms

In-placeUses O(1) extra memory (beyond the input)

Note

Why stability matters: sort students by marks and then by class: a stable sort keeps the marks order within each class.

04Elementary Sorts (O(n²))

Bubble sort

Repeatedly swap adjacent elements that are out of order; the largest "bubbles" to the end each pass.

static void bubbleSort(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < a.length - 1 - i; j++) {
            if (a[j] > a[j + 1]) { int t = a[j]; a[j] = a[j + 1]; a[j + 1] = t; swapped = true; }
        }
        if (!swapped) break;                          // already sorted: best case O(n)
    }
}

Selection sort

Select the minimum of the unsorted part and put it in place.

static void selectionSort(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        int min = i;
        for (int j = i + 1; j < a.length; j++) if (a[j] < a[min]) min = j;
        int t = a[i]; a[i] = a[min]; a[min] = t;
    }
}

Insertion sort

Grow a sorted prefix by inserting each new element into its correct position, like sorting playing cards in your hand.

static void insertionSort(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }     // shift larger elements right
        a[j + 1] = key;
    }
}

Fast (O(n)) on nearly sorted data, which is why real libraries use it for small subarrays.

05Merge Sort

Divide and conquer: split in half, sort each half recursively, merge the two sorted halves.

[38, 27, 43, 3, 9, 82, 10]
 split → [38,27,43,3] [9,82,10] → ... → single elements
 merge ← [3,27,38,43] [9,10,82] ← ...
 merge ← [3, 9, 10, 27, 38, 43, 82]
static void mergeSort(int[] a, int lo, int hi) {
    if (lo >= hi) return;
    int mid = lo + (hi - lo) / 2;
    mergeSort(a, lo, mid);
    mergeSort(a, mid + 1, hi);
    merge(a, lo, mid, hi);
}

static void merge(int[] a, int lo, int mid, int hi) {
    int[] tmp = new int[hi - lo + 1];
    int i = lo, j = mid + 1, k = 0;
    while (i <= mid && j <= hi) tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];    // <= keeps it stable
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi)  tmp[k++] = a[j++];
    System.arraycopy(tmp, 0, a, lo, tmp.length);
}
  • Time: O(n log n) always (log n levels × n work per level)
  • Space: O(n) auxiliary
  • Stable; ideal for linked lists (O(1) extra space) and external sorting

Counting inversions with merge sort

While merging, when a[j] is taken before a[i], all remaining left elements (mid - i + 1) form inversions with it. Total inversions in O(n log n).

06Quick Sort

Partition around a pivot so smaller elements go left and larger go right, then sort each side recursively.

static void quickSort(int[] a, int lo, int hi) {
    if (lo >= hi) return;
    int p = partition(a, lo, hi);
    quickSort(a, lo, p - 1);
    quickSort(a, p + 1, hi);
}

// Lomuto partition: pivot = last element
static int partition(int[] a, int lo, int hi) {
    int pivot = a[hi], i = lo;
    for (int j = lo; j < hi; j++)
        if (a[j] < pivot) { swap(a, i++, j); }
    swap(a, i, hi);                                   // pivot into its final place
    return i;
}
static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }

Choosing the pivot

StrategyEffect
Last / first elementO(n²) on already sorted input
Random pivotExpected O(n log n) for every input
Median of threeGood practical choice
swap(a, lo + new Random().nextInt(hi - lo + 1), hi);     // randomise before partitioning
  • Time: O(n log n) average, O(n²) worst (bad pivots)
  • Space: O(log n) recursion (recurse into the smaller side first to guarantee this)
  • Not stable; excellent cache behaviour, so it is usually fastest in practice
  • Many equal elements: use 3-way partitioning (<, =, >)

Quickselect: k-th smallest in expected O(n)

static int quickSelect(int[] a, int k) {                 // k-th smallest, 0-based
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int p = partition(a, lo, hi);
        if (p == k) return a[p];
        if (p < k) lo = p + 1; else hi = p - 1;
    }
    return -1;
}

07Heap Sort

Build a max-heap in O(n), then repeatedly move the maximum to the end and restore the heap.

static void heapSort(int[] a) {
    int n = a.length;
    for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, n, i);       // build max-heap
    for (int end = n - 1; end > 0; end--) {
        swap(a, 0, end);                                           // move the max to its final position
        siftDown(a, end, 0);
    }
}
static void siftDown(int[] a, int n, int i) {
    while (true) {
        int largest = i, l = 2 * i + 1, r = 2 * i + 2;
        if (l < n && a[l] > a[largest]) largest = l;
        if (r < n && a[r] > a[largest]) largest = r;
        if (largest == i) return;
        swap(a, i, largest);
        i = largest;
    }
}

O(n log n) guaranteed, O(1) space, but not stable and less cache-friendly than quicksort.

08Non-comparison Sorts

These beat O(n log n) by using the structure of the keys, not comparisons.

Counting sort: small integer range

static void countingSort(int[] a, int max) {              // values in [0, max]
    int[] count = new int[max + 1];
    for (int x : a) count[x]++;
    int idx = 0;
    for (int v = 0; v <= max; v++)
        while (count[v]-- > 0) a[idx++] = v;
}                                                           // O(n + max), O(max) space

Radix sort

Sort by each digit, least significant first, using a stable sort (counting sort) per digit: O(d · (n + k)).

Bucket sort

Distribute values into buckets by range, sort each bucket, concatenate. Great for uniformly distributed floats in [0, 1).

09Sorting in Java

int[] a = {5, 2, 9};
Arrays.sort(a);                                     // primitives: dual-pivot quicksort, O(n log n) avg
Arrays.sort(a, 1, 3);                                // sort a range

Integer[] b = {5, 2, 9};
Arrays.sort(b, Collections.reverseOrder());          // objects: TimSort (stable, merge+insertion hybrid)

List<String> list = new ArrayList<>(List.of("pear", "fig", "apple"));
Collections.sort(list);                              // natural order, stable
list.sort(Comparator.comparing(String::length).thenComparing(Comparator.naturalOrder()));

int[][] pairs = {{3, 1}, {1, 2}, {3, 0}};
Arrays.sort(pairs, (x, y) -> x[0] != y[0] ? Integer.compare(x[0], y[0]) : Integer.compare(x[1], y[1]));

Arrays.parallelSort(a);                              // multi-core for large arrays
Warning

Don't write comparators as (x, y) -> x - y. It overflows for extreme values. Use Integer.compare(x, y).

Comparable vs Comparator

class Student implements Comparable<Student> {
    String name; int marks;
    public int compareTo(Student o) { return Integer.compare(o.marks, marks); }   // descending by marks
}

Comparator defines additional orderings outside the class (Comparator.comparing(Student::name)).

Note

Arrays.sort(int[]) is not stable, but for primitives stability is meaningless. For objects Java guarantees stability, so multi-key sorts can be done by chaining comparators.

10Sorting Problems

Merge intervals

static int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
    List<int[]> res = new ArrayList<>();
    for (int[] cur : intervals) {
        if (res.isEmpty() || res.get(res.size() - 1)[1] < cur[0]) res.add(cur);
        else res.get(res.size() - 1)[1] = Math.max(res.get(res.size() - 1)[1], cur[1]);
    }
    return res.toArray(new int[0][]);                     // O(n log n)
}

Largest number (custom comparator)

static String largestNumber(int[] nums) {
    String[] s = Arrays.stream(nums).mapToObj(String::valueOf).toArray(String[]::new);
    Arrays.sort(s, (a, b) -> (b + a).compareTo(a + b));   // which concatenation is bigger?
    return s[0].equals("0") ? "0" : String.join("", s);
}

12Common Mistakes

  • Overflow in x - y comparators
  • Sorting when only a partial answer is needed (top K) → use a heap
  • Modifying the array while sorting with an incorrect comparator (violating the contract throws Comparison method violates its general contract!)
  • Forgetting that Arrays.sort(int[]) modifies the array in place
  • Expecting Arrays.sort on int[] to accept a comparator (use Integer[] or a stream)

13Quick Recap

  • Elementary sorts are O(n²); insertion sort shines on tiny or nearly sorted data
  • Merge sort: O(n log n) always, stable, O(n) space; quick sort: O(n log n) average, in-place, randomise the pivot
  • Heap sort: guaranteed O(n log n), O(1) space; counting/radix sorts beat n log n for bounded integer keys
  • Comparison sorting cannot beat Ω(n log n)
  • Java: Arrays.sort for primitives (dual-pivot quicksort), TimSort (stable) for objects; compare with Integer.compare
