Heaps, Priority Queues and Tries

Binary heaps and Java's PriorityQueue for top-K and scheduling problems, the two-heap median trick, merging k lists, and tries for prefix search and autocomplete.

01Heap

A heap is a complete binary tree that satisfies the heap property:

  • Min-heap: every parent ≤ its children (the minimum is at the root)
  • Max-heap: every parent ≥ its children (the maximum is at the root)
Min-heap                              Array representation
       2                              index:  0  1  2  3  4  5
     /   \                            value: [2, 4, 3, 9, 7, 5]
    4     3
   / \   /                            parent(i)=(i-1)/2   left(i)=2i+1   right(i)=2i+2
  9   7 5

A heap is not sorted overall: only parent-child relations are ordered. Because the tree is complete it is stored compactly in an array.

OperationTime
peek (min or max)O(1)
insert / addO(log n)
extract / pollO(log n)
Build a heap from n itemsO(n)
Search for an arbitrary itemO(n)
Remove an arbitrary itemO(n) (find) + O(log n)

02Heap Operations

  • Insert: add at the end, then sift up (swap with the parent while smaller than it)
  • Extract min: take the root, move the last element to the root, then sift down (swap with the smaller child while larger than it)

Min-heap implementation

class MinHeap {
    private int[] a = new int[16];
    private int size;

    void add(int x) {
        if (size == a.length) a = Arrays.copyOf(a, size * 2);
        a[size] = x;
        siftUp(size++);
    }

    int peek() { return a[0]; }

    int poll() {
        int min = a[0];
        a[0] = a[--size];
        siftDown(0);
        return min;
    }

    private void siftUp(int i) {
        while (i > 0) {
            int p = (i - 1) / 2;
            if (a[p] <= a[i]) break;
            swap(p, i);
            i = p;
        }
    }

    private void siftDown(int i) {
        while (true) {
            int l = 2 * i + 1, r = l + 1, smallest = i;
            if (l < size && a[l] < a[smallest]) smallest = l;
            if (r < size && a[r] < a[smallest]) smallest = r;
            if (smallest == i) return;
            swap(i, smallest);
            i = smallest;
        }
    }

    private void swap(int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
    boolean isEmpty() { return size == 0; }
}

Why building a heap is O(n), not O(n log n)

Sift down from the last parent (n/2 - 1) up to the root. Most nodes are near the bottom and move very little; the total work sums to O(n).

03Java's PriorityQueue

A binary min-heap by default. Elements come out in priority order, not insertion order.

PriorityQueue<Integer> minHeap = new PriorityQueue<>();
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());

minHeap.offer(5); minHeap.offer(1); minHeap.offer(3);
minHeap.peek();     // 1
minHeap.poll();     // 1
minHeap.size();

// custom priority: sort pairs by second value
PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> Integer.compare(x[1], y[1]));
pq.offer(new int[]{7, 2});

// objects
PriorityQueue<Task> tasks = new PriorityQueue<>(Comparator.comparingInt(Task::priority).thenComparing(Task::name));

// build in O(n)
PriorityQueue<Integer> fromList = new PriorityQueue<>(List.of(5, 1, 3, 2));
Warning

Iterating a PriorityQueue (or printing it) does not give sorted order; only repeated poll() does. Also, remove(Object) and contains are O(n). Don't use (a, b) -> a - b comparators with large values (overflow).

04Heap Problems

Kth largest element (size-k min-heap)

static int findKthLargest(int[] a, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();      // keeps the k largest seen so far
    for (int x : a) {
        heap.offer(x);
        if (heap.size() > k) heap.poll();                     // drop the smallest of the k+1
    }
    return heap.peek();                                        // O(n log k) time, O(k) space
}
Tip

For the k largest use a min-heap of size k; for the k smallest use a max-heap of size k. The heap keeps the "boundary" element on top so it can be evicted.

Top K frequent elements

static int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : nums) freq.merge(x, 1, Integer::sum);

    PriorityQueue<Map.Entry<Integer, Integer>> heap = new PriorityQueue<>(Map.Entry.comparingByValue());
    for (var e : freq.entrySet()) {
        heap.offer(e);
        if (heap.size() > k) heap.poll();
    }
    int[] res = new int[k];
    for (int i = k - 1; i >= 0; i--) res[i] = heap.poll().getKey();
    return res;                                                // O(n log k)
}

Merge k sorted lists

static ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> heap = new PriorityQueue<>((a, b) -> Integer.compare(a.val, b.val));
    for (ListNode head : lists) if (head != null) heap.offer(head);
    ListNode dummy = new ListNode(0), tail = dummy;
    while (!heap.isEmpty()) {
        ListNode n = heap.poll();
        tail.next = n; tail = n;
        if (n.next != null) heap.offer(n.next);
    }
    return dummy.next;                                         // O(N log k), N = total nodes
}

Find median from a data stream: two heaps

Keep the lower half in a max-heap and the upper half in a min-heap, sizes differing by at most 1. The median is at the top(s).

class MedianFinder {
    private final PriorityQueue<Integer> low = new PriorityQueue<>(Collections.reverseOrder());   // max-heap
    private final PriorityQueue<Integer> high = new PriorityQueue<>();                           // min-heap

    void addNum(int x) {
        low.offer(x);
        high.offer(low.poll());                                // keep every value of low ≤ every value of high
        if (high.size() > low.size()) low.offer(high.poll());  // rebalance: low has equal or one more
    }
    double findMedian() {
        return low.size() > high.size() ? low.peek() : (low.peek() + high.peek()) / 2.0;
    }                                                          // add: O(log n), median: O(1)
}

K closest points to the origin

Max-heap of size k keyed by distance squared (avoid sqrt).

Sort a nearly sorted (k-sorted) array

Each element is at most k away from its place: use a min-heap of size k + 1 → O(n log k).

Task scheduler / reorganise string

Max-heap by remaining count; repeatedly take the most frequent available task or character.

Connect ropes with minimum cost (Huffman-like)

static int connectRopes(int[] ropes) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();
    for (int r : ropes) heap.offer(r);
    int cost = 0;
    while (heap.size() > 1) {
        int sum = heap.poll() + heap.poll();                   // always join the two shortest
        cost += sum;
        heap.offer(sum);
    }
    return cost;
}

Meeting rooms II (minimum rooms)

static int minMeetingRooms(int[][] iv) {
    Arrays.sort(iv, (a, b) -> Integer.compare(a[0], b[0]));
    PriorityQueue<Integer> ends = new PriorityQueue<>();       // end times of rooms in use
    for (int[] m : iv) {
        if (!ends.isEmpty() && ends.peek() <= m[0]) ends.poll();   // reuse a freed room
        ends.offer(m[1]);
    }
    return ends.size();
}

Heaps in graph algorithms

  • Dijkstra: min-heap of (distance, node)
  • Prim's MST: min-heap of edges
  • A\*: min-heap ordered by f = g + h

05When to Use a Heap

ClueUse
"Top K", "K largest/smallest/most frequent"Heap of size k
Repeatedly need the current min or maxHeap
Merge k sorted streamsMin-heap of heads
Running medianTwo heaps
Scheduling by priority, event simulationHeap
Greedy choices that must pick the best available nextHeap

Choose quickselect instead for a one-off k-th element in O(n), and sorting when you need everything ordered.

06Trie (Prefix Tree)

A trie stores strings character by character along tree paths. Words sharing a prefix share nodes.

Insert: "cat", "car", "dog"

        root
       /    \
      c      d
      |      |
      a      o
     / \     |
    t*  r*   g*          * = end of a word
OperationTime (word length L)
InsertO(L)
SearchO(L)
Prefix check (startsWith)O(L)
DeleteO(L)

The cost depends on the word length, not the number of words.

Implementation with a child array

class Trie {
    private static class Node {
        Node[] next = new Node[26];
        boolean end;
        int passCount;                                       // words passing through (prefix counting)
    }
    private final Node root = new Node();

    void insert(String word) {
        Node cur = root;
        for (char c : word.toCharArray()) {
            int i = c - 'a';
            if (cur.next[i] == null) cur.next[i] = new Node();
            cur = cur.next[i];
            cur.passCount++;
        }
        cur.end = true;
    }

    boolean search(String word) {
        Node n = find(word);
        return n != null && n.end;
    }

    boolean startsWith(String prefix) { return find(prefix) != null; }

    int countWordsWithPrefix(String prefix) {
        Node n = find(prefix);
        return n == null ? 0 : n.passCount;
    }

    private Node find(String s) {
        Node cur = root;
        for (char c : s.toCharArray()) {
            cur = cur.next[c - 'a'];
            if (cur == null) return null;
        }
        return cur;
    }
}

For large alphabets (Unicode) use Map<Character, Node> children instead of a fixed array.

Autocomplete: all words with a prefix

List<String> autocomplete(String prefix) {
    List<String> res = new ArrayList<>();
    Node n = find(prefix);
    if (n != null) collect(n, new StringBuilder(prefix), res);
    return res;
}
private void collect(Node n, StringBuilder sb, List<String> res) {
    if (n.end) res.add(sb.toString());
    for (int i = 0; i < 26; i++) {
        if (n.next[i] != null) {
            sb.append((char) ('a' + i));
            collect(n.next[i], sb, res);
            sb.deleteCharAt(sb.length() - 1);                // backtrack
        }
    }
}

Wildcard search (. matches any letter)

boolean searchWild(Node n, String w, int i) {
    if (n == null) return false;
    if (i == w.length()) return n.end;
    char c = w.charAt(i);
    if (c != '.') return searchWild(n.next[c - 'a'], w, i + 1);
    for (Node child : n.next) if (searchWild(child, w, i + 1)) return true;
    return false;
}

07Common Mistakes

  • Using a max-heap when you need the k largest (you want a min-heap of size k)
  • Assuming PriorityQueue iteration order is sorted
  • Subtraction comparators that overflow
  • Forgetting end = true in a trie (so prefixes are mistaken for words)
  • Allocating 26-element arrays for huge sparse tries without considering memory
  • Heap siftDown bounds: use size, not the array length

08Quick Recap

  • A heap gives O(1) min/max and O(log n) insert/extract; it is stored in an array (2i+1, 2i+2)
  • Java PriorityQueue is a min-heap; pass Collections.reverseOrder() or a comparator for a max-heap
  • Top-K: keep a heap of size k (min-heap for the k largest); median of a stream: max-heap + min-heap
  • Trie = prefix tree: O(L) insert/search/prefix, ideal for autocomplete and dictionary problems
  • Always mark word endings in a trie and consider memory for large alphabets
