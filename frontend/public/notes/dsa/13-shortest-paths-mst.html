Shortest Paths and Minimum Spanning Trees

Weighted graph algorithms. Dijkstra, Bellman-Ford, Floyd-Warshall and 0-1 BFS for shortest paths, and Kruskal and Prim for minimum spanning trees, with the problems that use them.

01Weighted Graphs

Each edge carries a weight (cost, distance, time). Two classic questions:

  1. Shortest path: cheapest route from a source to other vertices
  2. Minimum spanning tree (MST): cheapest set of edges connecting all vertices
record Edge(int to, int w) { }
List<List<Edge>> g = new ArrayList<>();
for (int i = 0; i < n; i++) g.add(new ArrayList<>());
g.get(u).add(new Edge(v, w));                  // add the reverse edge for undirected graphs

03Dijkstra's Algorithm

Greedy: always expand the unvisited vertex with the smallest known distance. Requires non-negative weights.

dist[source] = 0, everything else = ∞
repeat: take the vertex u with the smallest dist (min-heap)
        for each edge u → v with weight w:
            if dist[u] + w < dist[v]: dist[v] = dist[u] + w   // relaxation
static int[] dijkstra(List<List<Edge>> g, int src) {
    int n = g.size();
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;

    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));   // {node, distance}
    pq.offer(new int[]{src, 0});

    while (!pq.isEmpty()) {
        int[] cur = pq.poll();
        int u = cur[0], d = cur[1];
        if (d > dist[u]) continue;                              // stale entry: a shorter path was already found
        for (Edge e : g.get(u)) {
            int nd = d + e.w();
            if (nd < dist[e.to()]) {
                dist[e.to()] = nd;
                pq.offer(new int[]{e.to(), nd});
            }
        }
    }
    return dist;                                                  // O((V + E) log V)
}

Recover the actual path

Keep a prev[] array: when relaxing v through u, set prev[v] = u. Walk back from the target and reverse.

List<Integer> path = new ArrayList<>();
for (int at = target; at != -1; at = prev[at]) path.add(at);   // prev[src] = -1
Collections.reverse(path);
Warning

Dijkstra gives wrong answers with negative edge weights. Use Bellman-Ford. Also use long for distances if sums can exceed Integer.MAX_VALUE, and avoid Integer.MAX_VALUE + w overflow when comparing (check dist[u] != INF).

04Bellman-Ford

Relax every edge V - 1 times. Works with negative weights, and detects negative cycles.

static int[] bellmanFord(int n, int[][] edges, int src) {       // edges: {u, v, w}
    int INF = Integer.MAX_VALUE / 2;
    int[] dist = new int[n];
    Arrays.fill(dist, INF);
    dist[src] = 0;

    for (int i = 0; i < n - 1; i++) {
        boolean changed = false;
        for (int[] e : edges) {
            if (dist[e[0]] != INF && dist[e[0]] + e[2] < dist[e[1]]) {
                dist[e[1]] = dist[e[0]] + e[2];
                changed = true;
            }
        }
        if (!changed) break;                                      // early exit
    }
    for (int[] e : edges)                                          // one more pass: any improvement means a negative cycle
        if (dist[e[0]] != INF && dist[e[0]] + e[2] < dist[e[1]]) throw new IllegalStateException("Negative cycle");
    return dist;                                                   // O(V · E)
}

Cheapest flights within K stops: run only K + 1 rounds, relaxing from a copy of the previous round's distances so a path never uses more than K + 1 edges.

Used in currency arbitrage detection (negative cycle on -log(rate)), routing protocols (RIP).

05Floyd-Warshall: All-Pairs Shortest Paths

Dynamic programming over the "allowed intermediate vertices".

static void floydWarshall(int[][] dist) {                // dist[i][j] = weight, INF if no edge, dist[i][i] = 0
    int n = dist.length;
    for (int k = 0; k < n; k++)                           // intermediate vertex: the OUTER loop
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (dist[i][k] != INF && dist[k][j] != INF && dist[i][k] + dist[k][j] < dist[i][j])
                    dist[i][j] = dist[i][k] + dist[k][j];
}                                                          // O(V³) time, O(V²) space

Handles negative edges (not negative cycles: a negative dist[i][i] signals one). Good for V ≤ 400 or so: transitive closure, "find the city with the fewest neighbours within a threshold".

060-1 BFS

When all weights are 0 or 1, use a deque: push 0-weight neighbours to the front, 1-weight neighbours to the back.

static int[] zeroOneBfs(List<List<Edge>> g, int src) {
    int[] dist = new int[g.size()];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    Deque<Integer> dq = new ArrayDeque<>();
    dq.offerFirst(src);
    while (!dq.isEmpty()) {
        int u = dq.pollFirst();
        for (Edge e : g.get(u)) {
            if (dist[u] + e.w() < dist[e.to()]) {
                dist[e.to()] = dist[u] + e.w();
                if (e.w() == 0) dq.offerFirst(e.to()); else dq.offerLast(e.to());
            }
        }
    }
    return dist;                                              // O(V + E)
}

07Shortest Paths in a DAG

Process vertices in topological order and relax outgoing edges: O(V + E), works with negative weights. The same idea finds longest paths in a DAG (critical path in project scheduling).

08A* Search (Idea)

Like Dijkstra but orders the heap by f(n) = g(n) + h(n) where h is an admissible heuristic (never overestimates the remaining cost, for example straight-line distance). Explores far fewer vertices when a good heuristic exists: used in games and map routing.

09Minimum Spanning Tree (MST)

A spanning tree connects all V vertices with exactly V - 1 edges and no cycles. The MST is the spanning tree with the smallest total weight.

Uses: network cabling, road/pipeline design, clustering, approximation algorithms.

Graph:                 MST (weight 9):
  A -4- B                A    B
  |  \  |                |\   |
  2   5 3      →         2  \  3
  |    \|                |   \ |
  C -1-- D               C-1-D

Key properties: cut property (the lightest edge crossing any cut is in some MST) and cycle property (the heaviest edge in any cycle is not in the MST). If edge weights are distinct, the MST is unique.

Kruskal's algorithm: sort edges, add if no cycle

static int kruskal(int n, int[][] edges) {                  // edges: {u, v, w}
    Arrays.sort(edges, (a, b) -> Integer.compare(a[2], b[2]));
    DSU dsu = new DSU(n);
    int total = 0, used = 0;
    for (int[] e : edges) {
        if (dsu.union(e[0], e[1])) {                           // joins two different components
            total += e[2];
            if (++used == n - 1) break;
        }
    }
    return used == n - 1 ? total : -1;                          // -1: graph is disconnected
}                                                                // O(E log E) = O(E log V)

(DSU is the union-find class from the Graphs topic.) Best for sparse graphs and edge-list input.

Prim's algorithm: grow the tree from a vertex

static int prim(List<List<Edge>> g) {
    int n = g.size(), total = 0, count = 0;
    boolean[] inTree = new boolean[n];
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));   // {node, edge weight}
    pq.offer(new int[]{0, 0});
    while (!pq.isEmpty() && count < n) {
        int[] cur = pq.poll();
        int u = cur[0];
        if (inTree[u]) continue;
        inTree[u] = true;
        total += cur[1];
        count++;
        for (Edge e : g.get(u)) if (!inTree[e.to()]) pq.offer(new int[]{e.to(), e.w()});
    }
    return count == n ? total : -1;                              // O(E log V)
}

Best for dense graphs (with an adjacency matrix and no heap it is O(V²)).

10Dijkstra vs Prim

They look alike (heap + greedy), but Dijkstra's key is the total distance from the source, Prim's key is just the edge weight connecting a new vertex to the tree. Dijkstra gives a shortest-path tree, which is generally not an MST.

12Common Mistakes

  • Using Dijkstra when negative weights exist
  • Integer overflow from INF + weight (use Integer.MAX_VALUE / 2 or long)
  • Not skipping stale priority-queue entries (if (d > dist[u]) continue)
  • Forgetting to add both directions for undirected edges
  • Looping Floyd-Warshall with k in the inner position
  • Confusing "shortest path" with "MST": they optimise different things

13Quick Recap

  • Pick the algorithm by the graph: BFS (unweighted), 0-1 BFS, Dijkstra (non-negative), Bellman-Ford (negatives, O(VE)), Floyd-Warshall (all pairs, O(V³))
  • Dijkstra = greedy relaxation with a min-heap: O((V + E) log V); skip stale heap entries
  • An MST connects all vertices with V - 1 edges at minimum total weight
  • Kruskal = sort edges + union-find; Prim = grow with a heap
  • Watch for overflow and for the "shortest path ≠ MST" distinction
