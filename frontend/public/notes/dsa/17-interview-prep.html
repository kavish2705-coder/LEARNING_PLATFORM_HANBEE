Interview Patterns and Cheat Sheet

Turn everything into a repeatable interview routine. Pattern recognition table, complexity cheat sheets, a Java quick-reference, problem lists by topic, communication tips and a 10-week practice plan.

01How Coding Interviews Work

A typical DSA round is 30 to 60 minutes: one or two problems, solved on a shared editor or whiteboard while you talk through your thinking. Interviewers judge:

SkillWhat they look for
Problem solvingDo you clarify, plan, and reach a correct approach?
CodingClean, working, readable code in your language
Complexity analysisDo you state and justify time and space?
TestingDo you check examples and edge cases yourself?
CommunicationDo you explain trade-offs and respond to hints?

02The Interview Routine

  1. Clarify (2 to 3 min): input/output types, size limits, duplicates, negatives, sorted?, empty input, return format
  2. Examples: walk through one normal and one edge case
  3. Brute force: say it and its complexity, even if you will not code it
  4. Optimise: name the bottleneck, then apply a pattern from the table below
  5. Agree on the plan before typing
  6. Code: meaningful names, helper methods, no premature cleverness
  7. Dry run your code with an example, line by line
  8. State final complexity (time and space) and mention improvements
Tip

If you get stuck, talk. Say what you tried and why it fails: interviewers give hints to candidates who communicate, and rarely to silent ones.

07Debugging Checklist (when your code fails)

  1. Re-read the problem: did you misread a constraint?
  2. Trace a tiny input by hand against the code
  3. Check boundaries: < vs <=, n vs n - 1, empty/one-element inputs
  4. Check initial values: min/max sentinels, DP base cases
  5. Check types: integer division, overflow, char arithmetic, Integer vs int equality
  6. Check aliasing: copied lists before storing, cloned arrays, reused StringBuilder
  7. Check visited handling in graph searches
  8. Print intermediate state (in practice) or narrate it (in interviews)

08Edge Case Checklist

  • Empty input, one element, two elements
  • All the same, already sorted, reverse sorted
  • Negative numbers, zeros, very large values (overflow)
  • Duplicates; null children / head; cycles in linked lists and graphs
  • Disconnected graphs; self-loops
  • Target not present; target at the first/last position
  • Strings: empty, single character, uppercase/lowercase, spaces

09Communication Tips

  • Think aloud, but briefly; summarise your approach before coding
  • Offer trade-offs: "Sorting gives O(n log n) with O(1) extra space; a hash map gives O(n) time with O(n) space"
  • Name patterns: "This looks like a sliding window because we want the longest contiguous range"
  • Take hints gracefully; ask clarifying questions rather than guessing silently
  • When finished, test your own code before being asked, and state complexity
  • If you do not know, say what you would try and how you would verify it

Habits that work

  • Daily practice (1 to 2 problems) beats weekend marathons
  • Spend 20 to 30 minutes trying before reading a solution; then re-solve it from scratch after a few days
  • Keep a mistake log: pattern, what you missed, the fix
  • Practise timed and in a plain editor sometimes (no autocomplete)
  • Explain solutions aloud or to a friend; teaching reveals gaps
  • Do mock interviews (peers, platforms) at least weekly in the last 3 weeks

13Quick Recap

  • Follow a routine: clarify → examples → brute force → optimise → plan → code → test → analyse
  • Recognise patterns from clues (sorted → two pointers/binary search, window → sliding window, top K → heap, shortest unweighted path → BFS, subsets → backtracking, overlapping choices → DP)
  • Memorise the complexity tables and constraint-to-complexity mapping
  • Always check edge cases, overflow and off-by-one errors
  • Practise steadily with a plan, a mistake log and mock interviews
