Introduction to DSA and Big-O Analysis

What data structures and algorithms are, why interviews test them, and how to measure code with Big-O time and space complexity. Includes a problem-solving framework you can reuse for every question.

01What are Data Structures and Algorithms?

  • A data structure is a way of organising and storing data so it can be used efficiently (array, linked list, stack, tree, graph, hash table).
  • An algorithm is a step-by-step procedure that solves a problem (sorting, searching, shortest path).

Together they decide how fast your program runs and how much memory it uses.

Program = Data Structures + Algorithms

Why learn DSA?

  • Interviews: most product and service companies test DSA in coding rounds
  • Performance: choosing a HashMap over a list can turn minutes into milliseconds
  • Problem solving: you learn to break big problems into known patterns
  • Understanding libraries: you will know what ArrayList, HashMap, PriorityQueue do internally
  • Foundation for databases, operating systems, compilers and system design

03Why Efficiency Matters: A Quick Example

Find whether any two numbers in an array add up to a target.

// Approach 1: check every pair  → O(n²)
static boolean hasPairBrute(int[] a, int target) {
    for (int i = 0; i < a.length; i++)
        for (int j = i + 1; j < a.length; j++)
            if (a[i] + a[j] == target) return true;
    return false;
}

// Approach 2: remember what we have seen  → O(n)
static boolean hasPairFast(int[] a, int target) {
    Set<Integer> seen = new HashSet<>();
    for (int x : a) {
        if (seen.contains(target - x)) return true;
        seen.add(x);
    }
    return false;
}

For n = 100,000, approach 1 does about 5 billion comparisons; approach 2 does 100 thousand operations. Same answer, completely different speed.

04Complexity Analysis

We do not measure seconds (they depend on the machine). We measure how the number of steps grows as the input size n grows.

MeasuresQuestion it answers
Time complexityNumber of basic operations"How does running time grow with n?"
Space complexityExtra memory used"How does memory grow with n?"

05Big-O Notation

Big-O describes an upper bound on growth: the worst-case behaviour for large inputs.

Rules for simplifying

  1. Drop constants: O(2n) → O(n)
  2. Drop lower-order terms: O(n² + n) → O(n²)
  3. Different inputs, different variables: looping over arrays a and b is O(a + b), not O(n)
  4. Nested loops multiply, sequential loops add

Related notations

NotationMeaningAnalogy
Big-O O(f)Upper bound (at most)"No slower than…"
Big-Omega Ω(f)Lower bound (at least)"No faster than…"
Big-Theta Θ(f)Tight bound (both)"Exactly this growth"

Best, average and worst case

Take linear search for a value in an array:

  • Best case: found at index 0 → O(1)
  • Average case: found in the middle → O(n)
  • Worst case: not found or at the end → O(n)
Note

Unless told otherwise, "complexity" means the worst case. Interviewers often also ask about the average case (for example quicksort: O(n log n) average, O(n²) worst).

07Analysing Code

O(1): constant

int first = arr[0];                 // one step regardless of array size
map.get(key);                       // average case for HashMap

O(n): a single loop

int sum = 0;
for (int x : arr) sum += x;         // runs n times

O(log n): the problem shrinks by a constant factor each step

for (int i = 1; i < n; i *= 2) { }  // i doubles: about log₂(n) iterations
while (n > 1) n /= 2;               // halving

O(n²): nested loops

for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        count++;                     // n × n
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)  // n + (n-1) + ... + 1 = n(n+1)/2  → still O(n²)
        count++;

O(n log n)

for (int i = 0; i < n; i++)          // n times
    for (int j = 1; j < n; j *= 2)   // log n times
        count++;

Sequential steps add

for (int x : a) { }                  // O(n)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) { }  // O(n²)
// total O(n + n²) = O(n²)

Two different inputs

for (int x : a) { }                  // O(a)
for (int y : b) { }                  // O(b)
// total O(a + b); nested would be O(a × b)

Hidden costs

for (int i = 0; i < n; i++) {
    s = s + "x";                     // string concat copies: O(n) each → O(n²) total
    list.remove(0);                  // ArrayList shift: O(n) each → O(n²) total
    list.contains(x);                // O(n) each → O(n²) total
}

Library calls have their own complexity: always check sort (O(n log n)), substring (O(k)), String.equals (O(length)), list.contains (O(n)).

08Recursion Complexity

Count calls × work per call.

int sum(int n) { return n == 0 ? 0 : n + sum(n - 1); }   // n calls, O(1) each → O(n) time, O(n) stack space
int fib(int n) { return n < 2 ? n : fib(n-1) + fib(n-2); } // ~2ⁿ calls → O(2ⁿ)

Recurrence relations

RecurrenceResultExample
T(n) = T(n-1) + O(1)O(n)Linear recursion
T(n) = T(n/2) + O(1)O(log n)Binary search
T(n) = 2T(n/2) + O(n)O(n log n)Merge sort
T(n) = 2T(n-1) + O(1)O(2ⁿ)Naive subsets/Fibonacci
T(n) = T(n-1) + O(n)O(n²)Selection-style recursion

Master theorem for T(n) = a·T(n/b) + O(nᵈ):

  • if d > log_b(a) → O(nᵈ)
  • if d = log_b(a) → O(nᵈ log n)
  • if d < log_b(a) → O(n^(log_b a))

09Space Complexity

Count the extra memory you allocate, not the input itself.

CodeSpace
A few variablesO(1)
New array/list of size nO(n)
n × n gridO(n²)
Recursion depth dO(d) (call stack)
In-place swap, two pointersO(1)
int[] copy = Arrays.copyOf(arr, arr.length);   // O(n) extra space
reverseInPlace(arr);                            // O(1) extra space
Tip

There is often a time-space trade-off: a HashMap uses O(n) memory to make lookups O(1).

10Amortised Analysis

Some operations are usually cheap but occasionally expensive. Amortised cost is the average over a sequence of operations.

Dynamic array (ArrayList): add is normally O(1). When the array is full it allocates a bigger one (about 1.5× in Java's ArrayList) and copies everything, which is O(n). Because resizes become rarer as the array grows, the amortised cost of add is O(1).

12Constraints Tell You the Target Complexity

A computer does roughly 10⁷ to 10⁸ simple operations per second. Use the input limit to guess the needed complexity.

Max nAcceptable complexity
≤ 10 to 12O(n!), O(2ⁿ · n) (brute force, backtracking)
≤ 20 to 25O(2ⁿ) (subsets, bitmask)
≤ 100O(n³)
≤ 1,000 to 5,000O(n²)
≤ 10⁵ to 10⁶O(n log n) or O(n)
≤ 10⁹O(log n) or O(1) (maths, binary search)

13A Problem-Solving Framework

Use the same steps for every question, in interviews and in practice.

  1. Understand: restate the problem; ask about input size, types, duplicates, negatives, sorted or not, empty input
  2. Examples: work through a small example and an edge case by hand
  3. Brute force: say the simplest solution and its complexity (it proves you understand)
  4. Optimise: look for repeated work, a better data structure, sorting, two pointers, hashing, recursion/DP
  5. Plan: describe the approach and confirm before coding
  6. Code: clean names, small helpers
  7. Test: dry-run with your examples and edge cases
  8. Analyse: state final time and space complexity

14Practising in Java

Fast input (competitive programming)

import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        int n = Integer.parseInt(br.readLine().trim());
        StringTokenizer st = new StringTokenizer(br.readLine());
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = Integer.parseInt(st.nextToken());

        StringBuilder out = new StringBuilder();
        out.append(a.length).append('\n');
        System.out.print(out);
    }
}

Measuring time

long start = System.nanoTime();
solve();
System.out.println((System.nanoTime() - start) / 1_000_000 + " ms");

Java-specific pitfalls

  • int overflows at about 2.1 × 10⁹: use long for sums/products (mid = lo + (hi - lo) / 2)
  • Compare boxed values with equals, not == (Integer cache trap)
  • Use StringBuilder for building strings in loops
  • Don't remove from a list while iterating; use an Iterator or index loop backwards
  • Arrays.sort(int[]) is fast, but sorting Integer[] with a lambda comparator avoids subtraction overflow: use Integer.compare(a, b)

15Where to Practise

  • Start with arrays and strings, then follow the order of these notes
  • Solve 2 to 3 problems per topic before moving on; revisit failures after a few days
  • Platforms: LeetCode, HackerRank, GeeksforGeeks, Codeforces, CodeChef, NeetCode roadmap

16Quick Recap

  • DSA decides speed and memory; efficient solutions matter at scale
  • Big-O describes worst-case growth; drop constants and lower-order terms
  • Loops multiply when nested, add when sequential; halving gives log n
  • Recursion cost = number of calls × work per call; know the common recurrences
  • Know the complexity of Java collections; use constraints to pick a target complexity
  • Follow a framework: understand → examples → brute force → optimise → code → test → analyse
