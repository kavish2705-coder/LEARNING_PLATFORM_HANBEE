Binary Search Trees and Balanced Trees

Ordered trees with fast search. BST operations including deletion, validation and k-th smallest, why balance matters, AVL rotations, red-black and B-trees, and range-query structures.

01Binary Search Tree (BST)

A binary tree where, for every node:

  • all values in the left subtree are smaller
  • all values in the right subtree are larger
  • both subtrees are themselves BSTs
            8
          /   \
         3     10
        / \      \
       1   6      14
          / \    /
         4   7  13

Inorder traversal of a BST gives the values in sorted order: 1 3 4 6 7 8 10 13 14.

OperationBalancedSkewed (worst)
SearchO(log n)O(n)
InsertO(log n)O(n)
DeleteO(log n)O(n)
Min / maxO(log n)O(n)

Inserting already sorted data into a plain BST creates a linked-list-shaped tree, so O(n) operations. That is the reason balanced trees exist.

02BST Operations

Search

static TreeNode search(TreeNode root, int key) {
    while (root != null && root.val != key)
        root = key < root.val ? root.left : root.right;
    return root;
}

Insert

static TreeNode insert(TreeNode root, int key) {
    if (root == null) return new TreeNode(key);
    if (key < root.val) root.left = insert(root.left, key);
    else if (key > root.val) root.right = insert(root.right, key);
    return root;                                             // duplicates ignored
}

Minimum and maximum

static TreeNode min(TreeNode n) { while (n.left != null) n = n.left; return n; }
static TreeNode max(TreeNode n) { while (n.right != null) n = n.right; return n; }

Delete: three cases

  1. Leaf: just remove it
  2. One child: replace the node with its child
  3. Two children: replace its value with the inorder successor (smallest in the right subtree), then delete that successor
static TreeNode delete(TreeNode root, int key) {
    if (root == null) return null;
    if (key < root.val) root.left = delete(root.left, key);
    else if (key > root.val) root.right = delete(root.right, key);
    else {
        if (root.left == null) return root.right;           // cases 1 and 2
        if (root.right == null) return root.left;
        TreeNode succ = min(root.right);                    // case 3
        root.val = succ.val;
        root.right = delete(root.right, succ.val);
    }
    return root;
}

Inorder successor and predecessor

static TreeNode successor(TreeNode root, int key) {          // smallest value greater than key
    TreeNode succ = null;
    while (root != null) {
        if (key < root.val) { succ = root; root = root.left; }
        else root = root.right;
    }
    return succ;
}

Floor and ceiling

static Integer floor(TreeNode root, int key) {               // greatest value <= key
    Integer res = null;
    while (root != null) {
        if (root.val == key) return key;
        if (root.val < key) { res = root.val; root = root.right; }
        else root = root.left;
    }
    return res;
}

03Classic BST Problems

Validate a BST

Checking only left < node < right locally is wrong; every node must satisfy the bounds inherited from its ancestors.

static boolean isValidBST(TreeNode n) { return valid(n, Long.MIN_VALUE, Long.MAX_VALUE); }
static boolean valid(TreeNode n, long lo, long hi) {
    if (n == null) return true;
    if (n.val <= lo || n.val >= hi) return false;
    return valid(n.left, lo, n.val) && valid(n.right, n.val, hi);
}

Alternative: inorder traversal must be strictly increasing.

K-th smallest element

static int kthSmallest(TreeNode root, int k) {
    Deque<TreeNode> st = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !st.isEmpty()) {
        while (cur != null) { st.push(cur); cur = cur.left; }
        cur = st.pop();
        if (--k == 0) return cur.val;                        // O(h + k)
        cur = cur.right;
    }
    return -1;
}

If the tree is queried often and modified, store subtree sizes in each node for O(h) rank queries.

LCA in a BST: O(h)

static TreeNode lcaBST(TreeNode root, int p, int q) {
    while (root != null) {
        if (p < root.val && q < root.val) root = root.left;
        else if (p > root.val && q > root.val) root = root.right;
        else return root;                                    // the split point
    }
    return null;
}

Sorted array to a height-balanced BST

static TreeNode sortedArrayToBST(int[] a, int lo, int hi) {
    if (lo > hi) return null;
    int mid = lo + (hi - lo) / 2;
    TreeNode n = new TreeNode(a[mid]);
    n.left = sortedArrayToBST(a, lo, mid - 1);
    n.right = sortedArrayToBST(a, mid + 1, hi);
    return n;
}

Range sum of a BST (prune with the ordering)

static int rangeSum(TreeNode n, int lo, int hi) {
    if (n == null) return 0;
    if (n.val < lo) return rangeSum(n.right, lo, hi);
    if (n.val > hi) return rangeSum(n.left, lo, hi);
    return n.val + rangeSum(n.left, lo, hi) + rangeSum(n.right, lo, hi);
}

04Why Balance Matters

A self-balancing tree keeps its height at O(log n) automatically after inserts and deletes, guaranteeing O(log n) operations regardless of insertion order.

TreeBalance ruleNotes
AVLHeight difference of the two subtrees (balance factor) is -1, 0 or +1Strictly balanced, faster lookups, more rotations
Red-BlackColour rules guarantee longest path ≤ 2 × shortestFewer rotations; used by TreeMap, TreeSet, Linux kernel
B-tree / B+ treeNodes hold many keys; all leaves at the same depthDatabases and file systems (fewer disk reads)
Treap, Splay, Skip listRandomised / self-adjustingSimpler implementations

05AVL Tree

Balance factor = height(left) - height(right). After an insert or delete, if any node has a balance factor of ±2, fix it with rotations.

Rotations

Right rotation (left-heavy, "LL" case)        Left rotation (right-heavy, "RR" case)

      z                  y                       z                     y
     / \                / \                     / \                   / \
    y   T4   ──►       x   z                  T1   y     ──►        z   x
   / \                / \ / \                      / \              / \ / \
  x   T3             T1 T2 T3 T4                 T2   x           T1 T2 T3 T4
 / \                                                 / \
T1 T2                                               T3 T4
CaseCauseFix
LLInserted into the left child's left subtreeRight rotation
RRInserted into the right child's right subtreeLeft rotation
LRInserted into the left child's right subtreeLeft-rotate the child, then right-rotate the node
RLInserted into the right child's left subtreeRight-rotate the child, then left-rotate the node
class AVLNode {
    int key, height = 1;
    AVLNode left, right;
    AVLNode(int k) { key = k; }
}

static int h(AVLNode n) { return n == null ? 0 : n.height; }
static void update(AVLNode n) { n.height = 1 + Math.max(h(n.left), h(n.right)); }
static int balance(AVLNode n) { return n == null ? 0 : h(n.left) - h(n.right); }

static AVLNode rotateRight(AVLNode z) {
    AVLNode y = z.left;
    z.left = y.right;
    y.right = z;
    update(z); update(y);
    return y;                                               // new subtree root
}
static AVLNode rotateLeft(AVLNode z) {
    AVLNode y = z.right;
    z.right = y.left;
    y.left = z;
    update(z); update(y);
    return y;
}

static AVLNode insert(AVLNode n, int key) {
    if (n == null) return new AVLNode(key);
    if (key < n.key) n.left = insert(n.left, key);
    else if (key > n.key) n.right = insert(n.right, key);
    else return n;

    update(n);
    int bf = balance(n);
    if (bf > 1 && key < n.left.key)  return rotateRight(n);                          // LL
    if (bf < -1 && key > n.right.key) return rotateLeft(n);                          // RR
    if (bf > 1 && key > n.left.key)  { n.left = rotateLeft(n.left); return rotateRight(n); }    // LR
    if (bf < -1 && key < n.right.key) { n.right = rotateRight(n.right); return rotateLeft(n); } // RL
    return n;
}

AVL height is at most about 1.44 log₂ n; insertion needs at most one rebalancing (single or double rotation), deletion may need O(log n) rotations.

06Red-Black Tree (Overview)

Each node is red or black with these rules:

  1. The root is black
  2. A red node cannot have a red child
  3. Every path from a node to its null descendants has the same number of black nodes

These guarantee height ≤ 2 log₂(n + 1). Inserts and deletes use recolouring and at most 2 to 3 rotations. It is the structure behind Java's TreeMap/TreeSet and HashMap tree bins.

AVLRed-Black
BalanceStricterLooser
LookupsSlightly fasterSlightly slower
Insert/deleteMore rotationsFewer rotations
Best forRead-heavyWrite-heavy / general library use

07Java's Ordered Collections

TreeMap<Integer, String> map = new TreeMap<>();
map.put(5, "e"); map.put(1, "a"); map.put(9, "i");
map.firstKey();         map.lastKey();
map.floorKey(6);        // 5   greatest key <= 6
map.ceilingKey(6);      // 9   smallest key >= 6
map.lowerKey(5);        // 1   strictly less
map.higherKey(5);       // 9   strictly greater
map.headMap(5);         map.tailMap(5);   map.subMap(1, 9);
map.pollFirstEntry();   map.descendingMap();

TreeSet<Integer> set = new TreeSet<>(List.of(10, 20, 30));
set.floor(25);  set.ceiling(25);  set.first();  set.last();  set.subSet(10, true, 20, true);

All in O(log n). Typical uses: calendar booking, "find the nearest value", sliding-window median, sorted streams.

08B-Trees and B+ Trees

  • Each node stores many keys (hundreds) and has many children, so the tree is very shallow (3 to 4 levels for millions of rows)
  • Designed to minimise disk reads: one node = one disk page
  • B+ tree: data only in leaves, leaves linked in order → fast range scans. Used by MySQL InnoDB, PostgreSQL indexes and most file systems
Search cost ≈ height of the tree ≈ log_m(n) page reads   (m = keys per node)

09Range Query Structures (Preview)

StructureSolvesBuildQuery / update
Prefix sumsStatic range sumO(n)O(1) query
Fenwick tree (BIT)Range sum with point updatesO(n)O(log n)
Segment treeRange sum/min/max with updates (and lazy range updates)O(n)O(log n)

class FenwickTree {
    private final long[] bit;
    FenwickTree(int n) { bit = new long[n + 1]; }

    void add(int i, long delta) {                           // 1-indexed
        for (; i < bit.length; i += i & -i) bit[i] += delta;
    }
    long prefixSum(int i) {
        long s = 0;
        for (; i > 0; i -= i & -i) s += bit[i];
        return s;
    }
    long rangeSum(int l, int r) { return prefixSum(r) - prefixSum(l - 1); }
}

10BST vs Hash Table vs Sorted Array

BST (balanced)Hash tableSorted array
SearchO(log n)O(1) avgO(log n)
Insert / deleteO(log n)O(1) avgO(n)
Sorted iterationO(n)Needs sortingO(n)
Min / max, floor / ceiling, range queriesO(log n)Not supportedO(log n)

Choose a BST/TreeMap when you need order-based queries; a hash table when you only need exact-match lookups.

11Common Mistakes

  • Validating a BST by comparing only parent and child (use bounds)
  • Using int bounds when node values can equal Integer.MIN_VALUE/MAX_VALUE (use long or null bounds)
  • Forgetting the two-children case in deletion
  • Assuming a plain BST is balanced
  • Allowing duplicates without a rule (count field, or always left/right)

12Quick Recap

  • BST property: left < node < right; inorder is sorted; operations are O(h)
  • Delete has three cases (leaf, one child, two children → use the inorder successor)
  • Validate with ranges, not just parent-child comparisons
  • Self-balancing trees (AVL, red-black) keep h = O(log n) using rotations; Java's TreeMap is red-black
  • B+ trees power database indexes; Fenwick/segment trees answer range queries with updates
