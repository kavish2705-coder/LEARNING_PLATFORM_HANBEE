Inheritance, Polymorphism and Abstraction

Reuse code with inheritance, change behaviour with overriding, and design with abstract classes and interfaces.

01Inheritance

Inheritance lets a subclass acquire fields and methods of a superclass using extends. It models an IS-A relationship: a Dog is an Animal.

class Animal {
    String name;
    void eat() { System.out.println(name + " is eating"); }
}

class Dog extends Animal {
    void bark() { System.out.println(name + " says Woof"); }
}

Dog d = new Dog();
d.name = "Tommy";
d.eat();     // inherited
d.bark();

Types of inheritance

TypeSupported with classes?
Single (A → B)Yes
Multilevel (A → B → C)Yes
Hierarchical (A → B, A → C)Yes
Multiple (B extends A and C)No (use interfaces)
Note

Java forbids multiple inheritance of classes to avoid the diamond problem, where two parents provide conflicting implementations.

What is (not) inherited

  • Inherited: public and protected members, and package-private members in the same package
  • Not inherited: private members, constructors, static initialisers
  • Every class ultimately extends Object

02The super Keyword

UseExample
Call parent constructor (first line)super(name);
Call overridden parent methodsuper.eat();
Access parent field hidden by childsuper.name
class Employee {
    String name;
    Employee(String name) { this.name = name; }
}

class Manager extends Employee {
    int teamSize;
    Manager(String name, int teamSize) {
        super(name);               // must be first statement
        this.teamSize = teamSize;
    }
}

If a subclass constructor does not call super(...), the compiler inserts super(). If the parent has no no-arg constructor, you must call super(args) explicitly.

Constructor chaining order

Parent constructor runs before child constructor.

03Method Overriding

A subclass provides its own implementation of an inherited method. This is runtime polymorphism.

class Shape {
    double area() { return 0; }
}

class Circle extends Shape {
    double r;
    Circle(double r) { this.r = r; }

    @Override
    double area() { return Math.PI * r * r; }
}

Rules of overriding

  • Same name, same parameter list, compatible return type (covariant allowed)
  • Access cannot be weaker (a public method cannot become protected)
  • Cannot throw broader checked exceptions
  • private, static and final methods cannot be overridden
  • Always add @Override: the compiler checks you really are overriding

Overloading vs overriding

OverloadingOverriding
WhereSame class (or subclass)Subclass
ParametersMust differMust be same
ResolvedCompile timeRuntime
Return typeCan differSame or covariant

04Polymorphism

One reference type, many actual behaviours.

Shape s = new Circle(2);        // upcasting: parent reference, child object
System.out.println(s.area());   // calls Circle.area() (dynamic dispatch)
Shape[] shapes = { new Circle(1), new Rectangle(2, 3), new Triangle(3, 4) };
for (Shape sh : shapes) {
    System.out.println(sh.area());   // each runs its own version
}

Upcasting and downcasting

Animal a = new Dog();          // upcast, implicit and safe
// a.bark();                    // compile error: Animal has no bark()
if (a instanceof Dog dog) {     // safe downcast with pattern matching
    dog.bark();
}
Dog d = (Dog) a;               // explicit downcast, ClassCastException if wrong
Interview question

Can fields be overridden? What about static methods?

No. Fields and static methods are hidden, not overridden, and are resolved by the reference type at compile time. Only instance methods use dynamic dispatch.

06Abstraction

Abstraction hides implementation details and shows only essential behaviour. Java offers abstract classes and interfaces.

Abstract classes

abstract class Vehicle {
    String brand;
    Vehicle(String brand) { this.brand = brand; }

    abstract void start();               // no body: subclasses must implement

    void stop() { System.out.println("Stopped"); }   // concrete method
}

class Car extends Vehicle {
    Car(String brand) { super(brand); }
    @Override void start() { System.out.println(brand + " starts with key"); }
}

// Vehicle v = new Vehicle("x");  // compile error: cannot instantiate
Vehicle v = new Car("Toyota");
  • Can have abstract and concrete methods, fields, constructors
  • Cannot be instantiated; a subclass must implement all abstract methods or be abstract itself
  • A class with even one abstract method must be declared abstract

Abstract class vs interface (summary)

07The Object Class: equals, hashCode, toString

class Student {
    int id; String name;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Student s)) return false;
        return id == s.id && Objects.equals(name, s.name);
    }

    @Override
    public int hashCode() { return Objects.hash(id, name); }

    @Override
    public String toString() { return "Student[" + id + "," + name + "]"; }
}
Warning

If you override equals(), you must override hashCode(). Equal objects must have equal hash codes or HashMap and HashSet will misbehave.

The contract

  • Reflexive: x.equals(x) is true
  • Symmetric: x.equals(y) ⇔ y.equals(x)
  • Transitive: if x.equals(y) and y.equals(z) then x.equals(z)
  • Consistent: repeated calls give the same result
  • x.equals(null) is always false

08Composition over Inheritance

HAS-A relationships are often more flexible than IS-A.

class Engine { void start() { } }

class Car {
    private final Engine engine = new Engine();   // Car HAS-A Engine
    void start() { engine.start(); }
}

Use inheritance only for a genuine IS-A relationship. Use composition to reuse behaviour without tight coupling.

RelationshipMeaningExample
AssociationObjects know each otherTeacher ↔ Student
AggregationHAS-A, parts can exist aloneDepartment has Teachers
CompositionHAS-A, parts die with the wholeHouse has Rooms

09Quick Recap

  • extends gives IS-A reuse; Java allows one parent class
  • Overriding gives runtime polymorphism; overloading is compile-time
  • super reaches the parent; final stops overriding/extending
  • Abstract classes mix shared code with required methods
  • Override equals and hashCode together
  • Prefer composition when the relationship is HAS-A
