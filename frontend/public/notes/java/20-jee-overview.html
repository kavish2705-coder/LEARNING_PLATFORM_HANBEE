Jakarta EE (JEE) Overview and Architecture

What enterprise Java is. Jakarta EE specifications, containers, multi-tier architecture, web servers versus application servers, WAR/EAR packaging and how the Spring ecosystem relates.

01What is JEE?

Java EE (Java Enterprise Edition) is a set of specifications built on top of Java SE for developing large, distributed, secure, multi-user business applications: web sites, REST services, messaging systems, banking back-ends.

In 2017 Oracle donated it to the Eclipse Foundation. It was renamed Jakarta EE, and the package names changed from javax.* to jakarta.* in Jakarta EE 9.

NamePeriodPackage prefix
J2EE1999 to 2005javax.*
Java EE 5 to 82006 to 2017javax.*
Jakarta EE 82019javax.* (same as Java EE 8)
Jakarta EE 9+ (10, 11)2020 onwardjakarta.*
Warning

javax.servlet.* and jakarta.servlet.* are not compatible. Tomcat 10+ and Spring Boot 3+ use jakarta.*; older Tomcat 9 and Spring Boot 2 use javax.*. Mixing them gives ClassNotFoundException or NoClassDefFoundError.

A specification is an API plus rules (an interface contract). Many vendors provide implementations, so your code is portable.

05Containers

A container is the runtime that hosts your components and provides services: lifecycle management, security, transactions, threading, resource pooling and dependency injection. You write business code; the container does the plumbing (the Hollywood principle: "don't call us, we'll call you").

ContainerHostsProvided by
Web (Servlet) containerServlets, JSP, filtersTomcat, Jetty
EJB containerEnterprise beansFull app servers
CDI containerManaged beansWeld etc.
Client containerStandalone clientsRare

07Packaging and Deployment

WAR structure

myapp.war
├── index.html, css/, js/              ← public static content
├── WEB-INF/                           ← NOT directly accessible from the browser
│   ├── web.xml                        ← deployment descriptor (optional with annotations)
│   ├── classes/                       ← compiled classes
│   └── lib/                           ← dependency jars
└── META-INF/context.xml

Deployment descriptor (web.xml)

<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee" version="6.0">
  <servlet>
    <servlet-name>hello</servlet-name>
    <servlet-class>com.hanbee.HelloServlet</servlet-class>
  </servlet>
  <servlet-mapping>
    <servlet-name>hello</servlet-name>
    <url-pattern>/hello</url-pattern>
  </servlet-mapping>
  <session-config><session-timeout>30</session-timeout></session-config>
  <welcome-file-list><welcome-file>index.html</welcome-file></welcome-file-list>
</web-app>

Since Servlet 3.0 most of this can be replaced by annotations such as @WebServlet("/hello").

08Core Technologies in One Look

Servlet

Java class that handles HTTP requests and responses (next topics).

EJB (Enterprise JavaBeans)

Server-side business components with built-in transactions, security and pooling.

TypePurpose
@StatelessNo client state, pooled. Most common.
@StatefulHolds state per client
@SingletonOne shared instance
@MessageDrivenConsumes JMS messages
@Stateless
public class StudentService {
    @PersistenceContext private EntityManager em;
    public void register(Student s) { em.persist(s); }   // transaction managed by the container
}

CDI (Contexts and Dependency Injection)

@ApplicationScoped
public class GreetingService { public String greet() { return "Hello"; } }

@Inject GreetingService service;

Scopes: @RequestScoped, @SessionScoped, @ApplicationScoped, @Dependent.

JPA, JAX-RS, JMS, JTA

Covered in later topics: JPA persists objects, JAX-RS builds REST APIs, JMS sends asynchronous messages (queues and topics), JTA coordinates transactions (@Transactional).

Spring Boot builds on the same standards (Servlet API, JPA, Bean Validation, JTA), so learning Jakarta EE fundamentals makes Spring much easier.

10Typical Request Flow

  1. Browser sends GET /students/5
  2. Web server/Tomcat receives it; the servlet container picks the right servlet via URL mapping
  3. Filters run first (security, logging, encoding)
  4. Servlet/controller calls the service (business logic, transaction)
  5. Service calls the repository (JPA/JDBC) → database
  6. Result flows back; a JSP/template or JSON serializer builds the response
  7. Container sends the HTTP response

11Setting Up a Development Environment

  1. JDK 17 or 21
  2. IDE: IntelliJ IDEA / Eclipse IDE for Enterprise Java
  3. Server: Apache Tomcat 10+ (Jakarta) or WildFly/Payara
  4. Build: Maven with <packaging>war</packaging>
  5. Database: PostgreSQL or MySQL
<packaging>war</packaging>
<dependencies>
  <dependency>
    <groupId>jakarta.servlet</groupId>
    <artifactId>jakarta.servlet-api</artifactId>
    <version>6.1.0</version>
    <scope>provided</scope>      <!-- Tomcat supplies it at runtime -->
  </dependency>
</dependencies>

12Quick Recap

  • Jakarta EE = enterprise specifications on top of Java SE; packages are jakarta.* from EE 9
  • Containers provide lifecycle, transactions, security and injection
  • Layers: Web (Servlet/JSP/REST) → Business (EJB/CDI) → Data (JPA/JDBC)
  • Deploy as WAR (web) or EAR (enterprise); WEB-INF is private
  • Spring Boot uses the same underlying standards with an embedded server
