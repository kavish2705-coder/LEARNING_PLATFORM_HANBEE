Exception Handling

Handle runtime problems gracefully with try, catch, finally, throw and throws. Checked versus unchecked exceptions, custom exceptions and best practices.

01What is an Exception?

An exception is an event that disrupts the normal flow of a program at runtime, such as dividing by zero, opening a missing file or accessing null. Java represents it as an object. Handling it lets the program recover or fail cleanly instead of crashing.

int result = 10 / 0;   // throws ArithmeticException: / by zero

02Exception Hierarchy

Throwable
 ├── Error                         (JVM problems, do not catch)
 │    ├── OutOfMemoryError
 │    ├── StackOverflowError
 │    └── AssertionError
 └── Exception
      ├── IOException, SQLException, ...        ← CHECKED
      ├── InterruptedException, ClassNotFoundException
      └── RuntimeException                       ← UNCHECKED
           ├── NullPointerException
           ├── ArithmeticException
           ├── ArrayIndexOutOfBoundsException
           ├── ClassCastException
           ├── IllegalArgumentException
           └── NumberFormatException

03try, catch and finally

try {
    int n = Integer.parseInt(input);
    System.out.println(100 / n);
} catch (NumberFormatException e) {
    System.out.println("Not a number: " + e.getMessage());
} catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero");
} finally {
    System.out.println("Always runs");   // cleanup
}
  • A try needs at least one catch or a finally
  • Catch blocks are checked top to bottom: put specific exceptions before general ones
  • finally runs whether or not an exception occurs (except System.exit() or JVM crash)

Multi-catch (Java 7)

try { riskyCode(); }
catch (IOException | SQLException e) {      // alternatives cannot be related by inheritance
    log(e);
}

04try-with-resources (Java 7)

Resources that implement AutoCloseable are closed automatically, even on exceptions.

try (BufferedReader br = new BufferedReader(new FileReader("data.txt"));
     PrintWriter pw = new PrintWriter("out.txt")) {
    String line;
    while ((line = br.readLine()) != null) pw.println(line);
}   // br and pw closed here, in reverse order
Tip

Always prefer try-with-resources over a manual finally { close(); } for files, sockets, JDBC connections and streams.

05throw and throws

static void setAge(int age) {
    if (age < 0) throw new IllegalArgumentException("Age cannot be negative");   // throw: create + raise
}

static void readFile(String path) throws IOException {      // throws: declare a checked exception
    Files.readAllLines(Path.of(path));
}
KeywordWherePurpose
throwInside a method bodyActually raise one exception object
throwsMethod signatureDeclare which checked exceptions may escape

06Custom Exceptions

public class InsufficientBalanceException extends Exception {     // checked
    private final double shortBy;

    public InsufficientBalanceException(String message, double shortBy) {
        super(message);
        this.shortBy = shortBy;
    }
    public double getShortBy() { return shortBy; }
}

class Account {
    private double balance;
    void withdraw(double amt) throws InsufficientBalanceException {
        if (amt > balance) throw new InsufficientBalanceException("Low balance", amt - balance);
        balance -= amt;
    }
}

Extend RuntimeException instead if callers cannot reasonably recover.

Exception chaining

try {
    dao.save(user);
} catch (SQLException e) {
    throw new ServiceException("Could not save user", e);    // keep the original as the cause
}

07How Exceptions Propagate

If a method does not handle an exception, it travels up the call stack to its caller, and so on, until something catches it or the thread dies with a stack trace.

main() → serviceA() → serviceB() → dao()  ✘ throws
         ↑ unwinds through each frame until a matching catch is found

08finally Subtleties

  • finally runs even if try or catch has a return
  • A return inside finally overrides earlier returns and swallows exceptions: avoid it
  • If both try and finally throw, the finally exception wins (use try-with-resources to keep suppressed exceptions)
static int test() {
    try { return 1; }
    finally { System.out.println("cleanup"); }   // prints, then returns 1
}

09Best Practices

  • Catch specific exceptions, never an empty catch (Exception e) {}
  • Don't use exceptions for normal control flow
  • Fail early with validation: Objects.requireNonNull(x, "x must not be null")
  • Log once, at the boundary, then rethrow or handle: don't log-and-throw at every layer
  • Preserve the cause when wrapping
  • Release resources with try-with-resources
  • Use unchecked exceptions for programming errors; checked for recoverable external failures
  • Never catch Error or Throwable unless you are a framework
Interview question

What is the difference between final, finally and finalize?

final is a modifier (constant / no override / no inherit). finally is a block that always runs after try. finalize() was a method called by the GC before reclaiming an object and is deprecated for removal.

Interview question

Can we have a try block without catch?

Yes, with finally or as try-with-resources.

11Quick Recap

  • Throwable → Error (don't catch) and Exception
  • Checked exceptions must be handled or declared; unchecked need not
  • try / catch / finally, multi-catch and try-with-resources
  • throw raises, throws declares
  • Wrap with a cause, catch specifically, never swallow silently
