Build Tools, Testing and Logging

Professional project tooling. Maven and Gradle, project structure, JUnit 5 and Mockito for testing, SLF4J logging and Git basics.

01Why Build Tools?

Real projects have dozens of libraries, many modules and repeatable steps (compile, test, package). A build tool automates this and manages dependencies.

MavenGradle
ConfigXML (pom.xml)Groovy/Kotlin DSL (build.gradle)
StyleConvention, declarativeFlexible, scriptable
SpeedGoodFaster (incremental, daemon, cache)
Common inEnterprise, SpringAndroid, modern projects

02Standard Project Layout

my-app/
├── pom.xml
├── src/
│   ├── main/
│   │   ├── java/com/hanbee/app/App.java
│   │   └── resources/application.properties
│   └── test/
│       ├── java/com/hanbee/app/AppTest.java
│       └── resources/
└── target/            ← build output (do not commit)

03Maven

pom.xml

<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>

  <groupId>com.hanbee</groupId>
  <artifactId>lms-app</artifactId>
  <version>1.0.0</version>
  <packaging>jar</packaging>

  <properties>
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>

  <dependencies>
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>5.11.0</version>
      <scope>test</scope>
    </dependency>
  </dependencies>
</project>

GAV coordinates (groupId:artifactId:version) uniquely identify an artifact in a repository such as Maven Central.

Dependency scopes

ScopeAvailable at
compile (default)Compile, test, runtime
providedCompile and test only (container supplies it, e.g. Servlet API)
runtimeRuntime and test (e.g. JDBC driver)
testTest only

Build lifecycle and commands

PhaseDoes
validateCheck the project
compileCompile sources
testRun unit tests
packageCreate the jar/war
verifyRun integration checks
installCopy to the local repository
deployUpload to a remote repository
mvn clean compile
mvn test
mvn clean package
mvn clean install -DskipTests
mvn dependency:tree

Each phase runs all the earlier ones. Use the Maven Wrapper (./mvnw) so everyone uses the same version.

Gradle equivalent

plugins { id 'java' }
java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }
repositories { mavenCentral() }
dependencies {
    testImplementation 'org.junit.jupiter:junit-jupiter:5.11.0'
}
test { useJUnitPlatform() }
./gradlew build
./gradlew test

04Testing with JUnit 5

import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorTest {
    private Calculator calc;

    @BeforeEach
    void setUp() { calc = new Calculator(); }

    @Test
    @DisplayName("adds two numbers")
    void add() {
        assertEquals(5, calc.add(2, 3));
    }

    @Test
    void divideByZeroThrows() {
        ArithmeticException ex = assertThrows(ArithmeticException.class, () -> calc.divide(1, 0));
        assertEquals("/ by zero", ex.getMessage());
    }
}

Annotations

AnnotationPurpose
@TestA test method
@BeforeEach / @AfterEachRun around every test
@BeforeAll / @AfterAllOnce per class (static)
@DisplayNameReadable name
@DisabledSkip
@NestedGroup tests
@TagFilter groups
@ParameterizedTestRun with many inputs

Assertions

assertEquals(expected, actual);       assertNotEquals(a, b);
assertTrue(cond);                     assertFalse(cond);
assertNull(x);                        assertNotNull(x);
assertArrayEquals(exp, act);          assertSame(a, b);
assertThrows(IOException.class, () -> ...);
assertAll(() -> assertEquals(1, a), () -> assertEquals(2, b));
assertTimeout(Duration.ofSeconds(1), () -> slowCall());

Parameterized tests

@ParameterizedTest
@CsvSource({"1,1,2", "2,3,5", "10,-5,5"})
void addCases(int a, int b, int expected) {
    assertEquals(expected, calc.add(a, b));
}

@ParameterizedTest
@ValueSource(strings = {"", " ", "\t"})
void blankStrings(String s) { assertTrue(s.isBlank()); }

Good test habits (FIRST)

  • Fast, Independent, Repeatable, Self-validating, Timely
  • Pattern: Arrange → Act → Assert
  • One logical behaviour per test, descriptive names
  • Test behaviour and edge cases (null, empty, boundaries), not private methods

05Mocking with Mockito

A mock replaces a real collaborator (database, API) so you test one class in isolation.

@ExtendWith(MockitoExtension.class)
class EnrollmentServiceTest {
    @Mock StudentRepository repo;
    @Mock EmailSender email;
    @InjectMocks EnrollmentService service;

    @Test
    void enrollSendsConfirmation() {
        when(repo.findById(1L)).thenReturn(Optional.of(new Student(1L, "Asha")));

        service.enroll(1L, "JAVA101");

        verify(email).send(eq("Asha"), contains("JAVA101"));
        verify(repo, times(1)).save(any(Enrollment.class));
    }

    @Test
    void unknownStudentThrows() {
        when(repo.findById(99L)).thenReturn(Optional.empty());
        assertThrows(StudentNotFoundException.class, () -> service.enroll(99L, "JAVA101"));
    }
}

Test types

TypeScopeTools
UnitOne classJUnit, Mockito
IntegrationSeveral components, real DBSpring Boot Test, Testcontainers
End-to-endWhole systemSelenium, Playwright, REST Assured

Also: TDD (write the failing test first), code coverage (JaCoCo; high coverage does not mean good tests).

06Logging

Never use System.out.println for application logs. Use a logging framework: levels, formats, files, rotation and per-package control.

SLF4J + Logback (standard stack)

private static final Logger log = LoggerFactory.getLogger(EnrollmentService.class);

log.trace("very detailed");
log.debug("Loading student {}", id);              // {} placeholders: no string building when disabled
log.info("Student {} enrolled in {}", id, course);
log.warn("Retrying payment, attempt {}", attempt);
log.error("Enrollment failed for {}", id, exception);   // exception last: logs stack trace
LevelUse for
TRACEFinest detail
DEBUGDeveloper diagnostics
INFONormal important events
WARNUnexpected but recoverable
ERRORFailures needing attention
<configuration>
  <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
    <encoder><pattern>%d{HH:mm:ss} %-5level %logger{20} - %msg%n</pattern></encoder>
  </appender>
  <logger name="com.hanbee" level="DEBUG"/>
  <root level="INFO"><appender-ref ref="CONSOLE"/></root>
</configuration>
Warning

Never log passwords, tokens or personal data.

08Quick Recap

  • Maven/Gradle manage dependencies, builds and project structure
  • mvn clean package builds; tests run in the test phase
  • JUnit 5 for tests; Mockito to isolate dependencies
  • Use SLF4J with {} placeholders and proper levels, not println
  • Keep everything in Git; ignore build output and secrets
