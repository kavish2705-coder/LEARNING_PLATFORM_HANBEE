Collections Framework

The standard data-structure library. List, Set, Map and Queue families, how HashMap works, sorting with Comparable and Comparator, and choosing the right collection.

01Collections Overview

The Java Collections Framework (package java.util) provides ready-made, tested data structures and algorithms. Everything is built on interfaces so implementations can be swapped.

Iterable
  └── Collection
        ├── List   ── ArrayList, LinkedList, Vector → Stack, (CopyOnWriteArrayList)
        ├── Set    ── HashSet → LinkedHashSet, TreeSet (SortedSet/NavigableSet)
        └── Queue  ── PriorityQueue, ArrayDeque (Deque), LinkedList

Map (separate hierarchy)
  ── HashMap → LinkedHashMap, TreeMap (SortedMap/NavigableMap), Hashtable, ConcurrentHashMap

03List

An ordered collection with positional access.

ArrayList

Backed by a resizable array. Fast random access, slow insert/remove in the middle.

List<String> names = new ArrayList<>();
names.add("Asha");
names.add("Ravi");
names.add(1, "Meena");          // insert at index
names.set(0, "Aisha");
String n = names.get(2);
names.remove("Ravi");           // by object
names.remove(0);                // by index
names.contains("Meena");
names.indexOf("Meena");
Collections.sort(names);
List<String> immutable = List.of("a", "b", "c");     // Java 9+, cannot be modified

LinkedList

A doubly linked list; also implements Deque. Fast insert/remove at the ends, slow get(i).

Vector and Stack

Legacy, synchronised classes. Prefer ArrayList and ArrayDeque.

A collection with no duplicates.

Set<Integer> set = new HashSet<>(List.of(3, 1, 2, 3));
set.add(2);                              // returns false: already present
Set<String> sorted = new TreeSet<>(List.of("pear", "apple", "fig"));   // apple, fig, pear

TreeSet<Integer> ts = new TreeSet<>(List.of(10, 20, 30, 40));
ts.first();  ts.last();  ts.floor(25);  ts.ceiling(25);  ts.headSet(30);  ts.descendingSet();
Note

HashSet uses hashCode() and equals() of your elements. Without a proper pair, duplicates may sneak in.

05Map

Stores key → value pairs. Keys are unique.

Map<String, Integer> marks = new HashMap<>();
marks.put("Asha", 90);
marks.put("Ravi", 75);
marks.put("Asha", 95);                       // replaces existing value
int m = marks.get("Asha");
int d = marks.getOrDefault("Zoya", 0);
marks.putIfAbsent("Meena", 80);
marks.containsKey("Ravi");  marks.containsValue(75);
marks.remove("Ravi");

for (Map.Entry<String, Integer> e : marks.entrySet()) {
    System.out.println(e.getKey() + " = " + e.getValue());
}
marks.forEach((k, v) -> System.out.println(k + " " + v));

// handy compute methods
marks.merge("Asha", 5, Integer::sum);                        // counting / accumulating
marks.computeIfAbsent("Tara", k -> 60);
marks.computeIfPresent("Tara", (k, v) -> v + 10);
Map<String, Integer> fixed = Map.of("a", 1, "b", 2);        // immutable

How HashMap works internally

  1. hashCode() of the key is computed and spread into a bucket index
  2. The entry goes into that bucket (an array slot)
  3. If several keys land in one bucket (collision), they form a linked list; since Java 8 a bucket with 8+ entries becomes a red-black tree (O(log n))
  4. On lookup, the bucket is found by hash, then equals() finds the exact key
  5. When size exceeds capacity × load factor (default 16 × 0.75), the table resizes (doubles) and rehashes
Interview question

Why must keys be immutable and override hashCode/equals together?

If a key changes after insertion, its hash changes and the entry becomes unreachable. If equal objects return different hashes, lookups miss their bucket.

06Queue and Deque

Queue<String> q = new LinkedList<>();       // or ArrayDeque
q.offer("A"); q.offer("B");
q.peek();      // "A", does not remove
q.poll();      // "A", removes (null if empty)

Deque<Integer> stack = new ArrayDeque<>();  // preferred over Stack
stack.push(1); stack.push(2);
stack.pop();   // 2   (LIFO)

PriorityQueue<Integer> pq = new PriorityQueue<>(Comparator.reverseOrder());
pq.add(5); pq.add(9); pq.add(1);
pq.poll();     // 9   (highest first)

07Iterating Collections

for (String s : list) { }                         // for-each
list.forEach(System.out::println);                // forEach + method reference

Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().startsWith("A")) it.remove();   // the ONLY safe way to remove while iterating
}
list.removeIf(s -> s.startsWith("A"));            // simpler
Warning

Removing from a collection inside a for-each loop throws ConcurrentModificationException. Use Iterator.remove() or removeIf.

08Sorting: Comparable and Comparator

Comparable: natural order (inside the class)

class Student implements Comparable<Student> {
    int id; String name;
    @Override
    public int compareTo(Student o) { return Integer.compare(id, o.id); }
}
Collections.sort(students);

Comparator: custom order (outside the class)

students.sort(Comparator.comparing(Student::getName));
students.sort(Comparator.comparingInt(Student::getAge).reversed());
students.sort(Comparator.comparing(Student::getCity)
                        .thenComparing(Student::getName)
                        .thenComparingInt(Student::getAge));
students.sort(Comparator.nullsLast(Comparator.naturalOrder()));

11Quick Recap

  • List allows duplicates and index access; Set forbids duplicates; Map pairs keys to values
  • Default picks: ArrayList, HashSet, HashMap, ArrayDeque
  • HashMap relies on hashCode + equals
  • Use Comparable for natural order and Comparator for custom orders
  • Never modify a collection during for-each; use Iterator.remove or removeIf
