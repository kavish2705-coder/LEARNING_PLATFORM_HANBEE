JDBC: Java Database Connectivity

Talk to relational databases from Java. Drivers, connections, Statement vs PreparedStatement, ResultSet, transactions, batch updates, connection pools and the DAO pattern.

01What is JDBC?

JDBC (Java Database Connectivity) is the standard Java API (java.sql and javax.sql) for connecting to a relational database, running SQL and processing results. Your code talks to JDBC interfaces; a vendor-supplied driver translates the calls for MySQL, PostgreSQL, Oracle and others.

Java App  →  JDBC API  →  JDBC Driver  →  Database

03Steps to Connect

  1. Add the driver dependency (Maven below)
  2. Obtain a Connection
  3. Create a statement
  4. Execute SQL
  5. Process the ResultSet
  6. Close resources (use try-with-resources)
<dependency>
  <groupId>org.postgresql</groupId>
  <artifactId>postgresql</artifactId>
  <version>42.7.4</version>
</dependency>

Since JDBC 4 the driver registers itself automatically; Class.forName(...) is no longer needed.

04A Complete Query Example

String url = "jdbc:postgresql://localhost:5432/lms";
String sql = "SELECT id, name, email FROM students WHERE age > ?";

try (Connection con = DriverManager.getConnection(url, "user", "password");
     PreparedStatement ps = con.prepareStatement(sql)) {

    ps.setInt(1, 18);
    try (ResultSet rs = ps.executeQuery()) {
        while (rs.next()) {
            int id = rs.getInt("id");
            String name = rs.getString("name");
            System.out.println(id + " " + name + " " + rs.getString("email"));
        }
    }
} catch (SQLException e) {
    e.printStackTrace();
}
Tip

Never hard-code credentials. Read them from environment variables or a secrets manager.

05Statement vs PreparedStatement vs CallableStatement

UseStatic SQL, DDLParameterised SQLStored procedures
ParametersNone? placeholders{call proc(?, ?)}
PerformanceRe-parsed each timePrecompiled, reusableRuns in the DB
SQL injection safeNoYesYes (with params)

SQL injection

// NEVER build SQL by concatenation
String bad = "SELECT * FROM users WHERE name = '" + input + "'";
// input = ' OR '1'='1   → returns every user

// Always use placeholders
PreparedStatement ps = con.prepareStatement("SELECT * FROM users WHERE name = ?");
ps.setString(1, input);
Warning

Placeholders work for values only, not for table or column names. Whitelist those instead.

06Executing Statements

MethodReturnsUse for
executeQuery()ResultSetSELECT
executeUpdate()int rows affectedINSERT, UPDATE, DELETE, DDL

CRUD

// INSERT
try (PreparedStatement ps = con.prepareStatement(
        "INSERT INTO students(name, email) VALUES (?, ?)", Statement.RETURN_GENERATED_KEYS)) {
    ps.setString(1, "Asha");
    ps.setString(2, "asha@mail.com");
    ps.executeUpdate();
    try (ResultSet keys = ps.getGeneratedKeys()) {
        if (keys.next()) System.out.println("new id " + keys.getLong(1));
    }
}

// UPDATE
PreparedStatement up = con.prepareStatement("UPDATE students SET email = ? WHERE id = ?");
up.setString(1, "new@mail.com");  up.setLong(2, 5);
int changed = up.executeUpdate();

// DELETE
PreparedStatement del = con.prepareStatement("DELETE FROM students WHERE id = ?");
del.setLong(1, 5);
del.executeUpdate();

09Transactions

A transaction groups statements so they succeed or fail together (ACID: Atomicity, Consistency, Isolation, Durability). JDBC auto-commits each statement by default.

try (Connection con = dataSource.getConnection()) {
    con.setAutoCommit(false);
    try {
        debit(con, fromId, amount);
        credit(con, toId, amount);
        con.commit();
    } catch (SQLException e) {
        con.rollback();
        throw e;
    }
}

Savepoints

Savepoint sp = con.setSavepoint("afterDebit");
// ... later
con.rollback(sp);

Isolation levels

10Batch Processing

Send many statements in one round trip.

try (PreparedStatement ps = con.prepareStatement("INSERT INTO logs(msg) VALUES (?)")) {
    for (String m : messages) {
        ps.setString(1, m);
        ps.addBatch();
    }
    int[] counts = ps.executeBatch();
}

Wrap in a transaction for atomicity and speed.

11Stored Procedures

try (CallableStatement cs = con.prepareCall("{call get_student_count(?, ?)}")) {
    cs.setString(1, "Java");
    cs.registerOutParameter(2, Types.INTEGER);
    cs.execute();
    int count = cs.getInt(2);
}

12Connection Pooling

Opening a database connection is expensive. A pool keeps connections open and hands them out.

HikariConfig cfg = new HikariConfig();
cfg.setJdbcUrl("jdbc:postgresql://localhost:5432/lms");
cfg.setUsername(user);
cfg.setPassword(pass);
cfg.setMaximumPoolSize(10);
DataSource ds = new HikariDataSource(cfg);

try (Connection con = ds.getConnection()) {     // borrowed from the pool
    // ... use it
}                                                // close() returns it to the pool

HikariCP is the standard (default in Spring Boot). Always close connections so they go back to the pool.

13DAO Pattern

Separate database access from business logic.

public interface StudentDao {
    Optional<Student> findById(long id);
    List<Student> findAll();
    long save(Student s);
    void delete(long id);
}

public class JdbcStudentDao implements StudentDao {
    private final DataSource ds;
    public JdbcStudentDao(DataSource ds) { this.ds = ds; }

    @Override
    public Optional<Student> findById(long id) {
        String sql = "SELECT id, name, email FROM students WHERE id = ?";
        try (Connection c = ds.getConnection(); PreparedStatement ps = c.prepareStatement(sql)) {
            ps.setLong(1, id);
            try (ResultSet rs = ps.executeQuery()) {
                return rs.next()
                    ? Optional.of(new Student(rs.getLong("id"), rs.getString("name"), rs.getString("email")))
                    : Optional.empty();
            }
        } catch (SQLException e) {
            throw new DataAccessException("findById failed", e);
        }
    }
    // other methods similar
}

15Best Practices

  • Always PreparedStatement; never concatenate user input
  • Use try-with-resources for Connection, Statement, ResultSet
  • Use a connection pool, not DriverManager in production
  • Keep transactions short; roll back on failure
  • Select only the columns you need; paginate large results (LIMIT/OFFSET)
  • Put queries in a DAO / repository layer
  • In larger applications use JPA/Hibernate or Spring JdbcTemplate on top of JDBC

16Quick Recap

  • JDBC = standard API; the driver does the vendor-specific work
  • DriverManager/DataSource → Connection → PreparedStatement → ResultSet
  • PreparedStatement prevents SQL injection and is faster
  • Transactions: setAutoCommit(false), commit, rollback
  • Pool connections with HikariCP and always close them
