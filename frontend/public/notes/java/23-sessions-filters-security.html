Sessions, Cookies, Filters, Listeners and Web Security

Keep users logged in with sessions and cookies, intercept requests with filters, react to lifecycle events with listeners, and secure a Java web application.

01State Management in a Stateless Protocol

HTTP forgets every request. To remember a user (login, shopping cart) you need state management.

TechniqueStoredNotes
CookiesBrowserSmall, sent with every request
HttpSessionServer (ID in a cookie)Most common for login state
URL rewritingIn the URLFallback when cookies are blocked
Hidden form fieldsIn the pageMulti-step forms
Tokens (JWT)ClientStateless APIs

02Cookies

// create
Cookie c = new Cookie("theme", "dark");
c.setMaxAge(60 * 60 * 24 * 30);      // 30 days; -1 = until browser closes; 0 = delete
c.setPath("/");
c.setHttpOnly(true);                 // not readable by JavaScript (blocks XSS theft)
c.setSecure(true);                   // only sent over HTTPS
resp.addCookie(c);

// read
Cookie[] cookies = req.getCookies();           // may be null
if (cookies != null)
    for (Cookie k : cookies)
        if ("theme".equals(k.getName())) System.out.println(k.getValue());
Warning

Never put passwords or sensitive data in cookies. Always use HttpOnly, Secure and SameSite for session cookies.

03HttpSession

The container creates a session ID (cookie JSESSIONID) and keeps the data on the server.

HttpSession session = req.getSession();            // create if absent
HttpSession existing = req.getSession(false);      // null if none

session.setAttribute("user", user);
User u = (User) session.getAttribute("user");
session.removeAttribute("user");
session.setMaxInactiveInterval(30 * 60);           // seconds
session.getId();   session.isNew();
session.invalidate();                              // logout

Login and logout example

@WebServlet("/login")
public class LoginServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws IOException {
        User user = auth.authenticate(req.getParameter("email"), req.getParameter("password"));
        if (user == null) { resp.sendRedirect("login?error=1"); return; }

        req.changeSessionId();                                 // prevents session fixation
        req.getSession().setAttribute("user", user);
        resp.sendRedirect(req.getContextPath() + "/dashboard");
    }
}

@WebServlet("/logout")
public class LogoutServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws IOException {
        HttpSession s = req.getSession(false);
        if (s != null) s.invalidate();
        resp.sendRedirect("login");
    }
}

04Filters

A filter intercepts requests before they reach a servlet (and responses on the way back). Use them for cross-cutting concerns: authentication, logging, encoding, compression, CORS.

Request ─► Filter 1 ─► Filter 2 ─► Servlet ─► Filter 2 ─► Filter 1 ─► Response
@WebFilter("/*")
public class EncodingFilter implements Filter {
    @Override
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {
        req.setCharacterEncoding("UTF-8");
        res.setCharacterEncoding("UTF-8");
        chain.doFilter(req, res);                 // continue; skip this call to block the request
    }
}

Authentication filter

@WebFilter(urlPatterns = {"/dashboard/*", "/admin/*"})
public class AuthFilter implements Filter {
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
            throws IOException, ServletException {
        HttpServletRequest req = (HttpServletRequest) request;
        HttpServletResponse resp = (HttpServletResponse) response;

        HttpSession session = req.getSession(false);
        boolean loggedIn = session != null && session.getAttribute("user") != null;
        if (loggedIn) chain.doFilter(request, response);
        else resp.sendRedirect(req.getContextPath() + "/login");
    }
}
  • Order of multiple filters is set in web.xml (annotation order is undefined)
  • Filter methods: init, doFilter, destroy
  • A filter can wrap the request/response (HttpServletRequestWrapper) to modify them

05Listeners

Listeners react to events in the web application's lifecycle.

Listener interfaceEvent
ServletContextListenerApp starts / stops
HttpSessionListenerSession created / destroyed
HttpSessionAttributeListenerSession attribute added/changed
ServletRequestListenerRequest begins / ends
ServletContextAttributeListenerApp attribute changes
@WebListener
public class AppStartup implements ServletContextListener {
    @Override
    public void contextInitialized(ServletContextEvent e) {
        DataSource ds = createPool();
        e.getServletContext().setAttribute("dataSource", ds);     // shared across the app
    }
    @Override
    public void contextDestroyed(ServletContextEvent e) {
        ((HikariDataSource) e.getServletContext().getAttribute("dataSource")).close();
    }
}

Typical uses: create connection pools at startup, count active users with HttpSessionListener, schedule background jobs.

Password storage

// Never store plain text or fast hashes (MD5/SHA-1/SHA-256 alone). Use a slow, salted algorithm:
// BCrypt, Argon2 or PBKDF2.
String hash = BCrypt.hashpw(password, BCrypt.gensalt(12));
boolean ok = BCrypt.checkpw(input, hash);

(Spring Security's BCryptPasswordEncoder or the at.favre.lib:bcrypt library provide this.)

Security response headers (set in a filter)

resp.setHeader("X-Content-Type-Options", "nosniff");
resp.setHeader("X-Frame-Options", "DENY");
resp.setHeader("Content-Security-Policy", "default-src 'self'");
resp.setHeader("Strict-Transport-Security", "max-age=31536000; includeSubDomains");

07Declarative Container Security

<security-constraint>
  <web-resource-collection>
    <web-resource-name>Admin</web-resource-name>
    <url-pattern>/admin/*</url-pattern>
  </web-resource-collection>
  <auth-constraint><role-name>ADMIN</role-name></auth-constraint>
  <user-data-constraint><transport-guarantee>CONFIDENTIAL</transport-guarantee></user-data-constraint>
</security-constraint>
<login-config><auth-method>FORM</auth-method></login-config>

Authentication methods: BASIC, DIGEST, FORM, CLIENT-CERT. In servlet code: req.isUserInRole("ADMIN"), req.getUserPrincipal(). Modern apps often use Spring Security, OAuth 2.0 / OpenID Connect and JWT instead.

08MVC Pattern (Recap)

  • Model: data and business rules (beans, services)
  • View: output rendering (JSP, templates)
  • Controller: handles input, calls model, picks view (servlets)

Front-controller frameworks (Spring MVC's DispatcherServlet, Struts, JSF's FacesServlet) route all requests through one servlet.

09Quick Recap

  • Sessions keep state on the server using the JSESSIONID cookie; call invalidate() on logout and changeSessionId() on login
  • Cookies live in the browser: set HttpOnly, Secure, SameSite
  • Filters intercept requests for auth, logging, encoding
  • Listeners react to app/session/request lifecycle events
  • Defend against SQL injection, XSS, CSRF; hash passwords with BCrypt/Argon2
