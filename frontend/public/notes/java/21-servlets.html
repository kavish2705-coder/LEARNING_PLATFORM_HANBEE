Servlets

The foundation of Java web development. How HTTP works, the servlet lifecycle, handling requests and responses, forms, redirect versus forward, and servlet configuration.

01HTTP Fundamentals

02What is a Servlet?

A servlet is a Java class, managed by a servlet container, that receives HTTP requests and produces responses. It is the base on which JSP, Spring MVC and JSF all sit.

Browser → Container (Tomcat) → Servlet.service() → doGet() / doPost() → Response

Servlet API hierarchy

interface Servlet
   └── abstract class GenericServlet
          └── abstract class HttpServlet     ← you extend this

03Your First Servlet

import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.*;
import java.io.IOException;
import java.io.PrintWriter;

@WebServlet("/hello")
public class HelloServlet extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
        String name = req.getParameter("name");
        if (name == null || name.isBlank()) name = "Guest";

        resp.setContentType("text/html;charset=UTF-8");
        try (PrintWriter out = resp.getWriter()) {
            out.println("<h1>Hello, " + escape(name) + "!</h1>");
        }
    }

    private static String escape(String s) {
        return s.replace("&", "&amp;").replace("<", "&lt;").replace(">", "&gt;");
    }
}

Run, then open http://localhost:8080/myapp/hello?name=Asha.

Warning

Always escape user input before writing it into HTML, otherwise you create a Cross-Site Scripting (XSS) hole. JSTL's <c:out> does it for you.

04Servlet Lifecycle

The container controls the lifecycle.

PhaseMethodCalledTypical use
Load + instantiateconstructorOnce (first request or at startup)None
Initialiseinit(ServletConfig)OnceOpen resources, read init params
Serveservice(req, resp) → doGet/doPost...Every requestBusiness work

@Override public void init() throws ServletException { /* runs once */ }
@Override public void destroy() { /* cleanup */ }
  • The container creates one servlet instance and serves all requests by multiple threads
  • Therefore servlets must be thread-safe: don't store per-request data in instance fields
  • loadOnStartup = 1 in @WebServlet loads it at startup instead of lazily

07Handling Forms (GET vs POST)

<form action="register" method="post">
  <input name="name" required>
  <input name="email" type="email" required>
  <button>Register</button>
</form>
@WebServlet("/register")
public class RegisterServlet extends HttpServlet {
    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        req.setCharacterEncoding("UTF-8");
        String name = req.getParameter("name");
        String email = req.getParameter("email");

        if (name == null || name.isBlank()) {
            req.setAttribute("error", "Name is required");
            req.getRequestDispatcher("/WEB-INF/views/register.jsp").forward(req, resp);
            return;
        }
        studentService.register(name, email);
        resp.sendRedirect(req.getContextPath() + "/students");     // Post/Redirect/Get
    }
}

Tip

Post/Redirect/Get (PRG): after a successful POST always redirect to a GET page. It prevents duplicate submissions when the user refreshes.

12File Upload

@WebServlet("/upload")
@MultipartConfig(maxFileSize = 5 * 1024 * 1024)
public class UploadServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws IOException, ServletException {
        Part file = req.getPart("photo");
        String name = Path.of(file.getSubmittedFileName()).getFileName().toString();   // strip any path
        file.write(uploadDir + File.separator + name);
    }
}

Validate type and size, never trust the submitted file name, and store uploads outside the web root.

13Async Servlets and Concurrency

@WebServlet(urlPatterns = "/slow", asyncSupported = true)

req.startAsync() frees the container thread while a long task runs. For most apps, a thread-per-request model (plus virtual threads on Java 21) is sufficient.

15Servlet Pitfalls

  • Instance fields shared across requests → race conditions
  • Forgetting setCharacterEncoding → garbled non-English text
  • Printing HTML inside servlets: use JSP/templates for views
  • Using GET for actions that change data
  • Not escaping output (XSS) or concatenating SQL (injection)
Interview question

Is a servlet thread-safe? How many instances exist?

By default there is a single instance serving many threads concurrently, so a servlet is not automatically thread-safe. Avoid mutable instance state, or synchronise access to it.

16Quick Recap

  • A servlet extends HttpServlet and overrides doGet/doPost
  • Lifecycle: init() once → service() per request → destroy() once
  • One instance, many threads: keep servlets stateless
  • Use forward to render a view, redirect after POST (PRG)
  • Scopes: request, session, application
