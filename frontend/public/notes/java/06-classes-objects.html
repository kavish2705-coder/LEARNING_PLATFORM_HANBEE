Classes and Objects

The core of Java. Classes, objects, constructors, this, static members, initialisation blocks, packages, access modifiers and encapsulation.

01Object-Oriented Programming Concepts

OOP models software as objects that combine data (state) and behaviour (methods). Java's OOP rests on four pillars:

PillarIdea
EncapsulationHide data inside a class, expose it through methods
InheritanceA class reuses and extends another class
PolymorphismOne interface, many forms (overloading, overriding)
AbstractionShow what an object does, hide how

02Classes and Objects

A class is a blueprint. An object is a real instance created from that blueprint.

public class Student {
    // fields (state)
    String name;
    int age;

    // method (behaviour)
    void introduce() {
        System.out.println("I am " + name + ", " + age + " years old");
    }
}
Student s1 = new Student();   // object creation
s1.name = "Asha";
s1.age = 20;
s1.introduce();

Student s2 = new Student();   // another independent object

What new does

  1. Allocates memory for the object on the heap
  2. Sets fields to default values
  3. Calls the constructor
  4. Returns a reference to the object
Stack                     Heap
s1 ───────────────────►  [ name="Asha", age=20 ]
s2 ───────────────────►  [ name=null,   age=0  ]

Reference variables

Student a = new Student();
Student b = a;        // b points to the SAME object
b.name = "Ravi";
System.out.println(a.name);   // Ravi
Student c = null;     // refers to nothing; c.name would throw NullPointerException

03Constructors

A constructor initialises a new object. It has the same name as the class and no return type.

public class Student {
    String name;
    int age;

    Student() {                       // no-arg constructor
        this("Unknown", 0);
    }

    Student(String name, int age) {   // parameterised constructor
        this.name = name;
        this.age = age;
    }
}
  • If you write no constructor, the compiler adds a default no-arg constructor
  • Once you write any constructor, the default is not added
  • Constructors can be overloaded
  • Constructors are not inherited, cannot be static, final or abstract

Copy constructor

Student(Student other) {
    this(other.name, other.age);
}

05Static Members

static members belong to the class, not to any object. There is one copy shared by all objects.

public class Counter {
    static int count = 0;           // shared by all objects
    final int id;

    Counter() {
        count++;
        id = count;
    }

    static int getCount() {         // call as Counter.getCount()
        return count;
    }
}
  • A static method cannot access instance members directly and cannot use this or super
  • Static members are loaded when the class is first loaded
  • static nested classes, static imports and utility methods (Math.max) are common uses

06Initialisation Blocks

public class Demo {
    static int x;
    int y;

    static {                 // runs once, when the class is loaded
        x = 10;
    }

    {                        // runs before each constructor
        y = 20;
    }

    Demo() { System.out.println("constructor"); }
}

Order of initialisation

  1. Static variables and static blocks (top to bottom, once)
  2. Instance variables and instance blocks (top to bottom, per object)
  3. Constructor body

07Packages and Imports

A package groups related classes and avoids name clashes. It maps to a folder structure.

package com.hanbee.lms.model;

import java.util.List;
import java.util.*;                 // all classes in java.util
import static java.lang.Math.sqrt;  // static import
  • java.lang is imported automatically (String, Math, System)
  • Use reverse domain names: com.company.project.module

09Encapsulation

Make fields private and expose controlled access with getters and setters. This lets you validate data and change internals without breaking callers.

public class Account {
    private double balance;

    public double getBalance() { return balance; }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Amount must be positive");
        balance += amount;
    }
}
Tip

Don't generate setters for everything. Expose only what callers truly need to change. Immutable objects (no setters) are the safest.

10Immutable Classes

Once created, an immutable object never changes (like String).

public final class Point {
    private final int x, y;
    public Point(int x, int y) { this.x = x; this.y = y; }
    public int x() { return x; }
    public int y() { return y; }
    public Point withX(int newX) { return new Point(newX, y); }
}

Rules: final class, private final fields, no setters, defensive copies of mutable inputs/outputs.

11Object Lifecycle and Garbage Collection

  • Objects are created with new and live on the heap
  • When no live reference can reach an object, it becomes eligible for garbage collection
  • You cannot force GC; System.gc() is only a hint
  • finalize() is deprecated; use try-with-resources / Cleaner for cleanup

12The Object Class Basics

Every class implicitly extends java.lang.Object, so every object has toString(), equals(), hashCode(), getClass().

@Override
public String toString() {
    return "Student{name=" + name + ", age=" + age + "}";
}

13Quick Recap

  • Class = blueprint, object = instance, new creates it on the heap
  • Constructors initialise objects; this(...) chains them
  • static members are shared per class
  • Use private fields + public methods (encapsulation)
  • Prefer immutable objects where possible
