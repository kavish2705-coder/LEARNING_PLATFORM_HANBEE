Lambdas, Functional Interfaces and Streams

Functional-style Java. Lambda expressions, method references, the built-in functional interfaces, Optional and the Stream API with collectors.

01Functional Programming in Java

Java 8 added a functional style: pass behaviour (functions) as data. This leads to shorter, more declarative code, especially when processing collections.

02Lambda Expressions

A lambda is an anonymous function: (parameters) -> expression or block.

// anonymous class
Runnable r1 = new Runnable() {
    public void run() { System.out.println("hi"); }
};
// lambda
Runnable r2 = () -> System.out.println("hi");

Comparator<String> byLength = (a, b) -> a.length() - b.length();

Syntax variations

() -> 42                         // no parameters
x -> x * 2                       // one parameter, parentheses optional
(int a, int b) -> a + b          // explicit types
(a, b) -> {                      // block body needs return
    int sum = a + b;
    return sum;
}

Rules

  • A lambda can only target a functional interface
  • It can use local variables only if they are effectively final (never reassigned)
  • this inside a lambda refers to the enclosing class, not the lambda

03Functional Interfaces

An interface with exactly one abstract method (SAM). Mark it with @FunctionalInterface.

@FunctionalInterface
interface Calculator {
    int apply(int a, int b);
}
Calculator add = (a, b) -> a + b;
Calculator mul = (a, b) -> a * b;
System.out.println(add.apply(3, 4));

Built-in interfaces (java.util.function)

InterfaceMethodPurposeExample
Predicate<T>boolean test(T)Test a conditions -> s.isEmpty()
Function<T,R>R apply(T)Transforms -> s.length()
Consumer<T>void accept(T)Use a value, no resultSystem.out::println
Supplier<T>T get()Produce a value() -> new ArrayList<>()
UnaryOperator<T>T apply(T)Function<T,T>s -> s.trim()
BinaryOperator<T>T apply(T,T)Combine two valuesInteger::sum
BiFunction<T,U,R>R apply(T,U)Two inputs(a, b) -> a + b
Runnable / Callable<V>run / callTasks() -> work()

Primitive variants avoid boxing: IntPredicate, IntFunction, ToIntFunction, IntUnaryOperator, etc.

Predicate<String> notEmpty = s -> !s.isEmpty();
Predicate<String> shortWord = s -> s.length() < 5;
Predicate<String> both = notEmpty.and(shortWord);      // also or(), negate()

Function<Integer, Integer> doubleIt = x -> x * 2;
Function<Integer, Integer> plusTen = x -> x + 10;
doubleIt.andThen(plusTen).apply(5);                    // 20
doubleIt.compose(plusTen).apply(5);                    // 30

04Method References

A shorthand for a lambda that only calls an existing method.

KindSyntaxLambda equivalent
Static methodInteger::parseInts -> Integer.parseInt(s)
Instance method of a given objectSystem.out::printlnx -> System.out.println(x)
Instance method of an arbitrary objectString::lengths -> s.length()
ConstructorArrayList::new() -> new ArrayList<>()

05Optional

A container that may or may not contain a value. It makes "no result" explicit instead of returning null.

Optional<String> name = Optional.of("Asha");
Optional<String> none = Optional.empty();
Optional<String> maybe = Optional.ofNullable(getNameOrNull());

name.isPresent();   name.isEmpty();
name.get();                                   // throws if empty: avoid
name.orElse("Guest");
name.orElseGet(() -> loadDefault());
name.orElseThrow(() -> new NoSuchElementException("No name"));
name.ifPresent(System.out::println);
name.ifPresentOrElse(n -> use(n), () -> log("missing"));
name.map(String::toUpperCase).filter(s -> s.startsWith("A"));
Tip

Use Optional as a return type. Avoid it for fields, method parameters and collections.

06Stream API

A stream is a sequence of elements supporting a pipeline of operations. Streams do not store data and do not modify the source.

Source  →  Intermediate operations (lazy)  →  Terminal operation (triggers work)
list    →  filter → map → sorted → distinct  →  collect / forEach / count / reduce
List<Integer> nums = List.of(5, 2, 8, 1, 9, 4);

List<Integer> result = nums.stream()
        .filter(n -> n % 2 == 0)       // keep evens
        .map(n -> n * n)               // square
        .sorted()
        .collect(Collectors.toList()); // [4, 16, 64]

Creating streams

list.stream();                          // from a collection
Arrays.stream(array);
Stream.of("a", "b", "c");
IntStream.rangeClosed(1, 5);            // 1..5
Stream.iterate(1, x -> x * 2).limit(8);
Stream.generate(Math::random).limit(3);
"hello".chars();                        // IntStream of characters
Files.lines(Path.of("data.txt"));       // lines of a file (close it!)

int total = nums.stream().mapToInt(Integer::intValue).sum();

boolean anyBig = nums.stream().anyMatch(n -> n > 8);

flatMap

List<List<Integer>> nested = List.of(List.of(1, 2), List.of(3), List.of(4, 5));
List<Integer> flat = nested.stream().flatMap(List::stream).toList();   // [1,2,3,4,5]

07Collectors

record Employee(String name, String dept, double salary) { }
List<Employee> emps = List.of(
    new Employee("Asha", "IT", 70000), new Employee("Ravi", "IT", 60000),
    new Employee("Meena", "HR", 50000));

emps.stream().map(Employee::name).collect(Collectors.toList());
emps.stream().map(Employee::name).collect(Collectors.joining(", ", "[", "]"));
emps.stream().collect(Collectors.toMap(Employee::name, Employee::salary));
emps.stream().collect(Collectors.toSet());

// grouping
Map<String, List<Employee>> byDept = emps.stream().collect(Collectors.groupingBy(Employee::dept));
Map<String, Long> countByDept = emps.stream().collect(Collectors.groupingBy(Employee::dept, Collectors.counting()));
Map<String, Double> avgSalary = emps.stream().collect(Collectors.groupingBy(Employee::dept, Collectors.averagingDouble(Employee::salary)));

// partitioning into true / false
Map<Boolean, List<Employee>> highLow = emps.stream().collect(Collectors.partitioningBy(e -> e.salary() > 55000));

// statistics
DoubleSummaryStatistics stats = emps.stream().collect(Collectors.summarizingDouble(Employee::salary));

08Parallel Streams

long count = hugeList.parallelStream().filter(this::expensiveCheck).count();

Splits work across the common ForkJoin pool. Helpful only for large, CPU-bound, stateless workloads. Avoid for small data, I/O or shared mutable state.

09Stream Rules and Pitfalls

  • A stream can be consumed only once; reuse throws IllegalStateException
  • Intermediate operations are lazy: nothing runs until a terminal operation
  • Don't modify the source collection while streaming
  • Keep lambdas pure (no side effects, no shared mutable state)
  • Prefer toList() / collectors over collecting into a list via forEach
  • Don't force everything into one long pipeline when a loop is clearer

10Common Stream Interview Programs

// second highest number
nums.stream().distinct().sorted(Comparator.reverseOrder()).skip(1).findFirst();

// first non-repeated character
"swiss".chars().mapToObj(c -> (char) c)
       .collect(Collectors.groupingBy(Function.identity(), LinkedHashMap::new, Collectors.counting()))
       .entrySet().stream().filter(e -> e.getValue() == 1).map(Map.Entry::getKey).findFirst();

// word frequency
Arrays.stream(text.split("\\s+")).collect(Collectors.groupingBy(String::toLowerCase, Collectors.counting()));

11Quick Recap

  • Lambdas implement functional interfaces; method references shorten them
  • Predicate, Function, Consumer, Supplier cover most needs
  • Optional models absent values, never call get() blindly
  • Streams: source → lazy intermediate ops → terminal op
  • Collectors.groupingBy, toMap, joining, partitioningBy do the heavy lifting
