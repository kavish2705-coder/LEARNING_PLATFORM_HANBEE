HanbeeLms Frontend Handover

Status of the connected frontend (LEARNING_PLATFORM_HANBEE, branch dashboard-ui-updated) against the live Supabase backend. Written so the next developer can continue without re-testing everything.

1. What is connected and working

  • Login: email and password sign-in, sign-out, and session checks. Wrong passwords show an error.
  • Google and GitHub sign-in: working after enabling the providers in Supabase Auth and registering the Supabase callback URL with each provider.
  • Sign-up: hidden for students. School staff and Hanbee staff keep the option.
  • Role routing: after sign-in each account lands on its own dashboard.
  • Sidebar: shows the real name and role, with no mock names. All 33 sidebar links point to existing pages. Student courses, attendance, and AI assistant sit under the Learning mode switch.

2b. Button check (safe buttons only)

Every non-destructive button on each role's pages was clicked in the browser (tabs, filters, toggles, and similar). No click produced an HTTP error, a page error, or an alert across the student, Hanbee staff, school owner, and manager accounts.

Not clicked: buttons that save, delete, suspend, restore, publish, submit, pay, or send. These need a click test on test data, one at a time, to avoid changing real accounts.

2c. Data-changing buttons (tested with TEST items, then removed)

  • Announcements (manager): create, then delete through the confirmation dialog. Both TEST items were removed. Found and fixed a bug: the delete dialog was never drawn, so Delete did nothing. The dialog now sits inside the page markup.
  • Hanbee schedule: delete opens the themed dialog and Cancel sends nothing. Earlier: create and delete of a TEST event returned 201 and 204.
  • Confirm dialogs in the design app: the remaining browser confirm boxes (school schedule, Hanbee schedule, school detail, tournament results) now use the themed dialog.
  • Announcements (manager): pin, edit, and delete all returned success. The TEST item was removed.
  • Settings (student): profile save returned success with the name unchanged.
  • Not yet tested: chat send (it messages real people), team creation, invitations, payments, approvals, and the school owner publishing. Each needs a TEST item or a test-only account.

  • Notification preferences (settings toggles).
  • Student ID and preferred team name (settings).

6. Environment and setup

  • Frontend environment file (git-ignored): only NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY.
  • Server secrets (Gemini, Google, GitHub, JWT) live in supabase/functions/.env locally and as Supabase Edge Function secrets in production. Never commit them.
  • Google and GitHub sign-in: enable each provider in Supabase Authentication. Register https://<project>.supabase.co/auth/v1/callback with each provider. Add http://localhost:3000/login to Supabase URL configuration for local testing.
  • The AI assistant origin list (ALLOWED_ORIGINS) must include the frontend origin, for example http://localhost:3000.
